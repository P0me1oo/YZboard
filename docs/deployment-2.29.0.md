## 升级后的线路恢复

v2.44.0/v2.42.0 停止时清理旧托管放行规则，新版在 NAT 来源未核对、缺少来源工具或端口冲突时暂停建立规则，导致五个落地节点的部分中转链路新增超时。证据包括：核心监听存在、UFW INPUT 默认拒绝、对应端口没有放行，以及 UFW 日志记录绑定前置的真实公网源地址被拦。

按面板当前拓扑、认证公网地址与落地阻断日志核对，在四台落地增加 **14 条限定源 IP 的 UFW 规则**，TCP/UDP 各一条，注释为 `yz229-recovery-node<编号>`：

| 落地服务器 | 节点 | 端口 | 允许来源 |
|---|---|---|---|
| BreadCloud-日本 | 199 | 13435 | 8.211.166.173 |
| KZC-香港 | 428 | 13131 | 8.210.52.196 |
| FFXF-加拿大 | 417 / 424 | 31324 / 23131 | 198.200.43.155 |
| 学长-香港 | 538 | 32421 | 195.58.144.122、103.42.183.64、8.210.52.196 |

未关闭防火墙、未改默认策略、未安装系统软件，也未添加全网放行。规则是部署恢复规则，不冒充 Agent 托管规则。它们保留在对应服务器 UFW；前置地址或拓扑改变时需重新核对，后续自动策略能够覆盖这些链路且真实验证成功后，再按该注释逐条撤销。NAT 自动核对、缺少工具和共用端口告警仍可能保留，不能表述为自动来源管理已全部正常。

恢复后逐线路对照升级前最近健康记录，新增线路失败为 0。最终 102 个新鲜运行节点，98 正常、3 失败、1 未检查，与升级前一致；内核运行失败为 0。既有失败是 Panstar-日本离线链路、台湾落地旧地址/连通性，以及未升级的 LazyCat 本机监听检查，未擅自修改地址或节点配置。
