# Solid-US LA 更新至面板 2.16.9

维护者：P0me1oo。日期：2026-11-15（北京时间）。

按用户本次发布与部署授权，通过 Lite MCP 将 Solid-US LA `/root/yzboard` 从 2.16.7 更新至 **2.16.9**，内置管理端由 0.98.4 更新至 **0.98.5**。运行账户为 `www-data`，PHP 8.4.27、MariaDB 12.3.3；没有升级 Agent 或发布 Docker 镜像。

## 固定来源与准备

来源为已发布的 `ba2d73bf08a492259d7dd5aab3a7e7b84783f482`，源码包 SHA-256 为 `373a1f1416f9b19b78561352b2488d2fca71721add53a9017c60ca710f267b7f`。程序验证见[发布记录](release-2.16.9.md)与[完整测试](release-2.16.9-tests.json)。

生产独立下载公开安装包，摘要与本机及 Release 一致。在 `/root/yzboard-deployments/2.16.9/source/` 准备源码，核对真实环境与框架缓存未进入包。锁文件保持相同，复制现有依赖后执行不含开发依赖的锁定安装、自动加载优化与平台检查，禁用安装脚本和插件；113 个生产依赖与锁文件逐项匹配，没有安装或升级依赖。

生产文件与现有 2.16.7 固定源码包对照，1,150 份待运行文件中有 15 份差异，全部属于已确认的五份 PHP、版本配置及管理资源。变更清单与源码提交之间的差异一致，没有覆盖生产额外改动。原有 `.env`、插件、主题与其他持久内容另以任务 HMAC 核对。

## 切换与版本元数据

暂停生产就绪标记和三个面板服务，等待在途调度结束，保存本次差异文件与原框架缓存，再按清单同步程序。以 `www-data` 完成包发现、`xboard:update`、迁移状态、配置缓存与视图清理，然后恢复标记与服务。程序切换耗时 **8.34 秒**。没有新增数据库迁移或全库备份，沿用 2.16.7 可用回退来源。

首轮管理页检查发现构建标记被工作进程启动逻辑写回保留的旧 Git 基线。启动后单次校准虽能通过，工作进程回收仍会再次覆盖。因此为 Web 服务增加独立的固定 Git 元数据：

- `/root/yzboard-deployments/2.16.9/runtime-git.git` 为公开版本 Tag 的浅层裸仓库，HEAD 核对为本次已发布 SHA，没有应用工作树或真实环境文件。
- `/etc/systemd/system/yzboard-web.service.d/source-metadata.conf` 设置该服务的 `GIT_DIR` 指向上述目录，使现有构建标记读取取到实际运行版本。
- 生产 `/root/yzboard/.git` 与其历史基线保持；没有在生产目录执行拉取、重置或重新克隆，也没有改写已发布程序文件。

重新加载服务配置并重启 Web 服务后，管理构建标记正确。随后以 `www-data` 执行一次 `octane:reload`，再次核对标记仍为 `20261115-ba2d73b`，1,150 份程序仍匹配固定源码。该配置只解决运行版本元数据，不改变设备协调、权限或流量规则。

**后续更新需要同时准备新固定版本的裸仓库，并更新 Web 服务的 `GIT_DIR` 引用。** 不应仅替换程序后继续指向本版元数据。

## 保留与回退

`/root/yzboard-deployments/2.16.9/` 保留安装包、清单、原差异文件、原框架缓存、状态与 HMAC 验证、服务日志及固定 Git 元数据。私有记录只允许 root 读取；Web 运行账户仅获得元数据所需的目录访问。元数据目录是 Web 服务运行引用，不能作为普通暂存目录删除。

回退时暂停就绪标记及三个面板服务，按 `plan.json` 恢复 `runtime-before/` 的原文件，对原先不存在的新文件按清单移除，恢复 `cache-before/` 与运行账户权限。仅移除本次的 `source-metadata.conf`，或将其明确指向已确认的旧版本元数据；执行服务配置重载后恢复就绪标记及服务，再检查版本、入口、心跳和队列。

本次没有数据库迁移需要回滚，环境配置、数据库、插件、主题与 Agent 均无需替换。程序回退固定至 2.16.7 的 `18c752fe3c83cdb5803659af66c52d07adab7985`；同时保留已有的 2.16.7 部署资料。
