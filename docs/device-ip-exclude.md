# 不计入设备数的来源 IP

设备数按节点看到的来源地址计算。经 flux 等转发机中转的连接，节点只看得到转发机的地址，看不到用户的真实 IP，所以转发机会被当成一台设备占用名额。把转发机的出口地址填进这份名单后，从这些地址进来的连接就不再计入设备数。

## 效果

- 名单内地址进来的连接不占设备名额、不参与设备超限判断，不出现在用户在线设备数和设备详情里，也不进入发给节点的跨节点设备汇总。
- 只经转发连接的用户，在线设备数为 0，也不受设备数限制。节点无法区分转发机后面有几台设备，这是用名单排除转发地址的代价。
- 不受影响：直连用户照常计数；连接数限制、限速和流量统计；节点列表的在线人数（Node `v1.20.0` 起按所有活跃来源计算）；首页的在线用户数（按最近 10 分钟有流量统计）。
- 名单为空时行为和以前完全一样，节点配置也不包含该字段。

## 填写

系统设置 → 节点配置 → “不计入设备数的来源 IP”，每行一个：

```
203.0.113.10
198.51.100.0/24
2001:db8:1234::/48
```

- 支持 IPv4、IPv6 地址和网段。IPv4 映射的 IPv6 写法会转为 IPv4，网段主机位自动清零，重复项去掉。
- 最多 256 项；网段最宽 IPv4 `/16`、IPv6 `/48`，防止误填把所有用户都排除。
- 转发机的出口地址可以在用户管理里把鼠标停在在线设备数上查看。转发机出口地址变了，名单要跟着改。
- 该页改动后自动保存，名单在离开输入框时校验并提交；有错误时提示第几行，不会提交。

## 生效方式

- 面板把名单放进节点配置（字段 `device_ip_exclude`）。名单实际变化时立即推送给通过 WebSocket 在线的节点，其他节点在下次拉取配置时拿到；只调换顺序不算变化。
- Node 更新本机名单后不重载内核，名单对已有连接立即生效。
- 面板 `1.25.0` 起保存 Node 上报的完整公网来源，在读取设备数和下发跨节点快照时按当前名单过滤，并将 IPv6 合并到 `/64`。这样单个 IPv6 地址的排除项只排除该地址。旧 Node 上报时已经合并的网段无法还原，升级 Node 后随下一次快照更新。
- WebSocket 常驻进程每 10 秒以及节点连上时重新读取系统设置，改名单或通讯密钥后无需重启该进程。

## 版本要求

需要面板 `1.24.0`、Node `v1.20.0` 和管理前端 `0.7.0`，先升级 Node 再升级面板。旧 Node 会忽略名单，自己判断设备数时仍把转发机地址算作一台设备，只有面板显示的数字会排除它。

想按用户真实 IP 计数，需要转发机把真实地址传给节点（PROXY protocol）。flux-panel 目前生成的转发配置没有这个选项，sing-box 也已不支持接收，因此本功能只能排除转发地址，不能还原真实地址。
