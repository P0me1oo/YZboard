# 设备快照复用

版本：`1.112.1`。开发基线为 `1.112.0`。正式发布验证及生产部署结果以[本版本发布附件](https://github.com/P0me1oo/YZboard/releases/tag/v1.112.1)为准；下文记录开发验证和局部基准。

## 要解决的重复处理

设备同步原先先查询节点可用用户，读取各用户的完整 Redis 设备记录和来源状态，过滤、组装并计算摘要，最后才判断是否发送。五秒校准以及设备变化通知都会进入该路径；多个节点可见同一用户时，会重复处理相同的设备记录。

本批保留每次调用中的用户资格、机器保护和路由权限查询。节点元数据、状态上报、全体变化通知、五秒校准、十秒续发及设备许可申请/撤销/续期规则均沿用原实现。订阅插件、后台调度和服务器参数不在本批范围内。

## 读取与复用

基础设备服务使用普通、未启用客户端序列化/压缩的 phpredis 连接时，通过 `DeviceSnapshotReader` 执行只读批量脚本：

1. 没有复用基线且用户数不超过 256 时，先用一次原生存在性检查处理全部设备键缺失的空闲场景。其它读取每批最多 32 个用户，在 Redis 内核对每个设备字段的原有 300 秒期限，对当前有效字段排序并计算内容标识。未变化时只返回标识；内容变化才返回有效字段，空记录返回精简标记。
2. PHP 保留有界的字段和过滤结果。来源新鲜度、当前排除名单每次重新读取；字段、来源新鲜度和排除规则均相同时，复用同一用户的 IP 过滤结果，允许多个节点共享该结果。各节点仍分别查询当前可用用户名单。
3. 基础设备服务生成的纯数组内容完全相同时，复用 SHA-256 摘要。共享代次、序号仍在原捕获锁内读取和校验；版本记录被删除或损坏时仍重新换代。最终发送仍由原连接上的版本与十秒续发规则决定。

实现采用读取时核对当前内容的方式，未给高频上报增加版本键或写操作，也未修改现有 Redis 数据格式。因此旧写入路径、直接哈希改写、删除和键过期都能被下一次读取发现，不依赖变更通知完整到达。

Redis 内部仍要读取设备哈希；优化减少的是传回 PHP 的完整记录、PHP 过滤和重复摘要计算，不代表 Redis 内部读取或命令总数下降。脚本将一部分处理移到了 Redis，需要同时观察 PHP 和 Redis 的 CPU，不能只报告 PHP 降幅。

## 有效期、故障与兼容

- 设备字段保留原 `当前时间 - 记录时间 <= 300 秒` 边界；节点状态仍按原 35 秒新鲜度判断。读取来源状态后如发生跨秒或时钟回拨，沿用原完整读取，避免用较早的时间延长设备有效性。
- 用户封禁、到期、流量耗尽、换组及机器停用、计量超时、超额等仍由当前数据库查询决定，不缓存授权结论。
- 任一批读取失败、错误类型、缺项或非法回包均报错，不返回旧快照或部分成功；重试重新读取当前记录。返回数组按值隔离，调用方修改不污染后续结果。
- 每用户超过 1024 个字段、字段超过 128 字节或时间格式超出标准整数形式时，沿用原读取和 PHP 过滤；自定义设备服务、Redis 管理器/连接、集群、客户端序列化或压缩也沿用原路径。带共享读取上下文或旧协议专用筛选的原入口保持原实现。
- 用户字段/过滤备忘及节点摘要备忘分别限制为最多 512 项、按条目估算最多 4 MiB；这是缓存计费预算，不是进程实际内存的硬上限。条目不足时淘汰并重新读取，单批在途数据另占内存。

本批不新增数据库迁移或 Agent 协议字段。回退程序不需要清理新业务数据；进程内备忘在退出时释放。

## 验证

测试使用本机一次性 PHP `8.4.27`、Redis `8.0.2`、MariaDB `11.8.6` 和独立数据库，未使用生产账号或业务数据。依赖包只解压到本次 `/tmp` 目录，未安装系统服务。测试版本不同于当前生产 PHP `8.2.35`、Redis `8.8.4` 和 MariaDB `11.4.13`，正式发布仍须执行项目发布流程规定的环境检查。

新增真实 Redis 回归覆盖内容不变、心跳更新时间、300 秒边界、无通知改写、删除、键过期、35 秒状态过期和恢复、排除名单变化、批量失败、淘汰后重读、返回值隔离、客户端序列化及扩展读取兼容。数据库集成回归确认权限查询次数保留，并验证权限撤销、恢复、机器保护和共享版本换代。

SQLite 完整回归：1,560 项、18,305 次断言；10 项 MariaDB 专属检查按设计跳过。MariaDB 严格分组完整回归：1,560 项、18,317 次断言全部通过。两套回归均提供专用真实 Redis。管理端资源检查 5 项通过，新增与修改 PHP 文件语法及差异空白检查通过。

## 局部基准复现

```bash
YZ_TEST_SUBSCRIPTION_REDIS_PORT=<专用本机端口> php vendor/bin/phpunit tests/Fixtures/DeviceSnapshotBenchmark.php --do-not-cache-result
```

固定 48 个合成用户，每用户分别为 0、4、64 个来源。以沿用旧读取路径的基础服务子类对照新实现，预热后交替运行四轮，每轮 100 次。设置使用真实设置读取类；来源状态使用不记录调用的固定测试实现，避免把测试替身的调用记录开销算成收益。每次都核对输出一致，并在结束后清理随机前缀数据。

该基准只衡量设备记录读取与过滤，不包含权限 SQL、完整来源状态读取、快照摘要复用、网络发送或生产业务波动，不能外推为整机 CPU 的下降比例。Redis 命令计数包含脚本内部的命令。

最终实现的单次完整基准如下；数值均为四轮合计 400 次读取，包含少量计数器读取开销：

| 每用户来源数 | 耗时 ms：原 → 新 | PHP CPU ms：原 → 新 | Redis CPU ms：原 → 新 | Redis 返回字节：原 → 新 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 29.759 → 25.475 | 17.103 → 14.844 | 11.976 → 10.151 | 100,258 → 25,058 |
| 4 | 370.518 → 154.092 | 348.145 → 53.931 | 19.959 → 98.149 | 2,683,047 → 1,013,710 |
| 64 | 5,254.704 → 831.510 | 5,167.904 → 153.787 | 100.085 → 674.022 | 43,767,478 → 1,007,073 |

三个场景的 PHP 与 Redis 合计 CPU 分别约减少 14%、59%、84%。有设备时 Redis CPU 增加，返回量和 PHP 计算显著减少；全空场景通过原生存在性检查避免进入脚本。Redis 命令总数分别为 19,204 → 404、19,204 → 40,052、19,204 → 40,004，不能宣称所有 Redis 命令减少。4 来源场景包含一次跨秒后沿原路径重新读取。

基准输出一致性检查 27 次断言通过。首次完整测试发现临时 PHP 缺少二维码依赖的 `iconv` 扩展，补齐临时配置后通过；未修改二维码功能。最终空闲快速路径也经过回归检查。

生产更新后仍需在相近节点数和报告量下比较整机、WebSocket、PHP、Redis CPU 与上报延迟；本页局部基准不代表生产降幅。

正式发布前的 PHP 8.2.35 / MariaDB 11.4.8 检查及 DartNode-US 部署已完成。实机存在间歇 HTTP 超时，旧版同机对照也能复现；恢复时曾出现 Web 启动重试。具体结果见[部署验证](deployment-1.112.1.md)，不能将开发基准作为生产稳定性或降幅的结论。
