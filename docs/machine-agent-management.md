# 服务器 agent 管理

面板 `1.19.0`、管理前端 `0.4.0` 和 Node `v1.16.0` 配套提供本功能，已于 2026-09-21 正式发布。

## 页面行为

- 运行版本来自当前 yz-agent 进程的构建版本，不读取安装记录来推断。离线时保留最后一次回报，可结合现有在线状态判断。
- 公网 IP 是面板收到 agent 控制请求时识别的来源 IP。可信代理沿用现有代理头规则；私网和无法识别的来源显示空值。NAT 下显示出口地址，不枚举网卡；反向代理应正确转发来源地址。
- 操作前确认目标；重启对象是 yz-agent 服务，其全部实例和节点会短暂中断。更新固定到执行时解析的最新正式版，复用原有附件校验及失败回滚事务。
- 列头选择当前页，翻页保留选择；排序和刷新按服务器 ID 绑定，切换筛选条件清空选择。批量逐台返回受理或拒绝结果。
- 每页数量仅保存在当前浏览器，刷新及重新登录保留，不跨浏览器同步。

## 通信与结果

管理接口 `POST server/machine/operate` 接收 `ids`（最多 200 个）与 `action`（`upgrade` 或 `restart`），沿用管理员鉴权。前端超过 200 台时分批提交。

Node 每 5 秒调用 `POST /api/v2/server/machine/control`，使用已有机器鉴权，上报运行版本、进程标识、控制能力及任务结果。此通道不依赖 WebSocket，也不要求机器绑定节点。旧面板返回 404 时继续原有服务。

`agent_runtime` 和 `agent_operation` 分别保存最近运行信息和最近任务。数据库行锁保证同一服务器只能有一个未完成任务。30 秒无控制回报视为离线，拒绝新操作；15 分钟未确认则显示超时，不自动重试。

成功必须同时满足独立执行器完成和新 agent 进程回报，发出请求或只替换文件均不算成功。网络中断可能导致“超时未确认”，应先检查实际服务状态，不能据此认定没有执行。

## 安装条件

远程操作要求 Linux 上安装的 yz-agent、root 权限及 systemd 或 OpenRC。systemd 使用独立临时服务执行，OpenRC 使用独立会话执行。本机执行锁避免多个面板实例同时修改同一服务。容器、手工二进制路径或不支持的旧 agent 不宣称具备控制能力。

操作标识与固定结果码位于安装目录 `remote-operations`，不保存凭据和命令输出。重复请求与配置重载不重复执行；异常退出后任务超时，内核执行锁自动释放。面板超时不强杀正在安装或回滚的事务，仍在执行的进程继续持锁，后续操作返回忙碌。

更新时应先让 Node 具备新能力，再更新面板。面板 `latest` 已更新到 `1.19.0`；完整来源、镜像 digest 和回滚基线见 [兼容矩阵](../YZ_COMPATIBILITY.md)。数据库回滚前应等待在途任务结束；旧面板可保留新增的可空字段。
