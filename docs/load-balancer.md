# 前置 DNS 调度

新建池使用单台自建 PowerDNS Authoritative，通过 API 管理解析；后端需支持 RRset comments，例如 gsqlite3 或 gmysql。连接路径为“用户 → 前置成员 → 落地”，PowerDNS 仅提供 DNS 答复，不承载代理转发。已有的旧转发池保留兼容，转换方式见下方。

## 配置与分配

1. 准备 PowerDNS 区域和 API，在“前置 DNS 调度 → DNS 配置”填写区域名称、API 基础地址、服务器 ID（通常为 `localhost`）和 API Key。基础地址不含 `/api/v1`、认证信息或查询参数；编辑密钥留空保留原值，密钥加密保存且不回显。多个区域共用同一台 PowerDNS 的 API 地址及服务器 ID。
2. 新建前置池，选择 PowerDNS 配置并填写池域名。可以直接使用委托区域的根名称，例如 `pool.example.com`；也可以使用区域内的子域名。每台服务器选择一个现有 VLESS Reality + TCP 前置节点，服务器需运行 Agent v2.25.0 或更新版本。选择列表支持节点名称、服务器名称和公网 IP 搜索；筛选保留勾选状态与选择顺序。
3. 池端口取第一个选中节点的公网连接端口，不固定为 443 或从 20000 分配。直接复用各节点的原服务，不新建监听实例，也不覆盖原节点的协议、密钥或权限组。NAT 节点的内部监听端口可以不同，例如两台机器分别监听 443 和 8443、都映射到公网 30443；池订阅使用 30443。
4. 落地节点选择对应前置池。用户订阅使用池域名和首选节点的公网端口。原前置接收池内落地线路及对应用户权限，已有直连线路继续使用原权限。DNS 模式不创建调度入口实例；启用 PROXY 协议接收的节点会标为不兼容。

选择时自动标注协议、Reality 模式、TCP 传输、公网端口、Reality 公钥、短 ID、握手域名、握手端口和 VLESS 流控的差异。参数以首个选中节点为准；取消首选后改用剩余选择中的第一个。后端保存时再次核对，参数不兼容时拒绝保存并指出节点和原因，不自动复制或修改密钥。共享父级节点应选择实际运行服务的父节点。

优先级数字越小越优先。面板每 60 秒执行 `balancer:sync`，直接复用节点列表的现有在线/离线状态，结合节点与机器启用、现有流量保护及连接参数兼容性筛选。默认关闭主动端口检查；启用后分别检查已记录的 IPv4/IPv6 公网端口。手动优先级模式只发布最高可用优先级的全部已记录地址，该级全部离线后自动使用下一优先级。原节点上线恢复后重新加入，同级地址由 DNS 和客户端选择，不保证均匀会话数量。

DNS 模式以节点列表现有的可用状态字段（`available_status`）为基础，不使用旧转发池的独立心跳离线阈值，也不把展示采样缓存作为额外离线条件；可选端口检查与调度策略在此基础上筛选。服务器流量限额仍按现有保护处理。故障或参数变为不兼容的成员不再出现在新答复中；全部不可用时撤销本功能托管的池 A/AAAA 与个人 CNAME，恢复后重新加入。状态剔除不受 DDNS 或用户状态跟随开关影响。API 同步失败在列表显示错误，下一轮重试；不会改写其他用途的解析。

TTL 每池独立配置，范围 30–86400 秒，默认 60 秒。切换还受定时检测、递归 DNS 和客户端缓存影响，不能迁移已建立的连接；从无记录恢复时还受区域 SOA 的否定缓存时间影响。单台 PowerDNS 不可用时，解析和同步依赖已有缓存，面板不能通过故障 API 撤销旧答复。

## 自动调度与落地主备

面板 `1.114.0`、管理端 `0.84.0` 与 Agent `v2.30.0` 为本地开发版本，尚未发布。本版增加迁移 `2026_11_02_000001_add_scheduling_policies.php`，只新增调度配置、状态和记录，不改变已有节点监听与认证。旧池的新增开关默认关闭，原优先级继续生效。

### 前置自动调度

- **检测前置端口**：每轮 DNS 同步并发检查各已记录地址的公网 TCP 端口，超时 2 秒。连续两次失败后撤下该地址，连续两次成功后恢复；IPv4/IPv6 分别判断。检查只证明端口可达，不能证明完整代理握手、用户认证或访问网站成功。端口检查关闭时沿用原节点状态。
- **同优先级内按延迟择优**：编辑已存在的池，选择绑定该池的 TCP 落地作为测速目标。Agent 从各前置直接探测该落地端口；它衡量前置到落地的 TCP 建连延迟，不代表用户到前置的延迟或下载速度。在最高可用优先级内选择延迟最低的前置；新候选至少快 10 毫秒且快 15%，连续两份新测量满足条件才切换。旧候选不可用时立即采用其他有效候选。没有测量时暂保留端口健康的前置，有明确失败结果的前置退出候选。
- **剩余流量调度**：开启后，低于设置百分比的机器优先退出候选；恢复到阈值以上 5 个百分点后重新加入。不限流量的机器不按这个阈值退出。若全部可用机器都低于阈值，保留剩余比例最高的机器，避免人为断流；真正达到流量限额或触发既有计量保护时仍撤下。只调整候选集合，不按比例分配连接。

Agent 探测每 15 秒运行，超时 2 秒，最多 8 个并发和 256 个目标。目标变化后旧测量失效；探测清单独立于核心配置，单独变更不重载代理监听。测量与既有状态报告一起发送，面板拒绝跨入口、错误目标标记、乱序、超出时间窗的结果。前置择优仍受每分钟 DNS 同步、TTL 和客户端缓存影响。

### 落地主备

在“落地主备”页新建池，选择原订阅线路，再按顺序选择备用落地。成员须是已有的内部落地节点，绑定同一前置节点或前置池，每台服务器只选一个成员；协议分别按前置与落地的实际核心校验。不同成员可以使用各自的协议、端口和内部认证，保存不会复制密钥、修改原节点或新建监听。

首成员始终是原线路的主落地。各前置独立选择第一个可用成员；稳定恢复后自动回到主落地。用户继续使用原线路名称和路由编号，权限、用户扣费和逻辑线路统计归属保持不变；实际转发使用所选成员自己的内部凭据。备份节点原有的其他线路继续保留，可在节点管理中自行调整是否展示。

TCP 内部链路使用 Agent 的连通性结果，连续两次失败/成功确认状态；WireGuard、VLESS KCP/Hysteria 等 UDP 内部链路只按节点状态及流量保护判断，不把 TCP 失败当作 UDP 故障。首次启用或重新启用提供 90 秒测量宽限期；TCP 测量超过 90 秒失效后，该成员退出候选。全部不可用时保留并阻断原路由编号，不回退前置直出。管理员停用原订阅线路会阻断这条线路，不自动绕过停用选择备用。

主备选择收到新的测量后更新，定时同步也处理心跳过期和流量保护。切换复用现有配置下发和核心重载机制，只改变后续连接；已建立的连接不能迁移。停用或删除落地池恢复原落地，不删除成员服务。启用自动择优或落地主备前，前置 Agent 必须达到 `v2.30.0`；旧版本不能静默启用。

### 状态与记录

池列表展示成员端口状态、测速结果和流量不足状态；落地页按前置展示当前落地及各成员状态。“切换记录”展示候选变化、主备切换、DNS 同步失败和恢复，保留 30 天，列表最多展示最近 100 条。相同结果及重复上报不重复记录。DNS 写入成功后才记录实际候选切换；失败保留上次已确认选择并记录同步错误。

新增功能涉及数据库迁移。回退源码前停用新增策略和落地池，并确认当前线路已恢复原配置；不要单独撤销迁移却保留新代码。实际部署与端到端线路尚需在发布后按授权验证。

## 三个独立开关

| 开关 | 默认 | 生效范围 |
| --- | --- | --- |
| DDNS | 关闭 | 仅负责成员 IP 变化后的同步。关闭时保留首次配置或最后一次同步的地址，按现有节点状态照常剔除或加入这些地址 |
| 用户独立域名 | 关闭 | 关闭时所有用户共用池域名；开启时每名用户使用固定随机标识的四级域名 |
| 跟随用户状态 | 关闭 | 独立域名开启后，可显式选择按封禁、到期、流量耗尽撤销个人解析，资格恢复后恢复同一名称；DDNS 不会自动开启它 |

开启独立域名时，池域名必须有三级，例如 `pool.example.com`。个人域名为 `固定随机标识.pool.example.com`，CNAME 指向池域名；发生前置切换不改变用户名称。关闭独立域名会改为下发池域名并撤销个人解析，但保留随机标识，重新开启仍使用原名称。权限组授权仍决定哪些用户可以获得该池的解析；“跟随用户状态”只控制额外的账号状态撤销，不替代节点认证或订阅权限检查。

成员地址优先采用服务器上报的有效公网 IPv4/IPv6，无有效上报时使用原节点手填 IP。DDNS 关闭时不追踪后续 IP 变更。各前置须可通过记录中的 IP 与池公网端口直达；DNS 不能按 IP 指定不同的 TCP 端口，只有不同公网映射端口的 NAT 节点会标为不兼容。原节点的连接参数被单独编辑后，池列表显示差异原因，后台撤销该成员的解析；对齐参数后恢复，或重新编辑池以新的首选参数保存。

## 从 Cloudflare 委托子域

以 Cloudflare 管理 `example.com`、委托 `pool.example.com` 为例：

1. 为 PowerDNS 准备一个可公开解析的 NS 主机名，例如 `ns1.example.com`，A/AAAA 指向该服务器 DNS 地址，Cloudflare 中设置为仅 DNS。使用委托范围之外的 NS 名称可避免子域内 NS 的胶水记录依赖。
2. 在 PowerDNS 创建 `pool.example.com.` 区域，配置对应 SOA 与 `ns1.example.com.` NS，并开放面向解析器的 UDP/TCP 53。API 通过受保护的管理地址供面板访问，不对用户暴露 API Key。
3. 在 Cloudflare 父区域添加名称 `pool`、内容 `ns1.example.com` 的 NS 委托。处理该名称原有冲突的 A/AAAA/CNAME；PowerDNS 内保留区域根部 NS/SOA。面板不会自动改写父区委托，也不会安装或重启 PowerDNS。
4. 在面板中添加 PowerDNS 配置，区域填 `pool.example.com`；池域名同样填 `pool.example.com`。由 PowerDNS 管理池 A/AAAA 和用户四级 CNAME，Cloudflare 只保存 NS 主机地址及委托，不保存每名用户的记录。
5. 用 `dig NS pool.example.com`、`dig @<PowerDNS地址> pool.example.com A`、`dig +trace pool.example.com` 检查权威答复、委托和最终解析。若启用 DNSSEC，父区 DS 与子区签名须配套；否定缓存 TTL 建议配合故障恢复要求设置。

API 采用官方的区域 RRset `GET` / `PATCH`，名称使用完整域名，以 `REPLACE` / `DELETE` 更新。每组记录先持久化随机归属标记，再写入 PowerDNS comments；请求响应丢失时按同一标记恢复，不重复建记录、不认领外部记录。域名冲突、归属变化、覆盖范围内的泛解析或下级 NS 委托会阻止写入。区域根部 NS/SOA 始终保留。

参考：[PowerDNS 区域 API](https://doc.powerdns.com/authoritative/http-api/zone.html)、[PowerDNS HTTP API](https://doc.powerdns.com/authoritative/http-api/index.html)。

## 旧方案兼容与转换

升级迁移不会自动切断旧转发池。已有池标记为“旧转发模式”，继续使用原调度服务器、原端口及 Cloudflare 托管记录；旧 API 带调度服务器参数的新建请求仍按旧模式处理。管理端新建统一使用 DNS 模式。

转换前准备 PowerDNS 委托及前置成员端口，依次执行：

1. 在列表停用旧池，执行“同步 DNS”清理旧池记录。
2. 如有旧池 DDNS，分别关闭其 DDNS 和独立域名，再到 DDNS 设置中清理旧解析，等待绑定完成清理；保留旧名称的退休绑定也需清理后再更换用途。
3. 编辑池，将调度方式改为 DNS，选择 PowerDNS 配置并保存。落地引用保留，池成员改为直接引用原节点，删除属于该池的旧专用成员和调度入口实例，并通知相关机器更新节点列表。新连接端口使用首选原节点的公网端口，原节点服务保留。
4. 启用池，确认原节点在线和 DNS 同步正常，再让客户端更新订阅。原调度入口端口不会继续转发。

已有 DNS 池不会在数据库升级时自动更换原连接入口；编辑并重新保存时才改为复用原节点，保存前须先对齐各原节点的公网端口和 Reality 参数，并让客户端更新订阅。仅列表停用操作保留已有实例。移除成员或删除池不会删除原节点。

DNS 池不能改回旧转发模式；需要旧方式时另建兼容配置。更换池域名或 PowerDNS 预设前，同样需停用并同步清理已有托管记录。删除池需先解除落地引用并完成 DNS 清理。数据库回退在仍存在 DNS 池、PowerDNS 配置或托管记录时拒绝执行，避免遗失记录归属。
