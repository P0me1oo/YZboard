日期：2026-09-30。版本：面板 `1.33.0`、Node `v1.26.0`、管理端 `0.14.0`；均为未发布工作区构建。

## 环境与来源

用户明确允许本次代理通过 Netcatty 部署、启停和清理隔离测试实例。DGN-HK 运行测试面板及四个前置入口，YT-HK 运行八个 WG 落地；Mihomo 1.19.31 和基于固定 sing-box 核心的完整客户端在本地运行，未使用第三台服务器。全部身份和目录独立，未替换既有 Node 或修改既有服务、防火墙和系统路由。

面板测试源码包 SHA256 为 `74619fa1cc0cc4cbb23fd1bc99050693882c3fc7ca565595080b5b91eb8f876c`，来源为面板基线 `e9591e28c5183563873fa5096dcb89e4f7405a6e` 加本次未提交修改。测试镜像仅复用已发布 `1.32.0` 镜像的运行依赖，应用源码完整替换为测试包；使用 SQLite、Redis 和真实 HTTP／WebSocket 接口。

Node Linux/amd64 测试程序 SHA256 为 `242f350aa4cd4df2810a00558644c42759a6d8f4b5162f0e8fc91150021b2ee4`。构建来源、两种架构和固定核心依赖见 Node 兼容矩阵；两台真实测试机均为 amd64，arm64 仅完成交叉构建。控制面经过临时 SSH 隧道，前置至落地的业务流量直接使用跨机 WG UDP。

## 管理与恢复

- Chrome 访问真实测试面板，编辑 WG 的 MTU 和保活间隔，保存后重新打开仍保持新值，没有页面异常；修改后的链路用两种客户端复测通过。
- 停用全部八个落地后，订阅中的对应线路数由八变为零，两种客户端的十六次旧订阅访问均被拒绝。重新启用后恢复八条线路，原客户端配置无需修改，十六次 HTTPS／UDP 检查通过。
- 将八个落地分别切到另一核心，面板记录与 Node 同步正常。初轮检查出现一次超时；落地 Node 重启后，已切换核心的十六次链路检查均通过。
- 再通过面板切回原核心，不手工重启 Node。十六次检查最终通过，其中四条线路第一次请求超时，第二次成功；从开始探测到成功耗时约 16.5–18.1 秒。本项证明可恢复，不证明重载期间连接无中断，也不是所有网络环境的恢复时限保证。

## 计费与资源

停止两端测试 Node 并等待队列处理完毕后，163 个报告批次全部完成，其中 69 个包含用户流量。用户累计上传 **184,229** 字节、下载 **428,527** 字节，与唯一批次合计逐项一致；WG 落地没有包含用户扣费的批次，失败任务数为零。调试期间实际产生的流量也计入，没有为保持收发对称删账。

测试期间的采样值为：面板容器约 457 MiB，前置 Node 约 229 MiB，落地 Node 约 156 MiB；两台机器仍有可用内存。Node 设有 384 MiB 的 Go 软内存目标。这些是少量测试连接下的采样，不是高并发容量或峰值保证。

## 测试限制与清理

早期直接把 sing-box 出站接口接到 HTTP 探测程序时，个别组合发生提前关闭或超时，未据此修改产品。改为完整 sing-box 客户端监听本地代理端口、由其正常转发请求后，八种组合及恢复验证通过；直接接口探测的失败记录保留，不将其描述成全程一次通过。测试期间控制面隧道数次断开，重新连接后恢复；业务转发链路不经过这些隧道。

本地 Node 全量回归另有一次既有退出重试计时测试失败，服务包独立重测及该项十次复测通过，原因未确证；没有运行本地竞态检测。上述结果不替代 MySQL 并发、高并发容量或所有客户端版本的验证。

测试结束后，两台 Node 临时服务、测试监听、面板容器、Redis 数据卷、Compose 网络、测试镜像和两台测试目录已删除；两条临时隧道及规则已删除，测试终端已关闭。本地 27 份私有测试文件和客户端运行缓存已删除，保留无凭据测试材料与构建产物。DGN-HK 保留原有 Docker 软件及无实例凭据的基础镜像、构建缓存。没有更新生产服务，没有创建 Tag、Release 或发布镜像。
