# 日志管理

面板 `1.103.0`、管理端 `0.74.0` 和 Agent `v2.23.0` 为本地开发版本，尚未发布。在管理端“日志管理”查看系统、Agent 和用户日志，仅管理员可查询。

当前面板 `1.104.1`、管理端 `0.75.1` 配套 Agent `v2.24.0`，新增按节点名称选择筛选；保留此前日志及 Xray 崩溃通知修改，尚未发布。

## 系统日志

面板运行日志沿用现有 `storage/logs` 文件，不重复写入数据库。可选择最近 14 天的日期、级别和关键词，最新记录在前。每个文件最多读取末尾 2 MB，文件较大时页面明确提示范围。只展示日志条目的首行，不展示原始请求、配置或完整堆栈；密码、令牌、完整链接、身份标识和密钥内容经过隐藏。

“管理员操作”复用已有操作审计，显示操作、管理员和来源 IP，不返回原请求参数与地址。沿用原三个月清理规则，页面只查最近 90 天。仅写入标准错误、系统日志或其他外部日志渠道时，面板不能读取这些渠道的历史；当前页面只支持本机标准 Laravel 文件。

## Agent 日志

以机器和节点为筛选条件，来源分为 Agent、Xray 和 sing-box，可按级别、时间和关键词查询。Agent 的节点启动、配置更新、控制通道和故障日志关联所属节点；机器发现、机器操作等关联所属机器。sing-box 原始运行日志关联核心实例的节点。

在“节点”下拉框选择名称后点击“查询”；名称后显示编号以区分同名节点。默认“全部节点”，清空筛选后恢复全部记录。选项包含当前节点（包括隐藏或停用节点）和最近 7 天日志中的已删除节点；现有节点使用当前名称，已删除节点使用最近入库记录的名称。节点列表读取失败时可重试，也可直接填写节点编号。筛选只返回明确属于所选节点的记录，不包括没有节点归属的机器级日志；机器、来源、级别和时间等条件可同时使用。

Xray 原始日志处理器在进程内共享，不能准确推断节点。进程仅管理一台机器时归属该机器，单独运行一个节点时归属其上报身份；同进程存在多个独立身份时仅保留本地输出，不把原始日志复制给多个身份。节点生命周期与启动失败仍有对应节点的 Agent 记录。查看节点日志时可同时查看该机器的 Xray 日志。

采集沿用当前 Agent 与核心日志级别，不自动开启调试或逐连接访问日志。Agent 在入队前隐藏敏感内容，面板入库和返回前再次处理。每 5 秒独立批量上报，每批最多 128 条，每个上报身份最多缓存 4,096 条及一个待确认批次；队列满会在后续有空间时保存丢弃数量。上报不与流量结算或转发互相等待。

批次编号在发送前落盘，确认后移除，断网重试与重启沿用同一编号，面板重复接收只保存一次。缓存位于对应配置目录，文件名为身份摘要，Linux 权限为仅当前用户读写。损坏缓存保留原文件并停用本次运行的采集，不影响代理运行。突然终止可能丢失最近一次落盘之后的内存记录；存储错误、持续超量或长时间不可达不能保证全量保存。

保存最近 7×24 小时，查询立即排除到期记录，调度器每 5 分钟分批清理。新面板握手声明 `agent_log.version=1`，旧面板不接收新日志；旧 Agent 的原有功能保持，新采集只在配套程序启用后生效。面板不会补采服务器原有日志文件。

## 用户日志

记录登录成功、已知账号的密码错误、账号停用、登录限制、两步验证错误，以及修改和重置密码成功；改密时旧密码错误也记录。完成认证并签发会话后才记录成功，注册后自动签发会话同样作为成功登录。未知邮箱不创建虚构用户记录。日志保存失败不改变认证或改密结果。

用户触发连接数、每秒新建连接和设备数限制时，保存用户、节点、事件时间、来源 IP（原快照有提供时）、本批拒绝次数、当时上限及观察值。复用原 Agent 的周期汇总和通知事件，不逐个重连写记录。面板 `1.104.3` 起，带编号的批次独立登记接收状态，日志与通知共同提交；HTTP、长连接和仅有限制事件的重试也只处理一次，失败后可使用原编号恢复。不带编号的历史客户端上报无法保证跨请求去重。

“触发带宽限速”按每秒采样核心共享带宽令牌桶的欠额，仅配置限速但没有发生等待不记事件。次数显示检测到欠额的秒数，上限为 Mbps；不是被拒连接次数，也不能视为完整等待时长。短于采样周期的等待可能未被观察到。原限速器、转发等待方式及计费不改变，该事件不触发原连接频率提醒。

已组成上报批次的限制事件随原编号落盘恢复；尚未组批或强制终止前尚未保存的事件可能丢失。用户日志保存最近 30×24 小时，每 5 分钟分批清理。订阅获取和代理访问仍使用原统计页面，不重复采集。

## 数据与兼容

新增 `v2_agent_log` 与 `v2_user_event_log` 两张表，迁移只创建新表，不重建既有数据。管理查询为管理前缀下 `GET logs/system|agent|user`，带现有权限、查询并发与耗时限制；每页最多 100 条，响应禁止缓存。时间按面板时区查询和显示。

Agent 上报为 `POST /api/v2/server/agent-log`，机器模式使用 `POST /api/v2/server/machine/agent-log`，复用现有认证，仅允许关联该身份的节点。每次最多 256 KiB，不接受任意附加日志字段。已移除节点的迟到条目确认并丢弃；存在但属于其他机器的节点拒绝接收。

正式使用须先更新包含迁移与查询的面板，再更新 Agent。当前未发布，不提供服务器更新命令。两个核心依赖保持原固定版本，无核心源码修改。回退到旧版本时可以保留新日志表，但旧版本没有到期清理任务；撤销新增迁移会删除新日志全部数据。
