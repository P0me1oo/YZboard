# 独立 Telegram Bot

## 版本与范围

开发中版本：面板 `1.39.0`、管理端 `0.19.0`，尚未发布。新增测试发送和投递诊断，无数据库迁移，不需要修改 Node。

本功能已从 `feat/telegram-bot` 工作区合入面板 `1.32.0`、管理前端 `0.13.0`，与实时通信和用户管理一起交付。正式发布状态见面板兼容矩阵。

功能开发基线为面板 `ea81b888137b0003de0eeddb1f77e29fe5af7a45` 和管理前端 `18f6f7c4b1869b5eecc445d8f39f9705faa0ec89`。合并保留实时通信与用户管理源码，两边测试断言均保留；管理端从合并源码重新构建，不沿用功能工作区的旧基线产物。

这是面板内置功能，不依赖旧 Telegram 插件的安装、启用、消息钩子、控制器或 API 客户端。旧插件及其历史数据保持原样，不自动迁移。旧用户页面中的 Telegram 字段仍属于旧接入，新模块以独立的「绑定记录」页面为准。

第一阶段只提供个人账号绑定和查询，不提供全站通知、管理员工单回复、群发、续费下单、批量改绑或管理端强制解绑。

## 账号操作

- 私聊机器人发送 `/start`。未绑定时提示发送本面板订阅链接；已绑定时展示主菜单。
- 链接必须能唯一匹配仍存在的 XBoard 用户。允许订阅已过期的账号绑定；旧 Token 被重置后不能再用于首次绑定。
- 一个 Telegram 用户与一个 XBoard 用户分别最多有一条新模块绑定，不能覆盖或抢占已有关系。
- 绑定后显示「订阅信息」「订阅链接」「账户信息」三个内联按钮。订阅信息包含当前套餐、状态、到期时间和流量；订阅链接每次按当前账号重新生成。
- 账户信息提供解除绑定，也可发送 `/unbind`。确认有效期为五分钟；取消、过期、已使用或重新绑定前生成的确认不能解除后来的关系。
- 群聊不执行账号操作。每次文本或按钮操作都按实际 Telegram 发送者重新查绑定，不能通过按钮参数选择其他用户。

链接仅在首次绑定时用作身份凭据。续费、流量重置、套餐变化、订阅地址或 Token 变化、订阅过期、机器人停用以及配置变更都不会删除绑定。用户单个或批量删除时，由数据库级联清理该用户的绑定；重新注册同一邮箱不会继承旧绑定。

## 链接识别

支持面板配置的订阅域名、域名中的数字范围和随机标识模板，以及以下两种订阅形式：

- 当前订阅路径：面板设置的订阅前缀加账号订阅标识。
- 旧订阅接口：`/api/v1/client/subscribe` 的订阅查询参数。

只在本地解析链接并查询数据库，不访问用户提供的网址，不展开短链。不接受任意外部域名、裸订阅标识、重复或数组形式的订阅参数，以及带账号密码的 URL。插件自行改写为其他凭据或未支持路径的链接，暂不能用于首次绑定；这不影响已经建立的绑定。

## 管理页面

配套代码完成部署后，入口为「系统管理 / Telegram Bot」，不在插件管理中。

### 机器人设置

1. 填写机器人密钥，确认消息接收地址是当前面板可访问的 HTTPS 地址。
2. 点击「保存」。保存仅写入配置，不会向 Telegram 发起请求或切换接收地址；已保存的密钥不回显，留空表示不修改。
3. 点击「验证连接」，检查机器人身份、接收地址、待投递消息和最近一次投递错误。「接收地址已登记」只表示 Telegram 登记的地址与配置一致，不保证实际消息已到达。
4. 点击「启用」并确认，才注册消息接收地址和私聊命令。发现该机器人已有其他接收地址时拒绝静默覆盖。
5. 停用同样需要确认。停用保留绑定，不主动丢弃待处理消息，也不会删除已经归其他接入使用的接收地址。

同一个 Telegram 机器人只能使用一个消息接收入口。若复用旧机器人，需要先明确停用旧接入；本模块不会擅自关闭旧插件、接管机器人或迁移历史绑定。

### 测试发送与故障定位

- 在「测试接收人」填写 Telegram 数字 ID，不能填 `@用户名` 或群组 ID；接收人须先在 Telegram 私聊该机器人发送 `/start`。即使接收地址故障、没有面板绑定记录或机器人本地未启用，也可使用已保存的密钥测试发送。
- 点击「发送测试消息」后，只发送固定测试文字。Telegram 返回对应私聊消息的确认结果后才提示成功；成功发送后十秒内禁止重复测试。失败可重试，输入保留。
- 测试发送不写入接收时间、不建立账号绑定，也不修改或重新登记消息接收地址。看到测试消息只能确认面板能够向 Telegram 发消息；回复 `/start` 才能继续检查反方向。
- 「刷新状态」使用已保存配置重新查询 Telegram，不覆盖表单里未保存的内容。待投递消息数量和经过分类的最近一次失败原因会显示在页面上，常见类别包括 HTTP 拒绝、路径不存在、服务错误、证书、域名解析、超时和连接被拒绝。
- 只有接收地址匹配时才显示该地址的投递错误。没有待投递消息、且面板收到消息的时间晚于 Telegram 记录的错误时，下一次检查清除历史告警；待投递消息仍存在时保留告警。远端错误原文不保存或回显，以免夹带认证信息。

若私聊发送 `/start` 后刷新仍为「尚未收到消息」，先查看投递错误：HTTP 403 需要区分入口拦截与来源校验失败，HTTP 404 检查路径和反向代理，HTTP 5xx 检查面板服务日志。具体服务器原因必须以实际诊断结果为准，不能仅凭地址登记成功判断。

启用期间以及注册结果未确定时，不允许直接换密钥或接收地址，应先停用。网络失败导致停用未确认时可重试；如果 Telegram 明确返回旧密钥已失效，则停止本地接收并允许保存新密钥，但不能声称远端地址已经移除。新密钥启用前仍会重新核对接收地址。

### 绑定记录

按邮箱或 Telegram ID 查询，分页显示账号、Telegram ID 和绑定时间。该页面使用面板管理员权限；普通用户无法调用这些管理接口。机器人私聊查询与管理员查看绑定记录是两个不同入口。

## 数据与消息处理

新增三张主应用数据表，不放入插件迁移：

- 机器人配置（`v2_telegram_bot_configs`）：密钥使用现有应用加密密钥加密存储；接口只返回是否已配置及非敏感状态。
- 账号绑定（`v2_telegram_bot_bindings`）：保存用户编号、Telegram ID、绑定时间和短期解绑确认。两端分别设置唯一约束；用户外键使用与现有用户主键一致的有符号整数类型，并启用删除级联。
- 消息处理记录（`v2_telegram_bot_updates`）：按机器人与消息编号防重，只保存动作、账号绑定记录编号和处理时间，不保存原始消息、订阅链接或订阅 Token。

绑定及业务处理状态在同一事务内提交。发送失败可以重试，但已经完成的绑定或解绑不会再次应用。缓存锁用于协调同一 Telegram 的请求，账号关系以数据库为准，清缓存不解绑。

消息记录按面板现有定时任务每天清理七天前的数据；超过七天的旧文本不会再次触发绑定。解绑确认本身短期且一次性有效。Telegram API 请求超时后，无法保证外部回复严格只发送一次，但重复投递不能重复改变绑定。

消息入口使用 Telegram 官方请求头密钥校验；出站请求使用 POST JSON，关闭订阅链接预览。日志不记录原始消息、完整链接、机器人密钥或带密钥的异常 URL。管理端审计仅记录操作和配置变更标志。

## 验证与限制

自动化测试覆盖绑定与双向唯一限制、过期账号、当前链接生成、订阅资料变化后关系保持、用户单个与批量删除、主动解绑、旧确认、消息重试、私聊身份隔离、配置启停和凭据失效后的恢复。机器人请求由本地 HTTP 模拟替代，未使用真实机器人密钥。

前端包含源码行为测试、浏览器交互测试、桌面和窄屏检查。合并后的构建产物同步主面板资源目录，具体执行结果记录在兼容矩阵和管理端维护说明中。

功能工作区源码开发模式检查曾在退出现有订阅模板编辑器时发生 `Canceled` 异常。合并后独立执行完整开发模式检查通过，包含编辑器输入后切换 TG 页面，没有复现该错误，也未修改编辑器或忽略页面异常。最终完整回归结果以兼容矩阵为准。

Telegram 功能使用本地模拟请求验证，没有使用真实机器人密钥或验证真实 Telegram 投递。MySQL/MariaDB 实际并发尚未验证，SQLite 测试不等同于这项验证；实时通信的双机联调记录不作为 Telegram 实际投递证据。
