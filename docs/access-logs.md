# 访问记录

面板 `1.86.0`、管理端 `0.58.0` 与 Node `v2.13.0` 配套使用。

在管理端「统计分析 → 访问记录」查看用户通过代理节点发起的连接。仅管理员可以查询。默认显示今天，支持最近 7 天、自定义时间、用户邮箱或编号、节点名称或编号、目标地址和端口筛选。连接时间按面板时区显示；翻页固定本次查询的记录上限，点击刷新查看新记录。

## 记录范围

- 每条记录包含用户编号、入口节点及名称、连接时间、目标域名或 IP 和目标端口。用户邮箱由现有用户资料关联，不上报用户认证信息。
- 记录经过身份和连接准入检查、交给核心处理的目标请求。时间是 Node 观察到该请求的时间，不是网页加载完成时间，也不保证远端连接成功。
- 优先使用代理请求携带的域名；sing-box 也可使用现有路由处理已经识别的域名。无法取得域名时保存目标 IP。不会为此开启新的内容嗅探、DNS 反查或 TLS 解密。Xray 在现有 Node 调度入口取得目标，不额外等待内部嗅探。
- TCP 按逻辑连接记录，UDP 按核心创建的目标会话记录，不逐个数据包记录。普通 WireGuard 在 Node 的用户准入层记录。中转记录归属用户连接的入口节点，落地不会重复记一条访问，也不会把落地服务器地址当成最终目标。
- 不保存 URL、网页路径、查询参数、请求头、请求正文或通信内容。域名以小写 ASCII 形式保存，国际化域名使用 Punycode；IPv6 使用规范化形式。
- 只记录新版本启用后发生的请求，旧数据不能补造。旧 Node 可以继续上报流量，但不会产生访问记录；新 Node 只有在面板握手声明支持后才开始采集，独立运行模式不采集。

## 保存与上报

面板保留最近 7×24 小时的记录，查询立即排除到期数据，每 5 分钟分批清理。需要保持项目原有调度器运行。迟到或重试的过期记录会被确认，但不会重新入库。

Node 每 5 秒由独立协程批量上报，每批最多 256 条，与流量计费及状态上报分离。批次在发送前保存到节点自己的配置目录，确认后清除；相同节点、批次和位置仅保存一次。快照中的批次编号固定，重启或确认响应丢失时重发不会产生重复记录。缓存文件使用仅当前用户可读写的权限，文件名区分面板、机器和节点，不包含凭据。

为避免记录故障影响代理转发，每个节点最多缓冲 32,768 条。长时间断网、磁盘错误或持续超量时不能保证全量保存；队列满会在 Node 日志中记录丢弃数量，不输出目标地址。突然断电或强制终止可能丢失最近一次快照后的记录；正常退出会保存剩余队列。损坏缓存保留原文件并停用本次运行的采集，避免覆盖；应先检查节点日志再处理该缓存。节点停用期间没有后台任务清理其缓存，重新启动后会排除过期批次。

## 接口与兼容

`POST /api/v2/server/access-log` 复用现有节点或机器认证，记录的节点归属来自认证结果。JSON 仅传递批次编号及记录列表；单条记录只允许用户编号（`user_id`）、连接时间 Unix 秒（`connected_at`）、主机名或 IP（`destination`）、端口（`port`）。单次请求最大 128 KiB，最多 256 条，拒绝非法主机名、附加内容字段及超前超过 5 分钟的时间。面板确认返回相同批次编号后，Node 才移除缓存。

管理查询使用现有管理员路由下的 `statistics/accessLogs`，不向普通用户开放。新增表 `v2_proxy_access_log`，不修改流量账本、套餐扣费或已有统计。两个核心保持现有固定依赖，无核心源码修改。回退旧面板和 Node 可以保留新增表；撤销数据库迁移会删除访问记录，应按需先备份。

旧面板没有访问记录清理任务。回滚后如保留新表，应单独安排到期数据清理，不能继续依赖旧版本自动执行 7 天留存规则。
