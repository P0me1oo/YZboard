# 主控与 Node 运行开销优化

## 1.111.9：插件命令与账号协调开销（已发布并部署）

普通 HTTP 请求初始化插件时，注册插件命令不再立即构建完整的 Artisan 控制台应用。命令对象仍在原位置创建，命令运行、列举或其他实际控制台调用时再按原顺序登记；已经启动的控制台立即登记。自定义控制台内核沿用原接口。插件启停、配置、动态路由与请求钩子继续按原请求周期处理。

设备协调每次仍在账号锁内从 Redis 读取当前完整账号记录。普通 `RedisStore` / `PhpRedisConnection`、未启用客户端序列化和压缩时，只对至少 4 KiB 且不超过 4 MiB 的记录保留解码备忘；只有最新原值逐字节完全相同才复用数组。每个进程最多 128 项、4 MiB 原始内容，按最近使用顺序淘汰；解码数组有额外内存开销。Octane 启动时预建该读取器，使连续请求能复用；长连接使用同一容器单例。返回值与备忘隔离，缓存删除、内容变更、损坏和读取异常不会使用旧授权。

此改动减少重复解码，不减少 Redis 读取次数或返回字节数。自定义缓存仓库和存储、集群、客户端序列化或压缩继续原读取。持有节点集合在协调前后各计算一次，供队列登记及退出清理共用；保留队列丢失修复、保存失败、撤销和真实归还确认。

新增局部基准使用接近此次线上形态的“大账号记录、小节点快照”：47 个账号、64 个节点，账号记录约 1.89 MB、节点快照约 48 KB，20 轮同步；另测 200 次插件初始化。使用同一份 `tests/Fixtures/RequestOverheadBenchmark.php` 和 `tests/Feature/PluginInitializationTest.php`，在独立的固定 1.111.8 检出与候选工作树分别运行：

```bash
# 固定 1.111.8 检出；先复制上述两份测试文件，使用专用本机 Redis。
YZ_BENCH_BASELINE=1 YZ_TEST_DEVICE_REDIS_PORT=16483 php vendor/bin/phpunit tests/Fixtures/RequestOverheadBenchmark.php --do-not-cache-result
# 候选工作树
YZ_BENCH_BASELINE=0 YZ_TEST_DEVICE_REDIS_PORT=16483 php vendor/bin/phpunit tests/Fixtures/RequestOverheadBenchmark.php --do-not-cache-result
```

基准只使用随机隔离测试键，不读取生产身份或状态。两份测试文件用于保持插件固定测试输入一致；不是把测试目录复制到生产。基准包含稳态同步预热，不能作为冷启动、真实业务请求率或整机 CPU 降幅。具体实测及回归范围见[兼容矩阵](../YZ_COMPATIBILITY.md)。

2026-10-30 部署 Cloudnium-US 后，以切换前两组、恢复后三组约 30 秒计数器采样对照：面板容器平均 CPU `154.93% → 141.83%`（100% 为一个核心），整机非空闲率 `96.45% → 90.82%`，44 台机器保持近期上报。Redis 返回量约 `3.44 → 3.71 MB/s`，没有观察到读取流量下降。前后包含不同的定时任务及宿主机抢占波动，不能把全部差异归因于本版，也不能将局部 78% 基准外推为整机收益。内部公共接口三次响应由 `2.04–3.22 秒`变为 `0.29–1.79 秒`，样本不足以计算延迟分位数；源站 HTTPS 返回 200，公网匿名 curl 探测被 Cloudflare 拦截为 403，未修改其访问规则。

## 1.111.6：设备协调解码复用（已发布）

同一轮设备许可同步会按账号依次加锁，多个账号往往需要读取相同节点的完整快照和队列。普通单机 phpredis 缓存现在仍在每个账号锁内执行一次完整批量读取，逐字节比较最新原值；内容相同时复用解码后的数组，变化或删除时立即替换或移除本轮记录。返回值与复用结果相互隔离，调用方修改不会污染后续读取。

解码结果只存活于本轮同步，最多保留 2,048 项、8 MiB 原始内容；解码数组还会占用额外内存。超过范围继续正常读取，不跳过校验。自定义缓存、Redis 集群、客户端序列化或压缩保持原读取。缓存不可用或当前内容损坏时抛出异常，不返回之前的状态。权限、锁、队列修复、设备名额、撤销、许可确认序号和一小时时限均不变，无数据库迁移或缓存格式变化。

机器接口和长连接认证复用单独的心跳保存方法：同一秒已经记录时直接返回，避免重复运行完整模型保存流程；条件更新防止较旧时间覆盖新心跳，并且不会顺带保存其他字段。没有延长心跳间隔、权限缓存或节点上报间隔。

基准使用独立 SQLite 与本机测试 Redis，不读取生产配置：

```bash
YZ_TEST_SUBSCRIPTION_REDIS_PORT=16379 php vendor/bin/phpunit tests/Fixtures/DeviceCoordinationBenchmark.php --do-not-cache-result
```

固定 128 个节点、40 个账号，每次执行 5 轮同步；输出总耗时、PHP CPU 时间、Redis CPU 时间和 Redis 返回字节数。测试键使用随机独立前缀并在结束时清理。前后比较应使用相同机器、PHP、Redis 和依赖，并交替运行以减少时序影响；此优化主要减少 PHP 解码开销，Redis 读取次数与传输量保持原有规模。测量与完整回归记录见[兼容矩阵](../YZ_COMPATIBILITY.md)。

2026-10-30 部署 Cloudnium-US 后，更新前后各三次 20 秒采样中，面板容器平均 CPU 为 158.25% 与 160.33%（100% 为一个核心），整机忙碌为 94.56% 与 94.69%；HTTP 请求率约 75.23 与 69.49 次/秒。采样时段与业务组合不同，不能据此归因微小差异，但没有观察到整机降幅。已确认普通 phpredis 解码复用路径启用，服务版本正确、接口可用；本版本没有解决该机的高 CPU，后续需要针对实际生产调用栈确定主导开销，而不是继续外推固定合成场景的约 54% PHP CPU 降幅。

## 排查依据

2026-10-08 对 Cloudnium-US 的只读观察中，设备来源同步约每秒 81 次，占当时约每秒 91 次 HTTP 请求的 89%。30 秒进程采样中，Web PHP 约占一个核心的 81%，节点 WebSocket 约 25%，数据库约 18%。这说明设备同步反复经过 HTTP 鉴权、应用启动和数据库读取是重点优化对象；请求占比不能当作 CPU 降幅。

该机 20 GB 磁盘约使用 93%，镜像及解压数据约 9.63 GB，站点访问日志约 1.62 GB。代码优化可减少设备同步访问日志的新增量，但不会清除已有镜像或日志。本次没有清理、重启或部署服务器，历史磁盘占用需另行处理。

## 设计与参考

对照 Komari 主控固定源码 `e48aa1e76931132fb5dc93ce53763dd59df83d9f`，借鉴同一认证长连接复用、最新状态共享、重复工作合并和有界发送的思路。设备授权和关闭确认仍在实际处理完成后返回；流量批次仍沿用可靠接收与去重结算，没有照搬监控报告入队即确认的做法。

| 路径 | 调整 | 保留的规则 |
| --- | --- | --- |
| 设备会话、申请、同步 | 复用机器已有 WebSocket，HTTP 和 WebSocket 调用同一处理入口 | 按节点权限检查用户，重复请求不会新增同一来源授权 |
| 来源未变化 | 完整快照确认后每秒轻量续期，存活和序号单独存储 | 不改变最近新建连接时间，不把续期当成关闭 |
| 来源发生变化 | 新连接、待处理申请、退出来源变化时发送完整内容 | 旧连接真实关闭后才归还名额 |
| 管理页面 | 每秒合并通知，同一订阅共用快照及摘要，无人订阅即释放缓存 | 首次订阅立即调度，定时检查过期，保留捕获版本 |
| Node 系统采样 | 同进程多节点复用最近一秒 CPU、内存、磁盘、网卡与运行指标 | 按需采样租约及各节点连接、流量统计独立 |
| Node 发送积压 | 心跳合并，控制优先，消息条数、字节数和等待确认数共同限额 | 可靠业务不静默丢弃，失败进入原补偿路径 |

## 通信与恢复

握手分别声明设备长连接能力（`device_handover_ws=1`）和快照续期能力（`device_handover_renewal=1`），不改变原设备协议版本。事件为 `device.begin`、`device.admit`、`device.sync`，各自使用同名 `.ack` 或 `.error` 确认。Node 同时匹配请求编号、节点和操作；换用 HTTP 时保留原运行身份、序号与业务内容。

完整快照被确认后，Node 比较来源、待处理申请和退出来源；来源年龄自然增加不算变化，新连接序号必须相同才可续期。续期只带运行身份、递增序号、已确认完整快照序号和未变化标记。完整来源仍留在共享缓存，续期只更新小记录；Redis 通过 `EXISTS` 检查完整记录，避免框架 `has()` 读出全部内容，其他缓存驱动保留兼容检查。只有同一运行身份和完整快照基线的记录才能合并读取。需要撤销的来源仍随续期确认返回。

缺少续期基线返回 412，Node 按同一序号补发完整内容；会话失效仍返回 409，按原规则关闭旧来源后重新建立会话。重复或过期报告不倒退状态，也不延长存活时间。面板回滚、不支持续期校验时，Node 停用续期并恢复完整同步。旧 Node 对新面板继续使用原 HTTP 完整同步；新 Node 连接旧面板时只有声明支持的能力才会启用。

发送队列有 64 个普通位置、16 个控制位置，普通积压上限 8 MiB，控制请求另保留 64 KiB，心跳最多合并为一个待发响应。上述字节数约束排队数据，不包含当前正在发送的单条消息及调用方原始采样。等待确认最多 512 项；队列满会明确返回失败，已取消且尚未发送的请求跳过发送。流量磁盘补报和设备重试仍按原编号执行。
