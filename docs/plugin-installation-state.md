# 插件安装状态保留

维护者：P0me1oo。修复始于面板 2.15.2，已随 [2.16.2](release-2.16.2.md) 发布并部署；本次前后核验确认生产插件安装记录和配置保持一致。下方保留原排查与开发验证记录。

## 行为

插件文件存在与插件已安装是两个条件。管理列表通过 `v2_plugins` 中是否存在对应 `code` 判断安装状态，插件配置、安装时间和启用状态也保存在这条记录中。

旧实现遇到缺失的 `Plugin.php` 会直接删除记录；启用时找不到插件实例也会删除记录。临时目录没有复制插件却连接了生产数据库，或者更新文件时恰好发生加载，都可能因此丢失安装状态和配置。重新安装会创建默认配置，不能恢复原自定义设置。

2.15.2 移除这两处隐式删除：

- HTTP 或控制台初始化、定时任务注册时，入口不可用则记录错误并跳过该插件，其余插件继续加载。
- 启用操作失败时返回原有错误，保留原启用状态和完整数据库记录。
- 缺失文件恢复后，后续初始化可以使用原配置加载，不需要重新安装。已加载过错误文件的常驻进程可能仍需按部署流程重启，文件替换不会自动清除 PHP 已加载的类。
- 管理列表中的“已启用”表示数据库保存的启用设置，不能单独证明入口加载成功；应结合文件和错误日志检查。整个目录缺失时，原有列表扫描仍无法展示该插件。
- 明确卸载仍执行插件清理、迁移回退和记录删除；入口不可用时仍会按原行为报错，本次未引入强制卸载或自动重装。

没有数据库迁移、管理端资源或 Agent 协议变化。
