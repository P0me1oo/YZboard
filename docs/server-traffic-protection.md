# 服务器流量保护

面板 `1.82.0`、管理端 `0.54.0` 和 Node `v2.11.0` 已配套发布。先更新面板，再升级所有 Node，包括前置和落地，最后设置服务器额度。

## 设置与计量

在新建或编辑服务器中设置流量上限、计费方式和每月重置日。上限单位沿用项目约定，1 GB = 1024³ 字节，0 表示不限。单向只计网卡出站，双向计入站加出站；与用户套餐的上传、下载方向和倍率无关。

旧服务器默认不限。首次开启保护时从 0 开始，不回推当月历史、不提供手动校准。以后关闭再开启保护、修改名称、提高额度或改变计费方式都保留本周期累计；入站、出站独立保存，切换计费方式重新计算当前用量。

Node 在 Linux 宿主机网络空间读取网卡累计字节。默认识别主路由表中 IPv4、IPv6 的默认出口，解析 VLAN、bond 的底层网卡并去重，不累计隧道、容器、回环及重复桥接接口。计费网卡可手动指定，多个名称用逗号分隔；多出口桥接或特殊策略路由需要明确指定外网网卡。云主机由虚拟化平台提供、在来宾系统中表现为硬件设备的网卡可以正常使用。容器部署必须能看到宿主机网络及其系统计数。

计量包含所选网卡上的实际收发，包括协议开销和非代理程序的流量；服务器列表显示本周期使用量、总量及进度条。原服务器代理流量、节点用量和历史承载量仍留在统计页面与数据库中，不能拿它们替代网卡计量。

## 重置、恢复与保护

- 按面板时区，每月指定日零点开启新周期；31 日遇二月取二月最后一天，下一月仍按 31 日。改变重置日只调整下一次归零时间，保存时不会清空已用量。
- 本地每秒采样并持久化，约每五秒上报，超限变化立即进入发送队列。采样间隔内的新增流量可能略微超过额度；跨零点的一次采样增量保守计入新周期。
- Node 停机跨越周期时，网卡累计值不能准确拆分零点前后的用量，恢复后的首个增量也按新周期计入，不用推测值扣减已用量。
- 进程重启保留网卡基线，系统重启或接口计数归零后累计新的计数；面板对同周期累计值取较大者，旧序号、旧代次和旧周期报告不能覆盖当前数据。
- 超限后 Node 关闭该服务器全部受管代理的监听和已有连接，管理连接继续保留。新周期或提高额度后重新读取面板实际启用的节点；不会修改管理员运行开关，也不会恢复手动关闭的节点。
- 落地进入保护时，面板同时向前置推送配置和用户线路权限，保留该线路的明确拒绝规则。通知尚未到达或管理网络中断时，前置旧配置仍指向已停止的落地，连接失败，不回退直出。
- 无法读取指定网卡或保存本地计量状态时，已开启保护的服务器暂停代理。恢复读取或写入后重试。计量状态丢失或损坏且面板确认曾经计量时，暂停至下个周期重建基线，不能通过删除状态或重装清零绕过额度。额度为 0 的服务器不因计量错误停服。

首次启用前，应先确保该服务器及相关前置运行配套 Node。未安装新计量能力的服务器会停留在等待计量状态。服务器管理的进度条会显示等待计量、上报中断、网卡异常、存储异常或达到上限等实际状态。

## 保留与移除

节点编辑中的旧额度输入和基于节点承载量的订阅限制已移除，节点列表只保留“节点用量”，不再显示“承载量 / 上限”。旧额度及承载量数据库字段不删除，不改变用户套餐额度、流量倍率、扣费、线路统计与历史记录。

## 通信与存储

服务器发现响应增加 `traffic` 配置，独立接口 `POST /api/v2/server/machine/traffic` 用服务器身份认证，交换累计计量和当前策略。保护状态不阻断该接口。配置包含代次、版本、本周期起止、时区、重置日、额度、计费方式及计费网卡。上报包含代次、周期、递增序号、累计入站/出站、计量状态及实际网卡名称。

Node 在实例配置目录中以 `machine-traffic-<身份摘要>.json` 保存状态，文件不包含认证信息。临时文件写入并同步后原子替换；常规升级需保留整个实例配置目录。面板在服务器行锁内更新累计量，不接受客户端直接指定用量上限、周期终点或管理员开关。

验证范围与结果见各仓库的兼容及维护记录。发布与产物核验已完成，尚未进行真实服务器联调或部署；回退旧版本将失去新保护能力，应先评估配置与额度。
