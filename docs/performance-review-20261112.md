## 优先优化项

### 1. 合并状态处理中的重复数据库读取

**已确认源码事实：** [主机监控开关](../app/Services/HostMonitoring.php)每次调用都查询 Lite 绑定和接入开关。[节点状态接收](../app/Services/NodeStateService.php)每条状态调用一次；同条状态携带负载、运行指标时，[兼容状态投影](../app/Services/ServerService.php)还会分别调用。机器状态接收与历史保存也有重复判断。已接入 Lite 省掉了部分采样字段，但开关判断本身进入了高频数据库路径。

另一个明确冗余是[日志策略读取](../app/Services/AgentLogPolicy.php)：控制器已经持有认证读取的机器模型，仍按同一机器编号查询一次 `agent_log_disabled`。

**建议实现：** 先让同一条状态处理复用一次读取结果、同次 HTTP 请求复用已经读取的机器字段；再评估按机器批量读取绑定表，并用变更版本失效。绑定、解绑、接入开关和日志隐私开关必须保持现有生效语义，不能直接增加一个跨请求 TTL 后延迟撤销。

参考 Lite 的同次看板构建共用基础资料。减少的调用次数可用测试固定验证；目前没有生产调用栈和 SQL 摘要，不能把全部 905–1,373 次 SELECT 都归因于这一路，也不能承诺整机降幅。

### 2. 减少 WebSocket 同条消息的重复资料检查

[消息处理](../app/WebSocket/NodeWorker.php)先进行一次机器认证，随后带节点编号再次认证；[认证方法](../app/Services/NodeConnectionAuth.php)会重复读取机器资料版本。后续状态处理还会再次读取节点资料。[资料缓存](../app/Services/NodeRuntimeMetadata.php)虽然缓存模型，但每次访问仍读取共享版本。

Redis 当前约 2,029 次 GET/秒、1,115 次 EXISTS/秒、788 次 EVAL/秒为第一窗口计数，说明通信与重复处理值得检查；这些是全服务数字，不是某个函数的独占量。

建议为一次消息建立短生命周期的读取上下文，批量核对版本、复用已经验证的模型和解码结果。保留机器启停、令牌变更、节点归属、发送前校验、账号锁及新旧序号保护；跨账号锁的授权结果不能直接复用。面板已有快照复用和批量 Redis 读取，应在现有路径上补齐重复点。

### 3. 修复两层 HTTP 反向代理的连接复用

生效配置走 `443 → 7001 → 7002`，未配置显式 upstream 连接池，多处转发客户端 `Connection` 头。运行快照中，到 7001 的 TIME_WAIT 约 4,828–5,474 条，到 7002 约 4,966–5,177 条；两层合计接近一万条已关闭连接。47 条到 8076 的 WebSocket 连接保持建立状态。

建议为两层普通 HTTP 配置明确的连接池及正确的连接头，并单独保留 WebSocket 升级路由。验证连接创建速率、TIME_WAIT、请求延迟和重连恢复。现有[连接复用示例](examples/nginx-yzboard-keepalive.conf)可供适配，不能直接套用到所有站点。这里确认了连接创建开销，尚未量化它对 CPU 的贡献。

### 4. 先压缩管理资源，再拆分加载

通过源站 HTTPS 请求当前管理主脚本，携带 `Accept-Encoding: gzip, br`：返回 200，未返回 `Content-Encoding`，实际下载 **6,946,903 字节**。本地对相同文件进行 gzip level 6 压缩后为 **1,868,847 字节**，传输体积可减少约 **73.1%**；这是文件大小对比，不代表页面耗时必然下降同比例。

第一步为 JS/CSS/语言资源配置源站压缩，确认 CDN 与源站的缓存、Vary、压缩行为；带内容摘要的静态文件采用长期缓存，HTML/入口清单保持适当更新策略。

第二步评估管理端按路由、编辑器和统计模块拆分。当前 `YZboard-Dash/vite.config.mjs` 强制把 features/api/runtime 放入同一应用块，路由表中的 lazy 写法没有实现相应网络拆包。恢复的运行时有初始化顺序与共用 React 约束，必须从源码调整并做受影响页面验证；仅压缩文件不会减少浏览器解析的代码量。

## 需要实测后决定的调优

- **PHP 字节码缓存与回收频率：** 生产 `opcache.enable_cli=0`，HTTP 每 500 次请求回收工作进程；一次 12 秒观察中已看到 HTTP 工作进程替换。可单独对 Octane 试验 CLI OPcache，观察启动耗时、CPU 和各服务实际内存后再调整回收阈值。长驻 PHP 本来就复用已加载类，不能假定开启后每次请求都能省去一次完整编译；也不建议先扩大所有 PHP 进程数。
- **Lite 请求等待占用 HTTP 进程：** [LiteMonitor 的缓存锁等待](../app/Services/LiteMonitor.php)每 100 ms 轮询，最久 12/22 秒；生产只有两个 HTTP 工作进程。Lite 上游变慢且多个管理请求同时到来时存在占满工作进程的风险。当前没有实测该情形，可评估更短等待、明确的重试响应，或只对允许过期展示的数据异步刷新；不能返回旧的绑定、额度周期或权限结果。
- **透明大页：** 系统为 `always`，多个 PHP 进程有约 18–44 MiB 的匿名大页。Lite 新版本采用进程内禁用 THP 并收紧缓存；可借鉴按服务对比实际内存和缺页的做法。匿名大页大小不等于浪费量，本次不据此推导能释放多少内存，也没有修改系统大页设置。
- **插件初始化：** 管理器使用请求作用域，每次初始化会查询启用插件、登记路由和钩子。可在 HTTP 分段采样后区分可缓存的静态元数据与必须每请求重建的钩子；直接改成单例会影响请求隔离，不作为未经验证的快速修改。

## 数据库空间与长期增长

数据库表和索引合计约 **2,396 MiB**；[流量报告表](../app/Models/NodeReportBatch.php)约 **2,067 MiB，占 86.3%**，其中数据约 1,151 MiB、索引约 916 MiB，行数估计约 450 万。MariaDB 数据目录实际约 2.8 GiB，包含数据库内部文件和可复用空间，与逻辑表大小口径不同。

[现有清理](../app/Console/Commands/PruneNodeReports.php)只清空七天后的详细内容，永久保留防重记录。因此这不是直接删除“过期日志”就能安全解决的问题。长期方案是把短期报告内容、处理状态与紧凑的永久防重凭据分离，评估完整摘要的二进制存储以及索引覆盖；必须验证重复上报、历史重放、并发提交和回退，避免重复计费。

本次磁盘仍有 27.4 GiB 可用，没有容量紧急情况。数据库缓冲池已为 1 GiB，三个窗口仅新增 5 次物理页读取，未出现 redo 等待；继续加大缓冲池或降低持久化保证缺乏当前证据支持。`innodb_flush_log_at_trx_commit` 实际为 1，应保留可靠接收与结算语义。

## Lite 可借鉴与已有实现

| Lite 思路 | 面板中的适用方式 |
| --- | --- |
| 看板基础资料共用、singleflight 合并同类请求 | 同次状态/请求共用读取；对允许短暂过期的展示结果合并刷新 |
| 资源有限时限制历史查询并发和缓存大小 | 面板已有两个重查询槽、超时和趋势点上限，应补覆盖缺口而非重复增加一层 |
| 查询临时对象有界复用、只计算必要的统计量 | 减少状态 JSON 重复解码与重复模型查询；缓存有容量上限，不跨越权限或账号锁边界 |
| 监控报告批量写入、实时 Ping 单独处理 | 区分展示采样与可靠业务；计费报告仍须持久化成功后确认，不能直接照搬监控入队确认 |
| 按内存预算收紧缓存、进程 THP 调整 | 分服务测量后调优，不照搬 Go/SQLite 的数值到 PHP/MariaDB |

面板已有按需展示采样、管理快照共享、设备轻量续期、Redis 批量读取、历史分桶及有预算的清理。本轮建议优先修补新路径中的重复工作，不把这些已有能力重新列为待开发功能。

## 验证边界与建议顺序

建议先处理状态读取去重、反向代理连接复用和静态资源压缩，再单独试验 PHP 缓存与回收参数；数据库存储结构调整单独设计。各项拆开验证，保持节点数、上报频率、设备授权和计费语义一致，再比较 CPU、查询数、Redis 通信量、接口延迟与数据新鲜度。

当前节点访问日志关闭，HTTP 聚合诊断关闭，MariaDB `performance_schema` 和慢查询日志也关闭；没有获得准确的接口耗时分布或 SQL 摘要排名。已有访问日志仅捕获少量非节点请求，其中 WebSocket 请求耗时代表连接存活时间，不能作为普通接口延迟。

没有执行生产压测、管理员页面操作或配置试验，因此本文不承诺优化后的资源降幅。一次较长 MCP 采样因工具执行租约到期未完成，已改用三个成功的独立短窗口，未将失败窗口计入结果。没有启动长期采样、修改诊断开关或留下服务器临时文件。仅新增文档，不运行产品回归。
