# 路由拦截记录

面板 `2.11.0`、管理端 `0.95.0` 将拦截记录并入路由管理并按用户汇总。已作为 2.10.1 入口位置的修正部署至 Solid-US LA，见[部署记录](deployment-2.11.0.md)。配套 YZ-Agent `v2.36.0` 保持不变；节点升级后才会产生记录。

## 查看与设置

管理员在“节点管理 → 路由管理 → 拦截记录”查看命中面板禁止访问规则的请求，与“路由规则”在同一页面切换。默认按用户汇总，展示用户、拦截次数和最近拦截时间，次数最多的用户排在前面；点击“查看明细”查看该用户的时间、执行拦截节点、命中规则、目标域名或 IP、端口和 TCP/UDP。无法识别的用户单独归组，已删除账号保留原用户编号。

支持按用户邮箱或编号、节点、规则、目标、端口、网络类型和时间筛选；次数只统计符合当前条件的记录。用户列表与明细分别分页，返回恢复用户列表页码。翻页与展开使用本次查询的记录上限和时间边界，刷新重新读取新记录，过期记录仍按当前保留期限排除。旧地址 `#/logs/block` 自动跳至 `#/server/route?tab=blocks`，日志管理中不再保留独立菜单。

拦截记录默认保存，不提供记录开关，不受“日志设置”中的开关影响。保存天数直接在“拦截记录”标签内设置，默认 7 天，可调整为 1–365 天；缩短期限后查询立即排除到期记录，清理任务随后删除，延长不能恢复已删除数据。机器隐私保护继续优先，开启时面板确认并丢弃该机器节点的拦截上报。

## 记录范围

- 记录“路由管理”中动作明确为“禁止访问”的规则，包括域名、IP 网段、端口、网络类型与 BT 条件。按两个核心最终选中的拦截出站识别规则，不根据普通连接错误推测命中。
- 普通节点、中转入口自身用户、普通 WireGuard 保留真实用户编号。中转落地使用共享认证，不能取得原始用户身份，用户显示“无法识别”；可用用户编号 `0` 筛选这类记录。落地的拦截由落地上报，入口不重复记录，也不推测落地用户。
- TCP 按逻辑连接、UDP 按目标会话记录，不逐个数据包保存。连接被设备数等准入规则提前拒绝时，不算路由拦截。系统防火墙、来源名单、内置私网保护及原生自定义路由没有面板规则编号，不纳入此页。
- 域名优先，无法取得域名时使用请求目标 IP。不新增嗅探、反向查询或解密，不保存 URL、路径、正文、认证凭据或来源 IP。现有 BT 嗅探范围保持原状。
- 规则编号来自执行时配置，规则名和节点名在首次接收时保存；重试或之后改名不覆盖已保存名称。规则在接收前已删除时仍保留编号，不伪造名称；已保存历史不依赖当前规则存在。

## 上报、清理与兼容

握手通过 `block_log.version=1` 声明能力，新端点为 `POST /api/v2/server/block-log`，复用节点或机器认证。记录只能归属上报节点自身，单批最多 256 条、128 KiB；只接收固定字段。每 5 秒独立上报，不让磁盘或 HTTP 等待进入连接处理路径。

节点复用访问记录的有界队列、隐私存储和确认机制，但使用独立队列与 `pending-block-*.json` 文件。每节点最多 32,768 条，发送前保存固定批次，失败按原批次重试；面板按节点、批次和原始位置去重。缓存损坏时保留原文件并停用本次运行的该类采集，磁盘故障、长期离线、超量或强制终止仍可能丢记录。节点待发送缓存最多保留 7 天，面板较长保留期只作用于已入库记录。

新增 `v2_route_block_log` 表，按时间、用户、节点、规则建立索引。查询沿用管理员权限、并发与耗时限制，最多每页 100 条且响应禁止缓存。`GET logs/block` 通过 `view=users` 请求用户汇总、`view=records&user_id=<编号>` 请求精确用户明细，编号 0 表示无法识别；不带 view 时兼容返回旧明细。汇总和分页由数据库完成，当前页用户邮箱单独关联，不把全量记录下载到浏览器。每 5 分钟加入现有管理日志分批清理，单批最多 500 条，达到批数或时间预算后每分钟续跑；重新读取保留期限，保持既有清理游标含义。

需要先完成配套面板迁移和前端集成，再启用配套 Agent；旧 Agent 不产生新记录，新 Agent 面对未声明能力的旧面板不启用新采集。原访问记录接口与字段保持兼容，通用日志设置保持原五类。保存天数独立存储为 `route_block_retention_days`，管理接口为 `GET/POST logs/block/settings`，仅接受保存天数；开发阶段保存过的 `log_settings.block` 开关、恢复时间和保留期不再参与处理。历史连接不能补造拦截记录。

每条面板拦截规则使用保留前缀 `yz-panel-block-` 的原生黑洞出站，自定义出站不能占用该前缀。同一规则编号下修改匹配条件仍可使用现有路由热更新；新增、移除拦截规则或改变动作涉及出站变化，会沿用核心实例重建路径，可能中断该节点现有连接。

回退旧程序可保留新表，但旧程序不会清理新表；回退该迁移会删除拦截历史。验证结果见[兼容矩阵](../YZ_COMPATIBILITY.md)。
