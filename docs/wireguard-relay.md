# WireGuard 中转落地

当前开发配套为面板 `1.46.0`、管理端 `0.23.0`、Node `v2.5.0`，尚未发布。正式发布状态与固定来源见 [兼容矩阵](../YZ_COMPATIBILITY.md)。使用新的 MTU 范围前，前置和落地都需要支持上限 1500 的 Node。

客户端连接 VLESS（包括 Reality）或 HY2 前置，选择逻辑节点后，由前置通过 WG 的 UDP 隧道访问对应落地，再由落地访问目标。前置和落地分别支持 Xray、sing-box，四种组合均纳入验证。客户端不需要配置 WireGuard。

## 管理与配置

创建节点时选择 WireGuard，填写落地地址、连接端口、服务端口，绑定前置入口和落地服务器。默认内核为 sing-box，可改为 Xray。新建节点 MTU 默认 1420，可选 1280–1500；已保存的值保持不变。保活默认 25 秒，0 表示关闭主动保活。停用后从订阅与前置活动出站中移除，重新启用保持原线路编号。

1500 是允许填写的上限，不是推荐值。WG 封装还会增加外层包长度；物理链路 MTU 为 1500 时，隧道内设置 1500 可能引起分片、丢包或降速，通常先使用 1420，再根据实测调整。

WG 只作为中转落地，必须有前置入口。已有 Shadowsocks、VLESS 落地继续使用原配置。节点自身的权限、显示、排序、倍率继承与流量统计沿用现有中转规则。

面板按应用密钥和节点身份分别派生两端密钥，不存储额外私钥。每端只收到自己的私钥和对端公钥，Node 生成对应内核配置。应用密钥或前置绑定变化会改变隧道密钥，需要两端完成配置同步。不要复制运行时配置到文档或日志。

Linux 自 Node `v2.0.0` 起为每条线路创建独立网络空间和 TUN 网卡，wireguard-go 负责加密，Linux TCP 使用 BBR。`v2.5.0` 让 Xray 直接在这些网络空间创建连接、监听隧道内流量，移除额外 sing-box 转接实例及本机转接端口；sing-box 保持原有直接接入方式。两端核心可以混用，用户管理和计费仍由前置负责，落地使用所选核心的路由和出站。

Linux 隧道内使用 SOCKS 传递目标地址，因此域名可交给落地解析；UDP 继续以 UDP 承载。非 Linux 平台仍使用原核心 WG 实现，不与 Linux 系统 TCP 路径混用。运行权限、生命周期及最新验证见 Node 的 `docs/system-wireguard.md`；下方保留历史版本验收记录。

## 验证进度

面板完整回归 387 项、4368 个断言通过，最新 WG 专项 196 个断言通过。管理端完整验证通过，包括 3023 个源码文件检查、50 项行为测试、56 项浏览器测试、构建与开发模式检查；产物已同步面板，5 项资源检查通过。

Node 本地验证通过 VLESS／HY2 与两种前置、两种落地的八种组合，覆盖 TCP／UDP、多落地选路、计费、重复重载、用户撤销、停用恢复及落地重启。Mihomo 1.19.31 与 sing-box 客户端经 Xray VLESS + Reality + TCP 前置、sing-box WG 落地的 TCP／UDP 测试通过，目标为本地测试服务。Linux amd64／arm64 构建通过；Node 全量回归有一项退出重试计时测试失败，随后整个服务包独立重测及该项连续 10 次重测通过，详见 Node 兼容记录。

停用 WG 后，面板继续下发被停用的线路编号：Xray 拒绝对应流量，sing-box 不再注册对应认证身份，避免旧订阅回退到前置直连。落地重启后需要重新握手，恢复期间可能出现短暂超时。

2026-09-30 经用户明确授权，通过 Netcatty 在 DGN-HK 运行隔离测试面板及前置，YT-HK 运行落地，客户端在本地运行。两种客户端的八种跨机组合全部通过 HTTPS 出口核对和 UDP DNS 测试；真实管理页面编辑、停用与恢复、落地核心切换及 Node 重启恢复通过。切换恢复的一轮有四条线路初次请求超时，重试后约 16.5–18.1 秒通过，不承诺连接无中断。临时实例、身份、配置、数据库和隧道已清理，详见 [跨机验收记录](wireguard-acceptance.md)。
