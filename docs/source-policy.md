# 来源 IP 限制

面板 `1.99.0`、管理端 `0.70.0`、Agent `v2.20.0` 新增黑白名单模式。Agent `v2.21.0` 开发版本增加系统防火墙过滤，沿用现有界面和接口，尚未发布。发布状态见[兼容矩阵](../YZ_COMPATIBILITY.md)。

## 设置方式

在节点编辑页打开“高级设置 → 连接设置”，配置“来源 IP 限制”和“接收 PROXY 协议”。保存高级设置后，还需提交节点；取消高级设置会恢复本次打开前的来源限制及 PROXY 接收状态。

- **关闭**：不限制来源，保留填写的名单和大陆屏蔽选择，便于再次使用。
- **黑名单**：屏蔽“屏蔽来源 IP”中的地址，其他来源继续执行原有认证、权限和路由。打开“屏蔽大陆来源 IP”即可一键屏蔽大陆 IPv4 和 IPv6；“大陆 IP 例外放行”只跳过地区限制。地址同时出现在地区例外和具体黑名单中时，具体黑名单优先。
- **白名单**：仅允许“允许来源 IP”中的地址，其他 IPv4 和 IPv6 来源均屏蔽。至少填写一个地址；大陆屏蔽选择和黑名单暂不参与匹配，切回原模式时保留。

每份名单最多 128 个具体 IPv4 或 IPv6 地址，不接受域名、网段、未指定地址或组播地址。等价地址会统一格式并拒绝重复。白名单使用允许来源名单；黑名单中的地区例外使用同一份允许来源名单，切换时保留地址，请在提交前确认。

旧节点的大陆屏蔽开启时自动显示为黑名单，并保留例外；关闭时仍保持关闭，不自动启用新限制。新建节点默认关闭。

## 使用范围

普通代理节点（含普通 WireGuard）、前置入口和非 WireGuard 落地可分别设置。WG 中转落地不单独开启，用户来源在前置限制；普通 WG 按外层 UDP 来源匹配。切换为 WG 中转落地时，管理端关闭来源限制并保留名单。

该策略不判断用户国籍或所在地，也不限制用户访问大陆网站。系统防火墙按实际数据包来源判断，经过代理或中转时通常是上一跳出口；核心仍保留已有来源检查。接收受信任的 PROXY 来源信息时，白名单需要同时允许上一跳和解析后的客户端，或在前置节点执行用户来源限制。IP 归属数据可能有误差。

大陆中转连接受保护节点时，可将实际出口 IP 加入地区例外；白名单模式需将它加入允许来源名单。面板不自动猜测或放行前置出口。前置入口的策略作用于它接收的直出和中转请求，落地策略独立设置，不从入口复制。

## 执行与数据更新

Node 为 Xray、sing-box 和普通 WG 生成共用的来源拦截集合。Agent `v2.21.0` 开发版本在固定监听端口安装并核验系统防火墙规则后才启动节点，使受限来源在 SOCKS5、TLS 等握手前被丢弃；该端口的 REALITY 伪装回源同样受限。核心原有检查继续保留，通过名单仍执行原认证、线路权限和路由。

已有 UFW 可继续使用；自动选择底层 nftables，或 iptables/ip6tables 配合 ipset。运行中的 UFW 在工具齐全时优先使用 iptables 路径。缺少工具、无权限、关闭自动防火墙管理、规则冲突或核验失败均停止对应受保护节点，并保留控制通道报告错误；环境恢复后重新核验再启动。程序不会自动安装或开启系统防火墙。详细工具要求、后端配置、运行检查周期及容器和动态 UDP 范围见 [Node 来源限制说明](../../YZboard-Node/docs/source-policy.md)。

手动黑名单和白名单不依赖地区库，也不触发地区库下载或刷新。启用大陆屏蔽时，使用 [Loyalsoldier/geoip 的 cn.txt](https://github.com/Loyalsoldier/geoip/blob/release/text/cn.txt)，运行时本地匹配，不逐连接查询外部接口。

大陆库首次启用时下载并校验，成功后保存到 Node 地理数据库目录的 `cn-source.txt`。每 24 小时更新，后台每分钟检查；下载失败至少间隔 5 分钟重试。同目录节点共用缓存和下载锁，IPv4 或 IPv6 缺失、空文件、无效内容和全地址网段均拒绝使用。新数据校验和写入成功后才替换旧版本，集合未变化不重载。

开启大陆屏蔽且首次没有有效库、下载又失败时，该节点报错并停止接受代理业务；控制通道继续工作，后台取得数据后自动恢复。后续下载失败保留上一份有效数据和限制。切换为手动名单后不再依赖地区库，迟到的地区下载结果不会改变手动名单。

受保护节点的模式、名单、有效地区集合或运行配置变化时，先停止旧监听，再安装规则并重新启动，已有连接会中断。Agent `v2.20.0` 及更早的核心路由实现可能先完成握手，不能用来保证名单外扫描器收不到 SOCKS5 特征。

## 兼容与回退

黑白名单格式至少需要 Agent `v2.20.0`；系统过滤至少需要 Agent `v2.21.0`，后者目前仍为未发布开发版本。旧 Node 不认识名单模式和具体黑名单，保存成功不能证明它已经执行新限制；`v2.20.0` 也不提供握手前系统过滤保证。原大陆屏蔽策略继续兼容。

本次复用已有节点策略 JSON 列，无数据库迁移。回退到旧面板或旧 Agent 前先关闭来源限制并确认节点配置已更新；升级、发布及真实部署状态以兼容矩阵为准。
