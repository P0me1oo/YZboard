# 节点运行开关

运行开关自面板 `1.14.0` 引入，启停联动显隐自 `1.15.3` 引入；`1.15.5` 补齐新建节点的初始显隐。固定发布来源、镜像和验证记录见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 使用方式

节点管理列表原来的“显隐”改为“开关”，读取和修改节点的 `enabled` 状态。

- 开启：同时设为显示，并把当前节点加入绑定服务器的运行列表，Node 同步后启动该节点。
- 关闭：同时设为隐藏，并把当前节点移出运行列表，Node 同步后停止对应节点实例。
- 请求处理中暂时锁定当前开关；保存失败时保留原状态，并显示失败原因。
- 重新开启仍需通过内部端口冲突检查。发生冲突时，目标节点的启停与显隐都保持原值，其他节点继续运行。

开关表示面板保存的运行设置，节点旁的运行状态仍以 Node 上报为准。实时通知可用时立即触发同步；通知不可用时，Node 通过定期获取运行列表应用变更。因此，开关保存成功不等于远程节点已经完成启停。

未绑定服务器的独立部署节点显示“--”，悬停提示在部署端启停。独立部署没有这条按服务器发现节点的远程控制通道。

单独调整显隐继续使用批量“显示节点 / 隐藏节点”操作：隐藏不会关闭节点，显示不会开启节点。已经隐藏但仍运行的托管节点，开关仍显示为开启；再次设置运行开关时，显隐会跟随本次开启或关闭操作。

列表开关、服务器详情开关和批量启停使用相同的单向联动规则。启停与显隐在同一事务中保存；批量操作任一节点校验失败，整批节点的启停与显隐全部回滚。重复设置相同开关状态仍会同步显隐，同一次启停请求附带不同的显隐值时，以开关为准。

新建节点时，初始显隐同样跟随运行开关：开启时显示，关闭时隐藏。保存接口会覆盖表单自带的 `show=false`，避免开关已开启但用户列表和订阅仍隐藏。未传 `enabled` 时沿用数据库默认开启并显示；显式传入 `enabled=null` 时保留原显隐，兼容独立部署。新建校验或端口冲突失败时，不保存节点，也不改变已有节点状态。

显隐影响用户列表及后续订阅下发，客户端已保存的节点列表需要更新订阅才会变化。普通编辑保留独立设置的显隐；升级不会批量改写已有节点记录。此前新建但仍隐藏的节点，可以在后台勾选后执行“显示节点”，再刷新用户页面和客户端订阅；节点仍需满足用户权限组及流量额度等可用性条件。

## 同服务器节点隔离

开关只向 `POST /api/v2/<管理路径>/server/manage/update` 提交当前节点的 `id` 和目标 `enabled`，后端在同一次保存中将 `show` 同步为目标状态。批量启停通过 `server/manage/batchUpdate` 应用相同规则，不修改服务器本身的启用状态。

保存成功后，面板发布该服务器完整的已启用节点列表。Node 对比运行列表，只停止被移出的节点；仍在列表中的节点保留现有实例。机器共享的通信连接保持可用，其他节点继续接收配置和用户同步。

关闭服务器上的最后一个节点时，运行列表可以为空，但服务器本身仍保持启用，控制连接保留。之后重新开启节点，可以通过同一连接触发发现和启动。

这里只描述同服务器上独立节点实例的隔离。若其他节点的业务链路本来就依赖被关闭的前置入口，关闭入口仍会影响依赖它的连接。

## 实现与验证

- 管理端运行开关由 YZboard-Dash 源码工程实现，随管理端产物一起发布，包含中、英、俄文案。
- 前端行为测试在 YZboard-Dash 内执行，覆盖请求、状态刷新、连续点击、失败处理和独立部署；面板侧 `tests/admin-dist.test.cjs` 校验产物确实包含该定制。
- 面板测试覆盖单节点关闭与恢复、重复调用、同服务器及其他服务器节点保留、端口冲突、实时通知失败后的运行列表查询。
- 显隐联动测试覆盖单节点与批量启停、单独显隐不触发启停、冲突字段优先级、用户可见节点列表及整批失败回滚；普通编辑不会重置独立设置的显隐。
- 新建测试覆盖明确开关、缺省开关和显式空值，通过实际用户列表与订阅接口核对初始显示、编辑保存、重复关闭与恢复；保留已有隐藏节点的设置，校验失败不留下新节点或推送。
- 通信连接测试覆盖移除单节点后的其他节点消息发送，以及空服务器重新加入节点时的共享连接保留。

本次只调整面板新建保存接口，管理端沿用原有表单。没有数据库迁移、Node 通信或核心依赖变化，未连接真实节点服务器。

`1.15.5` 已于 2026-09-15 正式发布。[发布 CI](https://github.com/P0me1oo/YZboard/actions/runs/34892223416) 在 PHP `8.2.33` 下通过完整回归 202 项测试、3055 个断言及管理端 72 项测试；两个架构中的实际节点管理代码与版本文件均与固定发布提交一致，`latest`、版本别名及不可变标签指向同一镜像。来源 commit、digest 和回滚基线见兼容矩阵。
