# 节点内部端口提醒

当前规则适用面板 `1.61.0`、管理端 `0.36.0`，包含 `1.60.0` / `0.35.0` 开发阶段的改动。初始检查在 `1.13.5` 引入；此前拒绝冲突保存及开启的行为由本版改为提醒。版本记录见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 检查规则

检查用于提示同一绑定服务器上的节点可能争用内部监听端口。当前面板向 Node 下发的监听地址为 `0.0.0.0`，因此按“绑定服务器 + 内部端口 + TCP/UDP”比较。

- 两个节点的内部端口相同，且 TCP/UDP 监听范围有交集时，在端口旁显示红色图标，提示可能冲突的节点名称、编号和端口。允许保存、开启、换绑和批量修改。
- 一个只监听 TCP、另一个只监听 UDP 时，可以使用相同的端口号。
- 客户端连接端口不参与重复检查；同一个节点的连接端口和内部端口可以相同。
- 不同绑定服务器互不影响；未绑定服务器的节点不参与机器内的重复检查。
- 隐藏或停用节点同样参与配置重叠检查；提醒不表示这些节点正在监听，也不阻止它们开启。
- 内部端口必须是 `1–65535` 的整数，不接受端口范围或列表。Hysteria2 的跳跃范围仍填写在连接端口中。

## 传输方式

判断的是固定内部端口上的监听方式，不是节点能否代理 UDP 流量。

| 节点配置 | 固定内部端口 |
| --- | --- |
| Shadowsocks、Naive | TCP 和 UDP |
| Hysteria、Hysteria2、TUIC | UDP |
| WireGuard | UDP |
| Mieru | 按所选 TCP 或 UDP 判断 |
| SOCKS / Xray，包括历史空内核值 | TCP 和 UDP |
| SOCKS / sing-box | TCP；UDP 转发使用临时端口 |
| VMess、VLESS、Trojan 使用 KCP、mKCP、QUIC 或 Hysteria 传输 | UDP |
| VMess、VLESS、Trojan 使用 TCP、RAW、WebSocket、gRPC、HTTPUpgrade、XHTTP 等传输 | TCP |
| AnyTLS、普通 HTTP | TCP |

Xray 的 HTTP 入站开启 TLS 时，按实际生成的传输设置判断。Naive 的默认配置同时启用 HTTP/2 与 HTTP/3，因此预留 TCP 和 UDP；协议能否在所选内核中启动，仍受该内核已有能力和证书配置约束。

规则依据为 Node 两个内核的配置生成器。初始实现对照 Xray `b4caa82d6414196565599c19ebc1b53e331349b6`、sing-box `v1.14.0-yz.2`；当前核心版本以配套 Node 的固定依赖为准。本次没有修改 Node 或核心依赖。

## 表单与复制

填写内部端口，或改变服务器、协议传输方式、内核时，表单等待输入停顿约 300 毫秒后检查。配置重叠使用指定的红色 SVG 提醒，不写入表单错误，也不拦截提交。关闭表单或改变输入后，旧请求的结果不会覆盖当前状态。端口格式错误、检测接口异常或无效响应仍显示原有校验错误，可修正或重试。

管理列表一次检查全部节点，筛选或分页不会漏掉其他行中的冲突方；相同连接端口和内部端口只显示一个提醒，两者不同时提醒紧邻内部端口。桌面悬停、键盘聚焦或手机点按可以查看详情。保存、复制、删除或修改端口后重新读取列表，双方提醒一同更新；检测结果不写入节点配置或数据库。

复制接口保留两个端口和绑定服务器，不为副本自动分配新端口；从面板 `1.20.4` 起副本默认关闭并隐藏，不再沿用源节点的启用状态。源节点开关为空（独立部署）时副本保持空值，只强制隐藏。副本与源节点都会显示端口提醒，管理员仍可修改名称、端口、绑定服务器及开启状态。

保存及开启成功只表示面板接受配置，不保证两个节点能在服务器上同时监听同一端口。实际启动结果仍通过已有节点运行状态查看。

列表绑定、内核切换、重新启用及批量操作均允许端口重叠；其他配置校验和事务回滚规则保留。

## 实现与验证范围

- `ServerPortService` 提供表单与列表的统一判断；列表从已查询的完整节点集合计算，不逐节点追加数据库查询。保存继续使用原有事务，移除端口冲突拦截及专用机器锁。
- 管理端表单检查由 YZboard-Dash 源码工程实现，随管理端产物一起发布；产物内含该定制的校验在面板 `tests/admin-dist.test.cjs` 中执行。
- 自动测试覆盖同端口 TCP/UDP 共存、双传输冲突、内核差异、重复及批量保存、复制后编辑、允许开启、提醒清除、错误恢复和过期响应。
- 本地 PHP `8.4.21` 下，SQLite 与 MariaDB `11.4.8` 严格分组完整回归各通过 665 项、6,589 个断言。管理端 60 项行为测试、源码检查，以及最终构建的 7 项节点权限组与端口提醒浏览器回归通过；同步面板后 5 项资源检查通过。完整浏览器回归和开发模式的具体结果见配套管理端维护说明。
- 未进行真实服务器监听测试，面板检测仍以配置重叠为依据。

检查仅覆盖面板管理的节点内部端口，不扫描服务器上的其他程序、手工监听或防火墙转发规则。Hysteria2 跳跃端口集合的外部转发冲突仍由现有 Node 防火墙逻辑处理。
