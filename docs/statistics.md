## 1.58.0 时间轴起点与最低流量（开发记录，纳入 1.59.1）

配套管理端 `0.34.1`，包含 `0.33.0` 开发阶段的统计改动。分钟、小时趋势从选择的开始时间展开，“今天”为面板时区当天 00:00，结束仍截至当前已到达的时间。图表保留首尾刻度，避免窄屏自动省略零点。统计启用后的空档显示零；启用前没有记录的时段返回空值、曲线留空。只有旧日汇总的数据仍按天显示，不分摊成分钟或小时，流量合计保持原值。

用户排行增加“最低流量（MB）”，默认 1，隐藏所选时段内总流量小于 1 MB 的用户。支持小数，0 表示不过滤，等于门槛仍显示。单位沿用流量展示的换算：1 MB = 1,048,576 字节；选择实际流量时按实际上传加下载筛选，选择扣费流量时按扣费上传加下载筛选。先汇总每个用户全部线路，再过滤、排序和分页；不影响节点排行、总趋势或用户明细的统计。

最低流量与搜索一起提交，修改后回到第一页；时间、排序、分页、刷新和从用户明细返回都会保留已应用门槛。管理员用户排行接口新增可选的 MB 门槛参数（`min_traffic_mb`），接受 0 至 8,589,934,591 的数值；省略参数保留旧接口不过滤的行为，管理页面始终传入当前门槛。无需迁移数据库，Node 与核心无需更新，与面板 `1.59.1` 一同交付。

## 1.54.2 MariaDB 明细修复

无需新增迁移或更新 Node。SQLite 和 MariaDB 11.4 的完整后端回归、管理端资源检查纳入推送到 `master`、PR 与发布前检查，使用方法见 [测试说明](testing.md)。

## 1.54.0 入站 IP

配套管理端 `0.31.0`，沿用 Node `v2.7.1`，无需修改通信协议或核心。“统计分析 → 入站 IP”按用户显示去重 IP 数量、首次和最近出现时间，可搜索邮箱或用户编号。点击用户明细查看完整 IP、归属地、ASN 和网络名称；国内按省级地区、境外按国家或地区分类，可筛选分类。手机端使用纵向明细。

### 日期与记录依据

- 默认今天，支持最近 7 / 14 / 30 天、全部及自定义完整日期；全部仍只有保留期内的记录。日期和展示时间使用面板时区，结束日期包含当天。入站历史按天保存，因此不提供日内时间筛选；原流量页的分钟、小时筛选不变。
- 保存今天及此前 29 个自然日。首次和最近出现是**所选日期范围内面板实际收到来源上报的时间**，不是连接建立或断开的精确时刻。Node 上报之间的短连接可能未被观察到，不能视为逐连接审计日志。
- 新增用户入站日历史表 `v2_stat_user_inbound_ip`，按用户、完整 IP、日期唯一。跨节点、重复与乱序上报取最早、最晚接收时间；同一 IPv6 网段中的不同地址分别显示，不改变设备限制原有的网段合并规则。
- HTTP、旧 WebSocket 和新实时状态共用记录逻辑。新实时状态投影重试使用原始接收时间；已应用的相同状态不会再次刷新历史时间。空快照和离线不会清除历史。记录写入失败则报告失败，地址索引与历史事务一起回滚，可重试恢复。
- 只记录规范化后的公网地址，IPv4 映射地址统一成 IPv4。节点管理“前置服务器 IP”名单在写入时过滤，并在查询汇总、分类和分页前按**当前名单**再次过滤，支持单个地址和网段。增加名单后已有历史立即隐藏；移除名单后仍在保留期内的旧记录可以重新出现，但不会补造排除期间的记录。
- 首次部署后开始积累，不从旧在线缓存、流量、登录 IP 或已删除数据反推历史。已删除用户的现存记录显示用户编号。每日 `reset:log` 删除过期日记录及无历史引用的地址资料；即使定时清理暂未运行，接口也不返回保留期外的数据。

### 地区与 ASN

- IPv4 地区使用随源码和镜像交付的 [纯真 `20260930` 数据库](../resources/ip/README.md)，不在运行时跟随最新下载。归属地和省份从库中的中文地区解析；纯真不提供 ASN，不从运营商文字猜测 ASN。
- ASN 与 IPv6 地区复用 IP2Location.io；成功的完整查询结果按 IP 缓存 30 天。共享查询缓存由此前七天延长到 30 天，因此用户管理的在线设备查询也使用新期限。失败或缺少位置信息的结果仍短暂缓存五分钟，不把失败固定保留 30 天。
- 外部查询沿用连接一秒、请求两秒、最多八个并发及每个 UTC 日最多 1,000 次的全局额度。额度与在线设备详情共用，额度耗尽、网络失败或未知位置时显示“未知”，IPv4 仍显示纯真结果。IPv6 省份按服务明确返回的省级地区分类，不能识别时归“未知”。位置为数据库标注，不保证是用户的实际物理位置。
- 新增地址资料表 `v2_inbound_ip`，由每分钟 `inbound-ip:refresh` 分批补齐；查看用户明细也会补齐最多 32 个到期的外部查询。本地 IPv4 分类在分页前分批完成，因此省份筛选不依赖先浏览全部页面。尚未查询到的 IPv6 归“未知”，后续查询成功会更新分类。
- 外部查询不在节点上报路径中执行。ASN 或 IPv6 位置文字保留 IP2Location.io 来源链接；IPv4 位置不被外部地区覆盖。

### 部署与验证

新增一项迁移创建两张表，原有流量、余额、设备计数和统计历史不改写。管理接口为 `/api/v2/<管理路径>/statistics/inboundUsers` 和 `inboundUser`，沿用管理员认证；普通用户无权访问。管理端必须与面板后端一同部署。

已随 [面板 v1.54.0](https://github.com/P0me1oo/YZboard/releases/tag/v1.54.0) 正式发布，双架构镜像、latest 及镜像内关键文件已核验。回退时可保留两张新表；旧代码不会继续写入或清理入站历史，再次启用时不回填停用期间的数据。30 天清理后的记录不能通过回退代码恢复。固定产物与验证记录见 [兼容矩阵](../YZ_COMPATIBILITY.md)；服务器更新由用户执行。

## 1.50.0 当前统计规则

配套管理端 `0.27.0`，Node 沿用 `v2.5.0`。节点管理的累计流量与节点额度判断保持原样；套餐仍按入口用户上传、下载乘入口当时生效的倍率扣除。

| 位置 | 当前依据 |
| --- | --- |
| 节点管理、概览节点排行 | 前置包含直出和中转，落地记录各自承载量 |
| 概览总量和趋势 | 所有节点的日统计相加，包含前置和落地；不等于用户实际用量 |
| 用户实际流量及明细 | 中转归到落地，前置只保留该用户的直出；纯中转不再显示一份前置流量 |
| 用户扣费排行及明细合计 | 保存实际结算量，不用查询时的倍率反推；新排行与明细使用同一升级后记录范围 |
| 用户节点明细 | 始终显示实际上传、下载和总量；非 1 倍同时显示生效倍率与归属扣除量，1 倍不附加这两项 |

例如前置直出 1 GB、经过前置到落地 4 GB：节点管理为前置 5 GB、落地 4 GB，概览合计 9 GB；用户明细为前置直出 1 GB、落地 4 GB，用户实际合计 5 GB。前置 2 倍时合计扣 10 GB。落地自己的倍率不参与扣费。用户详情保留实际量、扣费量两个合计；明细不再切换成仅显示扣费量。

### 记录和扣费归属

新增 `v2_stat_user_route_source` 保存用户、上报入口、节点、日期、结算倍率、入口原始量与实际结算量，以及同批的用户落地明细。入口总量与落地明细先按同一用户、入口、日期、倍率汇总，再从入口扣掉已归属落地的上下行量；不能先按界面选中的节点筛选，也不能逐批将负差值截为零。节点重新绑定前置后不会改变原有记录。

入口和线路计数不是同一时刻读取，短时可能有采样差异。负的直出差值按零展示，原始累计值保留，后续上报可继续对齐，不累计逐批截断产生的虚假直出。用户落地明细使用用户线路上报，不使用可能包含封装开销的落地节点总计数。跨日期或倍率边界的采样差异无法从旧上报精确追溯到单个字节。

节点明细的扣除量是**已实际扣费的归属分配**：在同一用户、入口、日期、结算倍率内，按各线路的上传、下载占比分别分配该方向已扣量，用整数运算固定取整余量；所有线路的扣除量之和严格等于已结算量。这只是展示归属，不再次扣费。流量来源有采样差异时，不保证某一行的实际量乘倍率恰好等于分配量。不同倍率分别成行，按周、月汇总也不合并成虚构的单一倍率。

新增 `v2_stat_node_hour` 汇总所有节点的小时用量，与节点日统计同事务写入。可靠上报使用首次接收时间，失败回滚、重试去重，跨天处理保留原日期；旧接口任务入队时保存时间，没有接收时间的旧任务不补造小时记录。小时与日汇总不一致时，单日趋势回退为日汇总，升级当天可能回退。

### 升级与历史

新用户归属统计从迁移启用后接收的报告开始，入口和落地旧记录不回填，新接口不推算旧线路倍率或扣费。升级前已接收的延迟批次仍正常扣费并保留旧统计，但不混入新用户归属记录；用户套餐已用量不清零。概览可直接复用已存在的节点日统计，旧入口小时表保留但不冒充全节点小时统计。

新表沿用 30 个自然日保留范围，清理时保留仍被新明细引用的已删除节点名称。普通旧接口继续记录直出；中转明细需要配套 Node 已有的用户线路上报。没有更改 Node 通信格式或核心。回退可保留新增表，不回滚删除数据；旧版本运行期间没有新归属记录，恢复新版后不补算该段明细。

- 所有新统计接口使用面板时区。最近 30 天包含今天及此前 29 个自然日；自定义结束日期包含当天，数据库查询不包含次日零点。周、月汇总仍严格受所选起止日期限制，首尾周期可能不完整。
- 排行和明细默认每页 20 条，可选 10、20、30、40、50、100 条，三个列表分别在浏览器记忆；切换条数回到第一页。页面每 30 秒刷新，实际数据到达时间取决于 Node 上报和结算队列。
- 单日总趋势自动按小时，今天只显示到当前小时。多日默认按天，保留周、月选择。单日历史没有小时记录或小时汇总与日汇总不一致时，继续按天显示，不把缺失数据补零。

## 小时记录

小时趋势以面板首次接收上报的时间为准，不是每条连接的发生时间；现有 Node 上报不提供可用于小时分配的事件时间。可靠批次使用持久化创建时间，重试、跨小时或跨天结算不改变归属。旧接口的新队列任务在入队时保存接收时间，升级前未保存时间的旧任务只保留日统计。旧接口仍没有跨网络重试去重保证。

新增 `v2_stat_traffic_hour` 只汇总入口上传与下载，不保存用户、节点或落地明细，和日统计在同一事务累加；失败整体回滚。小时记录自迁移启用后开始，不回填旧记录，保留今天及此前 29 个自然日。升级当天若已有日流量而缺少对应小时数据，全天继续展示日汇总。时区沿用面板设置。

## 流量口径

| 内容 | 统计依据 |
| --- | --- |
| 总趋势、用户实际流量 | 用户在入口节点的上传与下载，不乘倍率；中转落地不重复累计 |
| 用户扣费流量排行 | 现有用户日统计，包含当时的计费倍率 |
| 用户节点明细的扣费流量 | 保存结算时的值；倍率变化后不按新倍率反推历史 |
| 节点排行 | 现有节点日统计，每个节点各自的用量；入口和落地均可出现，不能相加当作用户总量 |
| 用户的中转落地明细 | 现有用户线路上报，只显示原始用量；没有独立扣费量，扣费列显示「—」 |

上传、下载方向沿用现有 Node 上报。数据是代理上报的流量，不是网卡总流量。不同核心的中转计数位置可能不同，入口、落地数值不保证相等，详见 [中转节点](relay-nodes.md)。用户入口合计和落地合计分开显示。

## 历史与保留

旧用户统计只保留用户、倍率和日期，不能可靠反推出用户在各节点的原始流量，零倍率数据尤其无法还原。因此不自动回填新明细。

实际用户流量、总趋势和用户节点明细从新功能启用后记录。`1.48.1` 起页面不再显示开始记录提示；趋势仍不会把启用前的日期补成零。只有一天记录时，按天趋势只有一个点。升级前已接收但尚未结算的报告可能迟到，按报告原日期保存实际收集到的部分数据。节点排行和扣费流量排行可复用仍在保留期内的旧日统计。升级当天的实际记录是部分数据，不能与整天历史扣费记录直接对账。

每日清理保留今天及此前 29 个自然日，包括旧用户日统计、节点日统计和新增用户节点明细。**这会将原来两个月的保留范围缩短为 30 天**；清理后的历史不能通过回退代码恢复。用户套餐已用流量、节点累计计数、上报去重编号不在此次清理范围内。

`1.48.1` 起，管理员单个或批量删除节点时保存删除前最后使用的名称，排行、用户节点明细和节点筛选统一显示「原名（已删除）」。在此之前已删除且没有留下原名的节点，不再显示对应节点行或筛选项；过滤在分页前完成。隐藏不等于删除流量记录，总趋势、用户排行和用户流量合计仍保留实际已经发生的用量。停用、隐藏但尚未删除的节点仍显示当前名称。已删除用户继续显示用户编号。

名称记录只包含节点编号、名称和删除时间，不保存节点配置。删除失败时名称记录一并回滚，重复删除不会刷新原删除时间。名称超过 30 天且已无剩余节点统计或用户节点明细引用后，由每日清理任务移除。

## 记录与兼容

新增日统计表为 `v2_stat_user_server`，以用户、节点、统计位置和日期唯一标识一条记录，保存原始上传、下载及结算后的扣费值。开始时间保存在设置项 `traffic_statistics_started_at`。两者由新增迁移创建，不修改已有套餐扣费算法。

可靠上报由 `ProcessNodeReportBatch` 在同一事务中更新旧汇总、新明细和批次状态。批次重试不会重复累加，任一步失败整体回滚。旧版上报的 `StatUserJob` 也记录入口明细；旧接口没有报告编号时，仍无法跨网络重试去重，这是原接口限制。

继续使用现有 Node 的流量与用户落地上报，无通信格式、核心依赖或 Node 版本变更。正常发布时需要同时纳入前端源码构建与面板后端迁移，仅运行管理端构建不会部署后端。

管理员接口位于 `/api/v2/<管理路径>/statistics/`：`traffic`、`nodes`、`users`、`user`、`searchUsers`，沿用管理员认证。所有范围、分组、页码和筛选均由后端校验，日期查询限制在保留范围内。

已随 [面板 v1.48.0](https://github.com/P0me1oo/YZboard/releases/tag/v1.48.0) 正式发布，配套管理端 `0.25.0`，Node 沿用 `v2.5.0`。双架构镜像和 `latest` 已核验可获取；只需更新面板，更新前备份数据库。验证结果和固定产物来源见 [兼容矩阵](../YZ_COMPATIBILITY.md)。
