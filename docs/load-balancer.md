# 前置负载分配

本文对应面板 2.0.4、管理端 0.85.4。面板提供按用户分配前置的能力。前置池通过 PowerDNS 给每名用户稳定分配具体前置。连接路径为“用户 → 分配的前置 → 落地”；面板和 DNS 服务器仅负责管理与解析，不承载用户代理流量。

## 配置

1. 准备 PowerDNS Authoritative 区域和 API，在“前置负载分配 → DNS 配置”填写区域、API 基础地址、服务器 ID 和 API Key。支持 RRset comments 的后端如 gsqlite3、gmysql；多个区域共用同一台 PowerDNS。
2. 新建池，选择 PowerDNS 配置后自动显示基础域名，只填写池前缀。例如配置区域为 `example.com`，填写 `pool` 得到 `pool.example.com`。基础域名沿用配置的完整区域，不截断子区域或 `example.co.uk` 等域名；编辑时拆出原前缀，切换配置保留前缀，已有直接使用基础域名的池仍可原样保存。再选择已有 VLESS Reality + TCP 前置。每台服务器一个成员，Agent 需达到 v2.25.0；不复制密钥、不新建监听或修改原节点权限。候选列表默认隐藏不支持的协议；兼容协议的端口、公钥等参数不匹配时仍显示原因。已有池的已选成员后来改变协议时保留显示，移除后隐藏。
3. 公网端口取首个选中节点。各成员的公网端口、Reality 公钥、短 ID、握手域名、握手端口和 VLESS 流控必须一致；NAT 内部监听端口可不同，公网映射端口必须相同。允许开启 PROXY 接收并保留原开关；落地或共享子节点不能作为成员。
4. 配置成员优先级和权重。优先级数字越小越优先；同级可用成员中按权重分配用户，权重范围 1–1000。例如 2:1 时大量用户约按 2:1 分布。分配比例针对用户数量，不保证连接数或实际带宽比例。
5. 落地选择该前置池。用户更新订阅后使用固定随机标签的个人域名；尚未更新的订阅仍可通过池域名连接候选前置。

入口前使用 Realm 等转发机时，节点连接地址和公网端口填写转发机入口，转发机发送 PROXY 头，接收该连接的前置节点开启接收。DNS 只分配连接地址，不生成或剥除 PROXY 头；同池成员可以分别开启或关闭接收，只需与各自链路匹配。前置节点能同时接收带头和不带头的普通连接，此次面板解除限制无需修改或升级 Agent。具体配置见[节点接收 PROXY 协议](proxy-protocol.md)。

## 用户分配与 DNS

个人域名形如 `随机标签.pool.example.com`，CNAME 指向该成员的稳定域名，后者的 A/AAAA 仅包含该成员可用的地址。每个成员仍接收原池线路所需的用户权限，原直连线路保留。

分配使用稳定加权哈希：配置、候选集不变时结果不变；撤下一个成员只重分配原来使用该成员的用户，恢复后回到原分配。新增成员或修改权重会让部分用户重新分配。策略变化只修改 DNS，用户标签和订阅名称保持不变。

同步先保存随机标签和 DNS 归属意图，PowerDNS 写入成功后再确认用户分配和候选状态。API 失败保留上次已确认分配，下一轮重试。全部不可用时撤销池、成员和个人解析，保留标签等待恢复，不把用户送到故障前置。

个人域名始终启用。2.0.2 起移除前置池的 DDNS 开关：创建、保存及每次同步都以成员节点填写的连接地址为准，不读取 Agent 上报的公网 IP。IPv4、IPv6 直接使用填写值，域名使用其 A/AAAA 解析并支持 CNAME 链；无效地址或解析失败时退出候选，不沿用旧地址。已有池不需要重建，下一次同步自动纠正曾保存的上报地址。旧池 DDNS 字段及旧管理端传入的开关只为兼容保留，不再控制地址来源；普通节点 DDNS 保持原行为。

跟随用户状态默认关闭。开启后，按封禁、到期和流量耗尽撤销个人解析；权限组授权仍决定哪些用户能获得解析。

TTL 范围 30–86400 秒，默认 60 秒。每 60 秒同步候选与 DNS，实际切换还受递归 DNS、客户端缓存和区域否定缓存影响；已建立连接不能迁移。单台 PowerDNS 不可用时，解析和同步依赖现有缓存。

## 选择模式

所有模式先排除离线、停用、流量保护和连接参数不兼容的成员，再应用可选的端口检查、剩余百分比筛选和优先级。

- **同优先级按权重分配**：在最高可用优先级的全部候选中稳定分配用户。
- **最低延迟单台优先**：保留原单台择优。前置到指定 TCP 落地的建连延迟最低者作为入口；新候选至少快 10ms 和 15%，连续两份新测量确认后切换。
- **低延迟多台分配**：在同优先级内保留不超过最低延迟加 `max(10ms, 最低延迟的15%)` 的前置，并按权重分配用户。例如 50ms 与 55ms 都可参与，200ms 退出；边界加入与退出分别由连续两份新测量确认，明确的连通失败仍退出。延迟衡量前置到落地，不代表用户到前置或下载速度。
- **临近流量重置日优先**：在同优先级的可用机器中，优先使用下次配额重置时间最近的成员；同一重置时间按成员权重分配。额度用完、离线或保护后使用下一批。不限流量的成员只在没有可用限额成员时参与。日期沿用服务器流量计量的时区及月底处理规则，不修改实际配额或重置日期。

剩余流量筛选开启时，低于设置百分比的机器退出，恢复到阈值以上 5 个百分点后加入；全部低于阈值时保留剩余比例最高的健康机器。真正超限和既有计量保护仍退出。周期模式同样遵守此开关，不绕过管理员的退出阈值。

端口检查默认关闭；开启后各地址独立连续两次失败撤下、两次成功恢复，超时 2 秒。TCP 端口可达不能证明完整代理握手或网站访问成功。延迟探测沿用 Agent v2.30.0，每 15 秒运行，目标变化后旧结果失效；开启两种延迟模式前必须满足版本要求。

### 落地主备

在“落地主备”页新建池，选择原订阅线路，再按顺序选择备用落地。成员须是已有的内部落地节点，绑定同一前置节点或前置池，每台服务器只选一个成员；协议分别按前置与落地的实际核心校验。不同成员可以使用各自的协议、端口和内部认证，保存不会复制密钥、修改原节点或新建监听。

首成员始终是原线路的主落地。各前置独立选择第一个可用成员；稳定恢复后自动回到主落地。用户继续使用原线路名称和路由编号，权限、用户扣费和逻辑线路统计归属保持不变；实际转发使用所选成员自己的内部凭据。备份节点原有的其他线路继续保留，可在节点管理中自行调整是否展示。

TCP 内部链路使用 Agent 的连通性结果，连续两次失败/成功确认状态；WireGuard、VLESS KCP/Hysteria 等 UDP 内部链路只按节点状态及流量保护判断，不把 TCP 失败当作 UDP 故障。首次启用或重新启用提供 90 秒测量宽限期；TCP 测量超过 90 秒失效后，该成员退出候选。全部不可用时保留并阻断原路由编号，不回退前置直出。管理员停用原订阅线路会阻断这条线路，不自动绕过停用选择备用。

主备选择收到新的测量后更新，定时同步也处理心跳过期和流量保护。切换复用现有配置下发和核心重载机制，只改变后续连接；已建立的连接不能迁移。停用或删除落地池恢复原落地，不删除成员服务。启用自动择优或落地主备前，前置 Agent 必须达到 `v2.30.0`；旧版本不能静默启用。

## 状态与记录

成员列表显示权重、已分配用户数、端口状态、测速结果、配额不足及下次流量重置日期；落地页按前置展示当前落地。切换记录保留 30 天，DNS 成功后才确认候选变化，失败记录同步错误。

## 从 Cloudflare 委托子域

以 Cloudflare 管理 `example.com`、委托 `pool.example.com` 为例：

1. 为 PowerDNS 准备一个可公开解析的 NS 主机名，例如 `ns1.example.com`，A/AAAA 指向该服务器 DNS 地址，Cloudflare 中设置为仅 DNS。使用委托范围之外的 NS 名称可避免子域内 NS 的胶水记录依赖。
2. 在 PowerDNS 创建 `pool.example.com.` 区域，配置对应 SOA 与 `ns1.example.com.` NS，并开放面向解析器的 UDP/TCP 53。API 通过受保护的管理地址供面板访问，不对用户暴露 API Key。
3. 在 Cloudflare 父区域添加名称 `pool`、内容 `ns1.example.com` 的 NS 委托。处理该名称原有冲突的 A/AAAA/CNAME；PowerDNS 内保留区域根部 NS/SOA。面板不会自动改写父区委托，也不会安装或重启 PowerDNS。
4. 在面板中添加 PowerDNS 配置，区域填 `pool.example.com`；池域名同样填 `pool.example.com`。由 PowerDNS 管理池 A/AAAA 和用户四级 CNAME，Cloudflare 只保存 NS 主机地址及委托，不保存每名用户的记录。
5. 用 `dig NS pool.example.com`、`dig @<PowerDNS地址> pool.example.com A`、`dig +trace pool.example.com` 检查权威答复、委托和最终解析。若启用 DNSSEC，父区 DS 与子区签名须配套；否定缓存 TTL 建议配合故障恢复要求设置。

API 采用官方的区域 RRset `GET` / `PATCH`，名称使用完整域名，以 `REPLACE` / `DELETE` 更新。每组记录先持久化随机归属标记，再写入 PowerDNS comments；请求响应丢失时按同一标记恢复，不重复建记录、不认领外部记录。域名冲突、归属变化、覆盖范围内的泛解析或下级 NS 委托会阻止写入。区域根部 NS/SOA 始终保留。

参考：[PowerDNS 区域 API](https://doc.powerdns.com/authoritative/http-api/zone.html)、[PowerDNS HTTP API](https://doc.powerdns.com/authoritative/http-api/index.html)。

## 升级与回退

2.0.0 删除旧转发模式和旧离线阈值接口，不会自动把旧 Cloudflare 转发池转为 PowerDNS。

升级前在仍支持旧模式的版本（如 1.114.0）完成旧池停用、池解析与个人 DDNS 清理、PowerDNS 转换，并重新保存已有 DNS 池以复用原节点。也可以在解除落地引用和清理托管解析后删除不再使用的旧池。新版迁移遇到旧模式、旧专用实例或旧池绑定时，在改表前报错并保留数据；没有旧配置则直接执行正常更新迁移。

迁移增加成员权重、成员域名标签及用户分配编号，保留历史迁移和端口存储字段。升级后同步 DNS，再让用户更新订阅，以便实际使用个人分配。

回退前停用前置池、同步清理池/成员/个人 DNS，并停用新增落地策略，再按固定旧版本恢复。新迁移在仍有启用池、分配或托管记录时拒绝回退，防止遗失记录归属；不要单独撤销迁移却保留新代码。

## 删除前置池

2.0.1 起，先解除落地引用，再点击删除即可：面板自动停用池、清理本池拥有的 DNS，然后删除池配置，不删除原普通节点。DNS 清理失败时池保持停用、配置与记录归属保留，处理网络或归属冲突后重试删除。删除和单纯停用不要求节点的 Reality 参数重新一致。
