# 日志设置

面板 `1.108.0` / 管理端 `0.79.0` 的本地开发功能，尚未发布。入口为“日志管理 → 日志设置”，仅管理员可读取和保存。

## 使用

每类日志独立设置“记录 / 不记录”和保存天数，范围为 1–365 的整数，修改后点击“保存设置”。默认全部开启，保存期限如下：

| 日志 | 默认天数 | 范围 |
| --- | --- | --- |
| 面板系统日志 | 14 | 面板标准运行日志及废弃接口警告 |
| 管理员操作日志 | 90 | 管理操作审计；原三个月清理统一为 90 天 |
| Agent 日志 | 7 | 面板收到的 Agent、Xray、sing-box 运行日志 |
| 用户日志 | 30 | 登录、改密和连接、设备、带宽限制事件 |
| 代理访问记录 | 7 | 面板收到的代理连接目标记录 |

关闭后停止新增该类记录，历史仍可在保留范围内查询，并继续到期清理。重新开启后恢复后续记录，不补采历史；Agent、访问和用户限制事件的迟到上报不能补存重新开启之前的记录。缩短期限后，查询立即排除到期记录，清理任务随后删除；延长只能保留尚未删除的数据，不能恢复已清理记录。

Agent 开关控制面板入库，也停止由这些日志产生的 Xray 崩溃通知，不停止 Agent 本地输出或上传。机器的“隐私保护模式”（原“永久停用运行日志”）始终优先，不能用这里的可恢复开关解除。用户日志开关不停止流量、在线状态、限制执行和原有限制通知；通知防重记录至少保留 30 天，较长的用户日志保存期限会相应延长防重保留。

## 自动清理

沿用项目调度器，每 5 分钟分批检查到期记录，不提供清理时刻或频率设置。调度器必须正常运行；积压或执行失败时实际删除可能延后，下次继续处理。面板查询和上报接收始终排除超期记录。

数据库日志按最近“天数 × 24 小时”保留；系统文件按面板时区的自然日保留，例如 2 天保留今天和昨天。系统文件只清理标准 `laravel-日期.log`、`deprecations-日期.log`，每轮最多 500 份，不跟随文件软链接，不删除备份或插件的自定义文件。

默认日志渠道继续按天写入；历史 `LOG_CHANNEL=single` 也改为按天轮转，防止单文件无限增长。旧 `laravel.log` 在最后修改日期到期后清理。标准错误、系统日志服务和 Docker 日志的外部存储保留由各自配置控制，面板不能删除这些外部历史。系统日志开关作用于项目提供的面板日志渠道；设置读取故障时暂不写入，避免意外恢复已关闭的记录。

“数据库分析”中的管理员日志和访问记录清理也使用当前期限。预览后延长期限，旧预览不能删除新规则仍应保留的记录。

## 兼容与维护

设置使用既有设置表，无数据库迁移。后端读取、写入和定时任务均读取最新设置，已有队列和长连接不依赖启动时的旧值。Agent 握手继续使用原版本的能力声明，保留天数反映面板设置；无需修改 Agent 或两个核心。

只改本地代码和构建产物不代表服务器已更新。回滚到旧面板会恢复旧的固定保留周期，旧面板不识别本页可恢复开关；永久停用机器策略沿用其独立约束。验证结果见[兼容矩阵](../YZ_COMPATIBILITY.md)。
