# 设备与 DNS 争锁修复

维护者：P0me1oo。日期：2026-11-14。面板 2.16.7，已推送并部署至 Solid-US LA，见[部署记录](deployment-2.16.7.md)。

## 排查依据

生产运行版本为 2.16.6，相关设备与 DNS 源码与本地一致。11 月 14 日 12:10 的近 24 小时日志统计到 41,263 条设备锁警告，39,061 条发生在账号锁；警告经过限频，不能当作请求或连接失败总数。12:13 的状态快照中，122 个设备许可节点有 103 个没有来源连接。

原实现将当前节点可用账号中的全部全局协调记录纳入锁内处理。隔离复现确认：一个没有连接、没有排队任务的节点仍会申请 12 个仅与其他节点有关的账号锁，任一账号被占用就会阻断这轮空同步。

DNS 新诊断捕获的 34 次失败全部发生在 PowerDNS 区域锁。两个前置池与 4 个 DDNS 绑定共用区域，原定时顺序先启动后台 DDNS，再同步前置池。近 24 小时调度记录有 52 次失败与恢复配对，间隔 58～66 秒；检查时两个池均已正常。现有日志没有记录持锁任务，DDNS 与前置池相撞是结合源码和配置判断的主要原因。

## 设备修复

- 本节点已上报、排队或归还的账号直接进入协调；其他可用账号以最多 256 个一批读取权威记录，仅选择与当前节点仍有来源或许可占位关联的账号。
- 关联筛选期间继续持有节点锁，阻止并发授予本节点许可。实际处理仍在账号锁内重新读取最新权威记录，筛选快照不能用于续期、释放名额或撤销判断。
- 即使队列丢失，现有许可仍能被找回并修复登记；空闲许可返回原确认与期限。未知来源、权限撤销、归还确认、写入失败和同序号重试沿用原保护。
- 无关账号不再抢锁，也不再执行其跨节点状态读取和队列维护。12 个无关账号的空节点场景从 12 次账号锁降为 0 次；这是隔离场景结果，不代表生产整体性能降幅。

## DNS 修复

- 同一次定时调度先执行前置池同步，结束后再启动后台 DDNS；两者仍按分钟调度，保留单任务防重叠设置。
- 保留以 API 服务、服务器标识和区域共同确定的区域锁，读取、归属检查及写入继续串行执行。锁等待从 2 秒调整为最多 10 秒，每 100 毫秒重试，短暂占用可在本轮恢复。
- 25 秒远端请求预算在等待区域锁前建立，等待不会额外叠加新的请求预算。跨轮、队列与手动操作仍可能争用同一区域；持续占用超过等待上限时继续失败并保留最后成功状态。
- 不缩小 DNS 记录归属保护范围，不跳过写入核对，也不把失败记录成成功。

修复前新增场景复现了空节点被无关账号锁阻断、DNS 占用 3 秒即退出和两类定时任务启动顺序问题。修复后覆盖：空节点零账号锁、600 个账号分批筛选、缺失队列找回空闲许可、筛选后撤销可见、八进程并发准入、名额不超额、同序号重放、写入失败不确认、HTTP/WebSocket 共用处理、DNS 短暂争用当轮恢复、持续占用有界退出、等待不重置远端预算、不同区域独立及失败安全释放锁。DNS 等待边界使用框架模拟时钟，真实 Redis 验证锁与状态读写；未执行真实 PowerDNS 服务器故障注入。
