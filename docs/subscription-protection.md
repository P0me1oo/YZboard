# 订阅防护

基础功能已随面板 `1.80.0` 发布，用户限频、手动解封和 Telegram 提醒已随 `1.82.0` 发布。面板 `1.83.1` / 管理端 `0.55.1` 本地改为自动保存、移动提醒入口并调整默认额度，尚未发布。

## 使用

打开「订阅管理 → 订阅防护」，完整输入在停止编辑约 0.7 秒后自动保存，没有保存按钮。四个防护开关默认关闭；读取失败不会保存默认值，保存失败保留输入并可点击“重试”，不完整参数不会提交。保存期间可继续编辑，切换页面仍提交待保存的完整输入。IP 白名单每行一项，也可用中英文逗号分隔；用户白名单按邮箱或编号搜索后选择。侧栏使用内置 [Lucide shield-ban](https://lucide.dev/icons/shield-ban)，无需向外部图标服务发请求；可在外观设置中隐藏此入口。

| 功能 | 开启后的行为 | 初始参数 |
| --- | --- | --- |
| 禁止浏览器访问订阅 | 拒绝浏览器标识及页面导航请求，返回 HTTP 403 | 关闭 |
| 订阅暴力探测防护 | 同一 IP 访问无效订阅链接达到阈值，临时限制订阅访问 | 10 分钟内 10 次失败，封禁 30 分钟 |
| 订阅频率限制 | 同一 IP 在窗口内共用请求额度，超出返回 HTTP 429 | 每分钟 20 次，默认关闭 |
| 按用户限制订阅频率 | 同一账号跨 IP 累计，超出返回 HTTP 429 | 每分钟 20 次，默认关闭 |
| Telegram 封禁提醒 | 在「Telegram Bot → 管理员通知」开启，新触发 IP 封禁、IP 限频或用户限频时提醒管理员 | 关闭，复用管理员接收人和冷却间隔 |
| 白名单 IP | 精确地址或网段命中时跳过上述四项防护 | 空名单，支持 IPv4、IPv6 和 CIDR |
| 白名单用户 | 通过该用户当前有效的订阅凭据命中时跳过上述四项防护 | 空名单，按用户编号保存 |

默认额度仅影响未配置的次数和窗口，升级不会覆盖已保存的自定义值。次数范围为 1–10000，三个统计窗口均为 1–10080 分钟，封禁时长为 1–43200 分钟。IP 白名单最多 256 项，用户最多 1000 个；允许明确填写 `/0` 网段，这等同于豁免该地址族的所有来源，应核对输入范围。

白名单不授予账号资格，不绕过原有账号封禁、到期、订阅资格及客户端限制。账号流量用尽时是否还能下载沿用原接口行为，不改动实际代理使用权限。白名单用户在同一 IP 已受限制时仍可使用自己的有效订阅；其他用户不会随之获豁免。删除用户或重置订阅后，旧凭据不能再命中用户白名单。

## 计数和恢复

以下入口统一执行防护，并按来源 IP 共用额度：

- 当前短订阅路径，默认 `/s/{token}`，也支持管理员自定义路径名。
- 旧版 `/api/v1/client/subscribe`。
- 旧客户端配置下载 `/api/v1/client/app/getConfig`，避免通过这个同样返回节点配置的入口绕过保护。

登录、管理页面、静态资源、客户端版本查询不参与计数。缺失、格式错误和不存在的订阅凭据计入探测失败；已有账号被禁用、到期、没有订阅资格、浏览器拦截或客户端限制不算猜测凭据失败。请求限频统计未豁免的订阅请求，包括无效链接和被浏览器规则拒绝的请求。

用户限频在有效订阅凭据解析后按账号编号计数，三个下载入口共用额度，切换 IP 或重置订阅不能重新获得额度。无效凭据、白名单请求，以及已被 IP 封禁或 IP 限频拒绝的请求不计入用户额度；有效账号被浏览器、账号资格或客户端规则拒绝时仍会消耗用户额度。两个账号在同一 IP 上的用户额度互不影响，IP 额度仍共用。

达到失败阈值的那一次请求即返回 HTTP 429。封禁和限频响应带 `Retry-After` 秒数；重复访问不会延长原窗口或封禁结束时间。成功访问不会清除同一窗口已有的探测失败次数，避免交替访问有效链接与随机链接规避限制。封禁结束后重新统计失败次数。

修改次数或时间参数会重置对应计数规则；重复保存相同参数不解封。关闭开关后立即停止对应检查，但旧计数自然过期前仍保留，再次开启可能继续受限。修改白名单立即影响后续请求，豁免请求不消耗额度，也不清除其他请求已有的计数。

所有防护拒绝响应均为纯文本且禁止缓存，不含订阅凭据或节点信息。共享设置读取失败、计数缓存异常或同一来源争用锁超时时返回 HTTP 503 和短暂等待时间，不将故障当作防护关闭。

## 手动解封

页面下方「当前限制」展示 IP 封禁、IP 限频和用户限频的对象、窗口内计数、触发时间及解除时间。仅展示仍启用、参数仍匹配、未过期、未被加白且共享缓存确认生效的记录；可刷新和分批加载。

- **解除本次限制**：只清除该对象的选中限制和计数。例如解除 IP 探测封禁后，该 IP 的请求额度仍然保留；解除用户限频不重置该 IP 或其他用户的计数。
- **永久加白**：IP 加入精确地址白名单，重置该 IP 的探测和请求计数；用户加入用户白名单，只重置该账号的请求计数。白名单按已有范围跳过订阅防护，不改变账号资格或客户端限制，其他对象不会被加白。
- 操作前核对本次事件编号。已过期、重复提交或过时的页面返回冲突，不解除后来触发的新限制。白名单已满或用户不存在时拒绝加白。编辑或保存期间暂停解封和加白，等待自动保存成功后操作；加白成功会回填白名单。

旧版本缓存只保存 IP 摘要，无法反推出原始地址。升级前已有的限制在相应 IP 再次请求后补入列表；此补录不发送历史 Telegram 提醒。正常进程重启保留计数和列表；缓存丢失后旧索引不会被当成生效限制。

## Telegram 提醒

在「Telegram Bot → 管理员通知」配置并保存接收人及重复告警间隔，再开启“Telegram 封禁提醒”。该开关独立自动保存，保留原有开关值；只修改提醒，不覆盖订阅防护规则。三类限制按“类型、对象、接收人”分别防重和冷却，复用现有默认 60 分钟间隔；与设备、连接告警互不占用冷却。浏览器拦截不发送提醒，受影响用户无需绑定 Telegram。

只有首次被拒绝的限频请求或达到探测失败阈值的请求登记事件。持续访问不重复登记、不延长限制；冷却结束后必须出现新限制才再次提醒，手动解封不清除通知冷却。后台每分钟调度到现有 Telegram 队列，成功发送、临时失败重试、各接收人隔离及过期取消沿用管理员通知规则。

消息只包含面板名、限制类型、IP 或用户邮箱及编号、计数和起止时间，不含订阅凭据、请求路径或节点配置。发送前重新检查提醒开关、机器人和接收人；关闭开关后待发送事件取消。订阅请求不直接调用 Telegram，通知登记或发送失败均不改变订阅结果。

## 识别边界

浏览器检查使用请求的 `User-Agent` 和 `Sec-Fetch-Mode` / `Sec-Fetch-Dest`，订阅输出格式参数不影响判定。它拦截常见浏览器标识以及页面导航；未知软件名称、空名称和命令行工具不自动拒绝。如需只允许指定软件，请配合 [客户端限制](subscription-client-control.md)。请求头可以伪造，这两种功能不能验证下载方实际运行的软件，也不能撤销已经下载的配置。

来源地址沿用面板可信代理解析，仅信任已有受信代理转发的地址。直连请求伪造转发头不能切换额度或命中白名单。部署在反向代理后应保证可信代理配置正确；否则多个用户可能共用代理出口的额度。内网地址和回环地址不自动豁免，需由管理员明确加入名单。IPv6 等价写法和 IPv4 映射地址会规范化；同一 IPv6 网段的不同地址仍分别计数，分布式探测需结合入口代理的防护。

## 维护

参考本地妙妙屋 `9c8e0267ef918be4704988b6dff9bcaa38911d7c` 的按 IP 失败窗口、临时封禁和请求窗口设计。根据面板环境，使用现有 Redis 缓存和分布式锁共享计数，未复制其进程内记录和订阅路径日志。计数键只含 IP 或用户编号的摘要，状态不保存请求路径或订阅凭据；正常面板进程重启保留计数，Redis 清空或未持久化的 Redis 重启会失去计数。

配置以 `subscribe_protection` 整份写入已有设置表。`1.81.0` 新增迁移：限制索引表保存管理员查询所需的原始 IP 或用户编号及有效期，每小时删除过期记录；现有管理员通知表允许无用户的 IP 事件，并增加对象去重索引。成功发送、取消或终止重试后仍清空通知详情，结束超过七天的订阅通知记录由每小时任务清理，保留最长冷却。计数以 Redis 为准，数据库索引不代替缓存判定。

管理员设置接口严格校验结构、阈值、IP 与用户存在性；专用用户搜索仅返回编号和邮箱，最多 20 条，不返回完整用户记录。新增管理员接口为 `GET /api/v2/{管理路径}/config/subscription-protection/restrictions` 和 `POST /api/v2/{管理路径}/config/subscription-protection/release`，普通用户不可调用。前端源码位于 `YZboard-Dash/src/features/settings/subscription/`，正常构建后同步进面板；不修改 Node 或核心。验证与交付状态见 [兼容矩阵](../YZ_COMPATIBILITY.md)。
