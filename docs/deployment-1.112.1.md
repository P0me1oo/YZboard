## 实机发现

首次部署后连续观察 10 分钟，共 21 个采样点。42 台机器保持近期上报，WebSocket 连接为 42；流量批次持续处理，待处理批次最大 16，期间多次清空，没有新增失败任务。但 24 次 HTTP 检查中有 11 次超过五秒超时，不能据此判定接口正常。

为判断是否由本次代码引起，临时回退到之前运行的 1.112.0 / `7f1de79e256eb3f2cdd0a3c0a791fd00bd184c68`，保持数据库和用户数据不回退。旧版的 16 次同机检查仍出现 5 次超时，随后恢复 1.112.1。这证明问题并非新版本独有，但没有隔离全部环境因素，不能据此断言最终根因。

检查时 Web 请求进程在等待数据库套接字响应，同时系统 I/O 压力较高；没有发现长时间数据库查询或新增设备脚本进入 Redis 慢命令记录。这些是定位线索，不是存储硬件故障的独立证明。

最后恢复时，创建 Swoole 服务器失败后，Octane 错误处理又报 `Laravel\Octane\Octane` 类不可用，掩盖了原始启动异常。Web 服务自动重试 17 次后恢复运行；之后确认该类可以正常加载，重试计数未继续增长。没有通过修改 vendor 或更换依赖版本隐藏该错误，原始启动失败原因尚未确定。

恢复后的三分钟记录包含启动阶段：28 次 HTTP 检查中 17 次返回 200、3 次超时，另有 8 次非成功结果；最后一轮四项检查都返回 200，但前面的间歇超时仍应计入结果。没有新增队列失败；已有设备同步 412 重取快照提示仍可见，回退停止窗口记录过一次设备推送运行时警告。
