## 已完成的真实验证

- Xray 三条跨机连接每方向回显 786,432 字节，页面显示三条连接、一个公网来源，关闭后归零。丢弃确认后约五秒通过 HTTP 重发同一流量批次，累计只结算一次。
- Xray 断开 WebSocket 后 HTTP 状态间隔实测约 10.98 秒、11.00 秒，未立即清空连接；恢复后重新使用 WebSocket。连接保持但丢弃消息时也能超时回退。
- 两通道中断期间另两条 Xray 连接每方向回显 524,288 字节。停止程序后未确认批次落盘；恢复后原批次补报、文件清空。早期临时服务未配置自动重启，断网启动失败后由测试操作重启，不能把该步骤记录为自动恢复。
- sing-box 两条跨机连接每方向回显 524,288 字节，页面显示两条连接、一个公网来源。此阶段结束用户累计上传 2,883,584 字节、下载 1,835,008 字节，与全部唯一批次之和一致；差额包含早期回显路由未完成时的实际上传，未删除或修改账本。
- 实际 Chrome 访问真实面板，浏览器 WebSocket 中断后立即使用 HTTP，后续间隔 10,424 毫秒、10,999 毫秒；恢复后停止轮询，编辑输入和勾选保留，无页面错误。
- 修正后的测试程序以机器模式启动，空节点列表仍建立实时连接；通过真实管理接口绑定节点后，两种核心自动启动，无需重启。两个核心各两条连接同时回显成功，页面汇总四条连接、一个公网来源，机器负载持续更新。
- 上述四条连接全部完成回显后，到真实管理端状态采样显示四条连接相差 856 毫秒；这是一次实际观测，不是所有网络环境的延迟保证。封禁测试用户发生在 HTTP 回退期间，两种核心均收到空用户列表，观测连接数与公网来源归零相差 8,052 毫秒；解除封禁后可重新连接。
- 机器共享连接丢确认时，两种核心分别在约五秒后用 HTTP 重发原批次，结算没有重复。断开共享连接后节点状态间隔约 11 秒，机器状态间隔约 10 至 11 秒；恢复后继续实时上报。机器在 WebSocket 关闭时启动没有连接尝试，开启后约五秒发现并建立一条共享连接。
- 双核心配置重载前的流量与后续离线流量合并保留，每个核心每方向共 524,288 字节；断网停止后各有一个 199 字节的待报文件。临时服务采用自动重启，网络恢复后自动启动，并在正常报告周期补报原批次，两个待报文件清空。期间 Netcatty 会话与隧道中断，重新连接后恢复测试通道，未手工改写批次。
- 最终九个非空唯一批次共上传 4,980,736 字节、下载 3,932,160 字节，用户累计与之完全一致。各次真实发送量均纳入，没有为保持对称而删账。
- 通过真实会话撤销接口删除测试管理员令牌，原实时连接收到拒绝并关闭，实测约 10,150 毫秒；随后 HTTP 状态接口返回 403。浏览器旧回调、乱序帧及旧 HTTP 覆盖新状态的保护另由本地自动化用例验证，不冒充真实网络乱序注入。

真实断线过程中发现旧程序错误日志包含认证查询参数，已在 Node 请求错误包装处修复，保留取消错误识别；定向测试、相关服务测试及 Linux 双架构构建通过。新程序实际触发连接拒绝后，程序化检查确认日志包含失败原因，但不含认证查询参数或实际测试令牌。机器共享连接保持连接但丢弃消息时，两个节点与机器均转为 HTTP 状态上报。

## 验收过程

先使用单节点模式逐项执行，再切换另一核心；最后使用一条机器连接管理两个测试节点重复关键故障。所有计数以同一组可控测试连接与固定测试字节量作为依据。

| 场景 | 操作 | 必须确认 |
| --- | --- | --- |
| 正常运行 | 打开用户、节点、机器页面，创建并关闭多条测试连接 | 连接数分别计数，IP 按现有设备口径去重，关闭后回收；记录采样到显示的实际延迟 |
| 浏览器断线 | 仅切断浏览器测试 WebSocket，保留 HTTP | 立即请求完整状态，之后约十秒兜底；恢复完整快照后停止状态轮询 |
| Node 断线 | 仅切断测试 Node 的 WebSocket | HTTP 继续下发和上报；面板不因连接关闭立即清零；恢复后使用最新状态 |
| 静默连接 | 测试代理丢弃该连接双向消息而不立即关闭 | 心跳或确认期限后回退，不无限等待 |
| 确认丢失 | 面板接收流量后丢弃确认，再放开 HTTP | 使用原批次编号重发；用户与节点累计只增加唯一批次之和 |
| 两通道中断 | 同时中断该测试实例的 HTTP 与 WebSocket，然后重启 Node | 未确认流量留在测试目录，恢复后沿用原编号补报，不漏报或重复结算 |
| 重载与空快照 | 保持连接时重载内核，再关闭全部连接或清空测试用户 | 流量保留，空用户实际清空，零连接与未知状态区分 |
| 乱序 | 延迟旧 HTTP 响应，期间发送新推送，再释放旧响应 | 用户、配置、设备及浏览器都保留新状态 |
| 后续启用 | Node 启动时关闭 WebSocket，随后开启；机器先无节点，再绑定节点 | 自动发现连接与新节点，不需要重启 Node 才生效 |
| 跨节点设备 | 一个测试用户在不同节点连接与断开 | 其他节点及时收到设备变化，重复状态不反复广播 |
| 管理员操作 | 连续更新时编辑、筛选、翻页、勾选、拖动排序和查看 IP 详情 | 编辑输入和勾选保留，分页不复位，IP 详情不自动关闭 |
| 权限失效 | 注销测试管理员或撤销测试登录令牌 | 订阅终止，旧连接或旧请求不能继续写入页面 |
