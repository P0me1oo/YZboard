# 节点状态处理优化

面板 `1.38.1` 保持 `1.38.0` 的页面刷新、节点心跳和展示采样频率，配套节点仍为 `v2.4.0`，不需要重新升级节点。

本次减少每条上报的处理开销：

- 固定结构直接遍历校验，避免为每个用户、IP 和中转连接展开通配规则。会话和序号仍由原验证器检查；IP、数组层级、非负整数及网速范围仍逐项检查。缺省字段与空数组的区别保持不变；损坏的空字符串不视为有效数字或数组。
- 投影锁内批量读取最新快照及已处理版本，减少一次缓存往返。仍使用原锁、版本和新鲜度判断，重复消息不续期，迟到消息不覆盖新状态；处理失败不提交已处理版本，重试继续补齐缓存。

设备数据未变化时只续期的路径在此前版本已实现，本次不重复修改。设备限制、流量结算、权限查询、配置下发和页面订阅机制不变。

## 验证

补充嵌套状态校验、空状态清理、离线缓存过期、投影版本隔离与缓存丢失检查；最终完整测试结果记录于兼容矩阵。

独立运行的新旧校验微基准，每组重复 100 次：0 用户为 1.0731 → 0.3800 毫秒，8 用户为 5.1828 → 0.4576 毫秒，100 用户为 60.6470 → 1.8935 毫秒。仅代表这段校验代码的本地耗时，不等于整机 CPU 降幅。正式发布及服务器实测见兼容矩阵。

服务器 PHP 8.2 与 Redis 独立临时键实测发现，框架批量写入 10/102 条记录时比逐条写入略慢，因此最终没有纳入在线缓存批量写入。保留原有写入方式，临时键已清理。测试比较新旧读取结果保持一致，不假定 Redis 数字返回值与 PHP 原始类型相同。
