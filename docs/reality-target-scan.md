# Reality 目标检测

面板 `1.92.0` / 管理端 `0.64.0` 支持在“设置 → 节点配置 → 预设扫描目标”维护扫描列表。每行一个目标，也接受逗号分隔；离开输入框自动保存，留空恢复默认列表。保存时校验目标格式及已有数量上限，无效输入不覆盖原配置。新预设用于下一次扫描，正在运行的任务继续使用原列表；临时输入和检测当前目标不改写预设。扫描预设与交互优化已随本版发布，本项不修改 Node 或核心。

“开始检测”在输入框下方靠右显示。点击可用结果的“使用”，自动关闭检测窗口，返回节点编辑并填入 SNI 和端口；其他草稿保留，提交节点后生效。

面板 `1.88.2` / 管理端 `0.60.2` 将结果中的未通过原因显示为带 Material Symbols 提醒图标的警告框，例如“目标不支持 TLS 1.3”，不显示末尾句号；不改变目标可用性与回填条件。目前尚未发布。

面板 `1.88.1` / 管理端 `0.60.1` 补充 **证书链** 大小显示，例如 `4287 B`。该值是 Node 握手时收到的所有证书 DER 二进制长度之和；数据缺失或为零时显示 `—`。本次只增加展示，不设置 3500 B 阈值，也不改变证书有效性或目标可用性判断；沿用已有 Node 上报字段，目前尚未发布。

面板 `1.88.0`、管理端 `0.60.0`、Node `v2.14.0` 增加以下结果，目前尚未发布：

- **CDN**：结合域名别名记录和厂商特有 HTTP 响应头识别 Cloudflare、Amazon CloudFront、Akamai、Fastly、Bunny CDN、阿里云、腾讯云、Azure、Imperva、Vercel 和 Netlify；存在多家特征时一并展示。悬停名称可查看识别依据。普通缓存头、DNS 托管商和证书签发者不作为 CDN 判据。结果属于特征识别，不能保证覆盖所有 CDN；“未发现特征”不等于没有 CDN，检查不完整显示“未知”。
- **IP 位置**：面板 `1.95.1` 起按统一本地规则查询 Node 实际连接的 IP：中国大陆 IPv4 用纯真，其他 IPv4 和全部 IPv6 用 ip2region；运营商取自 ip2region。同一响应中的重复 IP 只查询一次，空地址或库不可用显示“未知”，不调用外部位置 API。固定来源见 [IP 位置查询](ip-location.md)；此前版本仅接入 ip2region IPv4 库。
- **页面状态**：证书验证通过后，复用同一条 TLS 连接向目标端口发送 `GET /`，显示首个最终 HTTP 响应状态码及含义。支持 HTTP/2 和 HTTP/1.1，不跟随跳转、不读取或保存正文、Cookie 和完整响应头。403、404、5xx、页面超时与 TLS 可用性分别展示，不改变原有 Reality 回填条件；证书未通过时不发页面请求。

新增 DNS 与页面检查并行执行，最多占用单目标原有 10 秒时限中的 3 秒；握手延迟仍不包含这些检查。查询位置在管理员读取结果时执行，不放进 Node 控制请求。新任务携带可选 `diagnostics` 开关；旧 Node 忽略后仍返回原结果，界面提示升级以显示 CDN 和页面状态。新 Node 接收旧格式任务时不执行增强检测、不增加报告字段。原在途任务可继续完成。

参考本地 RealityChecker `8a152d4014b3781fa1e004f51e37dabcb1ffcbcf` 的展示思路，识别及请求代码独立实现，未采用其厂商名统一返回“CDN”、字符串任意位置匹配或自动跳转行为。不实现被墙检测，也不引入域名黑名单。

面板 `1.85.0`、管理端 `0.57.0`、Node `v2.12.0` 新增此功能，已正式发布；先更新面板，再更新 Node。交互参考本地 3x-ui 固定提交 `608ef4e4010bf83e2e78328e08f77efc051ad4d7`，检测及通信代码在 YZ 项目中独立实现。

在节点编辑界面选择 Reality，并绑定运行新版本 Node 的服务器后，可以使用：

- **检测当前目标**：检查已填的伪装域名和端口。
- **扫描目标**：打开后自动检测设置中的预设目标，输入框显示实际扫描列表。也可以输入逗号或换行分隔的域名、IP 或 CIDR 网段；网段使用 443 端口，域名和独立 IP 可以指定端口。清空输入后检测预设列表，未自定义时使用默认候选。
- **使用**：把通过检测的域名和端口填回表单并自动关闭检测窗口，保存节点后生效。密钥、短 ID、防盗用开关和其他草稿不变。

面板 `1.87.1` / 管理端 `0.59.1` 修正扫描入口：只有正在运行的任务会恢复；上一次检测已完成或失败时，重新扫描内置候选，不再显示旧的当前目标结果。此修正尚未发布。

检测由所选节点服务器执行。延迟包含域名解析、TCP 连接和 TLS 握手，不代表客户端经过代理后的延迟，也不包含后续单独执行的证书链校验耗时。可用判定要求证书有效且域名匹配、TLS 1.3、HTTP/2，以及 X25519 或 X25519MLKEM768 密钥交换。这是候选可用性检查，不替代实际客户端连接验证。

网段扫描先在不发送 SNI 的情况下连接 IP，从证书中发现具体域名，再按发现的域名重新解析并发起带 SNI 的握手。结果中的延迟和 IP 对应复测的域名；该域名可能解析到不同的服务器。它不会枚举服务器上的全部 SNI，也不会自动识别节点的当前网段。

默认候选为 `www.microsoft.com:443`、`aws.amazon.com:443`、`www.samsung.com:443`、`www.nvidia.com:443`、`www.amd.com:443`、`www.intel.com:443`、`www.sony.com:443`。默认列表不包含 `www.amazon.com:443`、`dl.google.com:443`、`www.cloudflare.com:443`，仍允许管理员在预设或临时扫描中主动输入。

每次最多输入 64 项，合计最多 512 个地址；单个网段最多 256 个地址（IPv4 至少 /24、IPv6 至少 /120）。同一服务器同时执行一个任务，同样的在途请求复用原任务。最多 32 个并发握手，单目标 10 秒、IP 初步发现 4 秒、整个扫描最多 170 秒，任务 180 秒后超时。任务和结果暂存 Redis，最后一次交互后保留最多 8 分钟，过期后重新检测。

只检测公网地址。私网、本机、链路本地、共享地址、文档及其他保留地址会被拒绝；域名解析结果中包含这些地址时同样拒绝。连接固定到已检查的 IP，不使用环境代理。此功能没有内网放行开关，不开放新的监听端口。

任务和结果随现有五秒服务器控制请求收发，不影响原重启、升级操作。旧 Node 不声明检测能力时，管理端明确提示升级；新 Node 连接旧面板时继续原有服务。检测只改变表单草稿，保存配置仍沿用原流程。进程变化、超时和过期结果不会覆盖后来的任务。

本地验证使用独立模拟接口和本机 TLS 证书，不扫描真实公网或连接生产服务器。版本与验证结果见 [兼容矩阵](../YZ_COMPATIBILITY.md)。
