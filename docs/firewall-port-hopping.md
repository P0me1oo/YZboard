# 节点防火墙与 Hysteria2 端口跳跃

面板 `1.13.0` 配合 Node `v1.13-yz.24` 管理 Hysteria2 跳跃端口。固定 Xray 和 sing-box 依赖不变，无数据库变更；正式发布状态以 [兼容矩阵](../YZ_COMPATIBILITY.md) 为准。

## 面板填写方式

例如让 HY2 内核监听 UDP `8443`，客户端使用 `20000-20100,20300`：

| 字段 | 填写值 |
| --- | --- |
| 协议 | Hysteria，版本 2 |
| 服务端口 `server_port` | `8443` |
| 连接端口 `port` | `20000-20100,20300` |
| 固定跳跃间隔 `protocol_settings.hop_interval` | `5`，单位秒；也可留空使用客户端默认值 |

支持 `20000,20010,20300`、`20000-20100` 及混合写法。端口须在 `1..65535` 内，不能有空项或倒序范围；设置固定间隔时必须至少 5 秒。空格、重复和重叠范围会在下发时规整。单独一个连接端口保持原有语义，不推断外部单端口映射。

Mihomo、URI 和支持端口跳跃的 sing-box 订阅收到对应集合；sing-box 使用多个 `server_ports` 范围。旧客户端的能力沿用原有版本判断，不支持跳跃时只能使用分配到的单端口。当前字段只提供固定间隔，没有新增官方客户端的随机间隔设置。

## Node 如何执行

配置接口新增 `port_hopping`，保留 `server_port` 作为单一监听端口。机器发现接口仍只返回节点标识和内核选择，具体配置由节点配置接口获取。普通 HY2 节点和 HY2 中转入口可跳跃，落地节点不创建跳跃转发。

Node 默认检测运行中的 UFW/firewalld，在内核成功启动后放行 TCP/UDP 端口，并通过 nftables 或 iptables 将跳跃 UDP 端口转发到真实监听。面板 `enabled` 停用、删除节点、普通节点没有用户、启动/重载失败和正常退出均会清理 Node 自己创建的规则。`show` 只控制订阅显示。

同一 Node 进程的多个节点共享规则，最后一个使用者停止后才回收。已有手工规则保留；被强制终止的进程需要下次以同一配置路径启动才能回收遗留规则。运行中的 Node 每 30 秒恢复缺失规则并重试清理。

Node 可以在顶层配置 `firewall.enabled`、`backend`、`redirect_backend`、`zone` 和 `state_dir`。系统权限、Docker 差异、自定义入站范围、SOCKS 动态 UDP 限制及测试方法见 Node 仓库的 `docs/firewall-port-hopping.md`。部署须使用固定发布版本。

## 验证和升级

面板测试覆盖端口解析、配置接口、停用节点发现、订阅输出和参数校验。Node 使用独立 Linux 网络环境验证真实 TCP/UDP 转发、IPv4/IPv6、手工规则保留、共享引用、规则恢复及失败清理，并使用官方 Hysteria 客户端验证实际跳跃和面板节点生命周期。

先更新 Node，再更新面板并刷新客户端订阅。旧 Node 会忽略新增字段，不能据此自动配置跳跃转发。回滚前先为旧 Node 准备手工放行/转发，或把连接端口改回真实监听端口，再正常停止新版回收托管规则。

协议背景见 [Hysteria 官方说明](https://v2.hysteria.network/zh/docs/advanced/Port-Hopping/)。
