# 数据库占用与清理

入口为“系统管理 → 数据库”，仅管理员可以访问。初始功能随面板 `1.102.0`、管理端 `0.73.0` 发布；原开发版本 `1.102.1` 的表用途说明和页面文案已随面板 [v1.104.3](https://github.com/P0me1oo/YZboard/releases/tag/v1.104.3) / 管理端 `0.75.1` 发布。

## 占用分析

点击“刷新”读取当前应用连接的数据库，显示总占用、表数量、各表数据与索引占用，可搜索表名并排序。内置及已知订阅聚合表的名称下显示灰色用途说明，兼容数据库表前缀；未识别的表显示“暂无用途说明”。用途说明不代表该表允许手动清理。不读取数据内容，不在打开页面时逐表统计精确行数。

- MySQL / MariaDB 使用当前库 `information_schema.TABLES` 的表、索引大小和估算行数。总占用是表与索引之和，不包括数据库日志、备份、共享空闲页或其他数据库，不能当作服务器磁盘占用。
- SQLite 总占用为主文件页数乘页大小，库内空闲空间可继续复用。各表大小来自可选的 `dbstat`；不可用时显示未知值并保留总占用和清理功能。SQLite 不提供估算行数；写入日志不计入主文件大小。
- 其余数据库驱动暂不支持本页分析。没有新增数据库权限、依赖或迁移。

占用口径依据 [MariaDB 表元数据说明](https://mariadb.com/docs/server/reference/system-tables/information-schema/information-schema-tables/information-schema-tables-table)与 [SQLite dbstat 说明](https://www.sqlite.org/dbstat.html)。

## 历史记录清理

勾选项目后点击“查看待清理记录”，查看到期条数和截止时间，再点击“确认清理”。旧版按钮名为“预览清理”，表示删除前的查询与确认，不展示记录内容，也不执行删除。默认不勾选任何项目，查询本身不删除历史数据。

| 项目 | 保留范围 | 清理边界 |
| --- | --- | --- |
| 访问记录 | 最近 7 天 | 仅访问明细，不改变流量与结算防重记录 |
| 机器监控历史 | 最近 24 小时 | 保留机器、节点和当前监控状态 |
| 管理员操作日志 | 最近 3 个月 | 保留当前操作审计 |
| Telegram 消息防重记录 | 最近 7 天 | 保留账号绑定和有效期内的防重记录 |

以上期限与现有定时任务一致，页面不缩短保留期。截止时间当天的边界按具体时间比较，仅删除严格早于该时刻的记录。用户、订单、余额、累计流量、统计汇总和节点报告不提供删除入口。数据库中不存在的清理表会明确标示不可用。

每个项目每轮最多删除 500 条，四个项目合计最多 2,000 条；有剩余时再次预览、确认。预览固定截止时间、最大记录编号和本轮记录列表，10 分钟有效，仅创建预览的管理员可以确认；预览后新写入的记录留到下一轮处理。同一预览重复确认返回已缓存的结果，不继续删除下一批；即使提交后结果缓存写入中断，重试也只处理原批次。数据库内的删除和剩余检查在同一事务中完成，任一步失败整轮回滚，可在预览有效期内重试。清理通过共享缓存锁互斥，沿用统计查询的并发和数据库查询超时限制；不自动重试浏览器提交。

先确认已有所需备份；清理无法撤销。删除后的空间一般留在数据库内复用，不保证磁盘文件立即缩小；页面不执行会重建表或数据库文件的 `OPTIMIZE TABLE`、`VACUUM`。原定时任务继续运行，预览条数可能因其清理而减少，最终以本轮实际删除条数为准。

接口为管理前缀下的 `GET database/overview`、`POST database/preview` 和 `POST database/cleanup`，沿用管理员权限、请求频率限制及操作审计。响应禁止缓存，预览凭据只保留在页面内存和短期服务端缓存；不写入网址或本地存储，审计沿用敏感字段过滤。重启或清空缓存后需重新预览。
