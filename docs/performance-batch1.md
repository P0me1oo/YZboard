# 第一批性能优化

开发版本 `1.82.1`，开发基线 `0841f0a2028453872bac3adb99eddea011c80e0d`，随 `1.82.2` 一并交付。只修改 YZboard 后端；正式发布状态与完整回归结果见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 实时读取

- 节点列表直接使用已批量取得的实时状态。新鲜状态补读旧心跳、最近流量上报时间；过期或尚未采样的实时状态只补读流量上报时间。没有实时记录的旧节点一次读取原来五项缓存，保留原输出。
- 正常在线节点原来触发 12 次缓存读取，现在只读取两个值，使用一次批量命令。旧心跳仍决定可用状态，不能因为收到实时心跳就视为已正常上报流量。300 秒旧节点判断边界、35 秒实时新鲜度、未知与空集合的区别不变。
- 同次快照中，用户连接数、速度、设备和节点展示共用节点资料及状态；缓存未找到的结果也在本次读取内复用。设备来源不在已取得的节点列表中时补读，不假定所有来源都是新节点。父节点相同且协议相同的展示共用回退读取和负载格式化，子节点自身累计流量仍分别返回。
- 连接数只为没有实时记录的旧节点读取兼容缓存；新节点缺少连接采样或已过期仍显示未知，不回退成陈旧的已知值。

参考 Lite 的 `web/rpc/jsonrpc/admin.dashboard_cache.go` 中同次构建共享基础资料的方式。没有引入其跨轮结果缓存或客户端资料 TTL；面板已有长连接复用、设备未变化时轻量续期、页面快照共享均不属于本次新增成果。

## 完整配置与设备同步

HTTP 和长连接完整同步原来各筛选两次可用用户。现在在同一设备版本锁内，用配置已取得的名单生成设备快照，普通路径只筛选一次。名单不会存到服务属性或跨轮缓存；下一次处理仍检查禁用、到期、流量耗尽和权限组。插件筛选与扩展服务继续走原来的调用顺序。

周期设备下发仍每五秒逐节点校准，不共享不同节点的资格。也没有复用各节点版本锁外已筛选的设备结果：另一条 HTTP 同步可能先提交新快照，之后再提交同轮早先缓存的旧设备结果会破坏顺序。本批只保留同次展示内的设备批量读取，以及完整同步锁内的资格复用。

配置版本和设备版本仍分别维护；长连接仍先发送配置再发送设备，设备读取失败不提交新设备版本，锁释放后可以重试。用户资格、设备过期、授权、流量事务与结算写入逻辑没有改变。

## 验证

针对实时展示、连接数、速度、状态存储、设备来源过滤、完整同步、插件、权限变更、校准和 HTTP 诊断运行相关回归。新增用例验证新旧展示字段等价、缓存读取次数、同次节点查询与父节点共享、缺失结果复用、下一次读取重新检查新鲜度、资格重新筛选、锁内读取与失败重试，以及诊断关闭、到期、隐私和连续请求的计数隔离。

PHP `8.4.21`、独立 SQLite 内存库及内存缓存下，相关回归通过 148 项、1,004 次断言，包含设备换网和服务器流量保护的资格路径。命令：

下一批优先检查：

1. 机器控制轮询中的重复资料读取与写入。`1.80.0` 源码确认，认证阶段查询机器并写最近在线时间，随后控制事务又锁定读取机器并再次写入在线时间和运行状态。是否能合并必须保留认证、机器启停和操作确认的事务规则，本批未改动。
2. 节点握手的认证与公共请求处理成本。握手响应本身较小，但请求量大；先拆分认证、插件初始化、路由与序列化成本，再决定修改，不直接降低握手频率。
3. 在有实际管理页面操作时重新采样管理接口，并单独观察长连接页面快照；本次 HTTP 数据不能代替长连接成本。完整同步的本批资格去重也尚未获得生产上线后的收益数据。

总耗时包含中间件、认证、控制器及等待，不是 CPU 时间；不含反向代理、框架启动前段、响应发送及异步队列。SQL 数字来自框架完成查询事件，不保存 SQL 或参数。Redis 数字来自框架命令事件，不包括原生 pipeline 内命令和 Lua 内部操作，不能当作 Redis 服务器命令总数；差额也不能直接归为 PHP 计算。聚合文件使用非阻塞锁，争用或写入失败会丢弃诊断记录，数字是成功聚合的样本，不能作为计费或审计账本。

## 诊断开关

配置位于 `config/http_performance.php`：

- `HTTP_PERFORMANCE_ENABLED` 默认 `false`，关闭时不注册监听器或写文件。
- `HTTP_PERFORMANCE_UNTIL` 为结束时间的 Unix 秒数，默认 `0`；未设置或已到期不采样。
- `HTTP_PERFORMANCE_SAMPLE_RATE` 默认为 `0.1`，范围限制在 0–1；设为 0 不采样。

仅写 `storage/logs/http-performance.json`，内容为代码中控制器方法对应的计数、耗时、缓存读写次数及错误数量，最多 128 个接口加一个其他类别；到期或禁用后停止采样，Redis 事件设置在每个采样请求结束后恢复。文件读取上限为 1 MiB，诊断读写失败不影响业务响应。采样比例不足 1 时，请求数是样本数，不能直接当作总请求数。

不记录 Token、Cookie、订阅、认证头、请求正文、原始查询参数、IP、用户/节点身份或完整路径。环境配置按现有部署方式加载；本次生产临时开关和文件已清理，仓库默认仍为关闭。上述实测发生在第一批代码提交和发布之前，不代表 `1.82.2` 已部署到生产服务器。
