# 中转节点：单入口、多逻辑节点、多落地出口

一个 VLESS 入口节点加若干落地节点，在订阅里表现为多个可以直接选择的普通节点。
所有节点共用入口的地址、端口和 Reality 参数，客户端不需要代理链，也看不到任何
落地服务器的连接信息。

## 父级节点的含义

本功能复用节点管理页面已有的“父级节点”字段，不新增管理端表单项。

- 父级节点为空：普通节点，行为不变。
- 父级节点不为空：当前节点是中转逻辑节点，父级节点是客户端实际连接的真实入口。

对于中转逻辑节点，各字段的含义变为：

| 字段 | 含义 |
| --- | --- |
| 协议 | 入口到落地之间的中转协议，第一版只支持 Shadowsocks |
| 节点地址、连接端口 | 入口连接落地服务器时使用的地址和端口 |
| 服务端口 | 落地服务器上内部入站的监听端口 |
| 绑定服务器 | 最终落地服务器 |
| 节点名称、排序、权限组、显示、启用 | 逻辑节点自身独立拥有 |
| 倍率 | 不生效，强制继承入口节点 |

约束：

- 父级节点必须是 VLESS 节点，且自身没有父级节点；
- 不允许节点以自己为父级、多层中转，或让已经是别人父级的节点再挂到别人下面；
- 逻辑节点的加密算法必须在支持列表内。

违反以上任一条时，保存节点会返回“父级节点”的校验错误。

## 路由编号

面板为每个节点自动分配一个 1-65535 的 VLESS 路由编号，管理员无需填写。生成订阅
时，编号被写入用户 UUID 的第 7、8 字节（标准写法的第三段）。Xray 校验用户前会把
这两个字节清零，因此不影响身份匹配；认证通过后再按原始字节还原编号，用于选择出站。

编号在创建时分配并保持稳定，编辑节点不会改变。分配游标只增不减，删除节点后编号
不会被立即复用。编号 0 不使用，因为 Xray 的端口列表解析会丢弃数字 0。

## 订阅生成

中转逻辑节点在订阅中继承入口的客户端协议、地址、端口和全部 Reality 参数，保留自己
的名称、排序、权限组和显示状态，并使用当前用户的原始 UUID（只改写路由字节）。入口
节点本身继续作为可见、可选择的节点存在，使用本机直接出口。

以下情况逻辑节点不会出现在订阅中：

- 用户所在权限组不在该逻辑节点的权限组内；
- 节点被禁用；
- 拓扑不完整，例如父级节点已被删除。

拓扑不完整时节点会被直接丢弃，不会退化成一个暴露内部地址的 Shadowsocks 节点。

## 服务器之间的中转

入口服务器上的 Xray 为每个逻辑节点生成一个独立的 Shadowsocks 出站，按路由编号选择；
落地服务器上的 Xray 生成一个只含内部凭据的 Shadowsocks 入站，收到请求后直接访问目标。
不使用 Realm、GOST、NodePass、WireGuard 或 iptables 端口转发，落地服务器也不需要开启
系统级转发或出口地址转换。

内部认证信息由面板从应用密钥派生，两端各自从面板拉取，不落库、不写入订阅、不写入日志。

## 权限、倍率和流量

每个逻辑节点保留独立的名称、权限组、显示状态、启用状态、排序和节点总流量。

流量分成两个互不叠加的口径：

**用户套餐流量**只在入口按真实 VLESS 用户身份统计一次。用户通过任意逻辑节点产生的
上下行流量都计入入口上的同一份用户流量。扣除公式固定为：

```
用户扣除流量 = (入口统计到的上行 + 下行) × 入口当前生效的倍率
```

入口倍率为 2 时，用户产生 100 MiB 原始流量，套餐扣除约 200 MiB。入口流量与落地流量
不相加后再乘倍率，也不分别用入口倍率和落地倍率重复计算。逻辑节点自己填写的倍率不参与
用户扣费，读取和展示时统一使用入口的有效倍率。

**落地节点流量**来自入口上各逻辑节点独立 Shadowsocks 出站的计数器，按稳定的出站标签
`relay-<节点 ID>` 映射回对应逻辑节点，只用于在控制面板查看各落地线路承载的上下行和总量，
不参与用户套餐扣费。落地服务器的内部入站没有面板用户，不会重复上报用户流量。

Shadowsocks 的协议封装会让出站统计与用户有效流量存在小幅差异，属于不同统计口径。

第一版不提供“某个用户在某个逻辑节点用了多少流量”的二维统计，因此逻辑节点不能设置独立
有效倍率。用户总流量、剩余流量、速度限制和设备限制统一以入口上的用户身份为准。

## 生命周期

逻辑节点新增、修改、禁用或删除后，面板会同时刷新入口节点的配置，入口据此重新生成
Shadowsocks 出站和路由规则。重复同步、节点程序重启和配置重载保持幂等，不会产生重复的
入站、出站或路由规则；清理逻辑节点不影响入口的真实入站，也不影响其他逻辑节点。

## 升级影响

“父级节点”的语义在本版本发生变化，升级前需要确认存量数据。

**`parent_id` 为 0 或 NULL 都表示“没有父级节点”。** 从 v2board 迁移过来的库通常用 `0`
填充该列，而不是 `NULL`；自增主键不会是 0，因此两者一律按普通节点处理，行为与升级前一致。

真正会改变行为的，只有父级节点指向一个真实节点 ID（大于 0）且协议是 Shadowsocks 的节点：
它们会被识别为中转逻辑节点，面板不再向其下发用户，订阅中也会改为继承入口参数或整体隐藏。
升级前可以用下面的查询确认：

```sql
SELECT id, name, type, parent_id FROM v2_server WHERE parent_id > 0;
```

查询结果中协议为 `shadowsocks` 的节点会被重新解释。如果这些节点原本只是借用父级节点共享
运行状态或 SS2022 服务端密钥，请在升级前把它们的父级节点清空。协议不是 Shadowsocks 的
历史子节点继续按旧语义工作，不受影响。
