# 设备名额与换网替换

设备替换从面板 `1.56.0`、Node `v2.8.0` 开始支持；面板 `1.57.0`、Node `v2.9.0` 增加通信与续期优化。本功能继续按来源公网 IP 计算设备名额，不能识别真实的手机或电脑。IPv4 按地址，IPv6 按 `/64` 合并；原有来源排除名单继续生效。

## 替换规则

名额未满时直接接纳新来源。满额时，面板比较该账号各来源最近一次新建连接的时间，选择最久没有新建连接的来源退出。已有长连接持续下载不会更新这个时间，因此仍可能被选中。

Node 关闭这个账号从旧来源建立的连接。同一来源同时出现在多个节点时，必须全部确认关闭，才能把名额交给新来源；不能只清除面板计数。共享公网 IP 的其他账号不受影响。

旧来源在完成关闭后进入 60 秒冷却，期间不能挤掉其他来源。账号出现真实空位时可以提前接入，并结束该来源的冷却。新来源无需等待这 60 秒。多个新来源同时申请时，面板串行协调；已放弃的候选不会永久保留替换优先权。

## 连接与恢复

Node 按实际连接保存来源记录，每秒同步。新版本在完整快照确认且内容未变化时只发送续期；来源变化、待处理申请变化和真实关闭仍上报完整快照，旧版继续完整同步。TCP、UDP 和普通 WireGuard 使用同一套名额协调；普通 WireGuard 的保活和已有连接流量不会被当成新连接，其首次来源申请异步完成，避免阻塞其他用户的收包。

设备会话、申请和同步优先复用现有长连接，两种通道共用校验与处理。确认丢失或断线后按原业务序号切换 HTTP；续期基线失配时补发完整快照，不将其视为连接已关闭。实现与兼容见 [运行开销优化](runtime-optimization.md)。

重复关闭请求只处理对应的一次授权，迟到的旧请求不能关闭重新接入的来源。核心重载和用户退出通过实际关闭回调回收名额。来源完全离线后，面板清理相应协调记录。

面板 `1.111.0` 与 Agent `v2.28.0` 配套时，断联使用已核验许可的固定期限，详见下节。旧组合沿用原连接记录，不具备一小时到期保证。会话缓存丢失时，Node 先关闭旧会话的连接，再重新握手；不承诺在固定秒数内完成换网。

## 跨节点许可与断联期限（1.111.0 / v2.28.0，本地未发布）

同一账号、同一完整公网 IP 共用一份许可。面板周期同步只向当前有权限使用该节点的账号下发仍有效的许可；节点即使暂时没有连接，也可以缓存许可并供重连使用。目标节点有有效许可时直接本地放行，仍受最新账号、节点及中转路由权限限制；没有许可时向面板申请。IPv6 的名额计算仍按 `/64` 合并，同网段不同完整 IP 分别申请许可。

每个持有节点有自己的最后确认时间和固定到期时间，最长间隔一小时。Node 使用单调时钟，并扣除响应传输时间；新建连接、重试、重复响应、普通心跳和收发数据均不续期。只有面板重新核对账号、节点权限以及权威许可后才能更新期限。节点重启清空本地许可，断联时不能通过重启获得新的一小时；恢复后需要面板核验。

断联期间，已缓存许可可在原期限内重连。到期拒绝新连接，并独立关闭依赖它的 TCP、UDP、WireGuard 来源连接；某条连接关闭较慢不会阻塞其他到期连接。已知撤销、封禁或权限移除立即使许可失效，不等待一小时。许可列表恢复时撤销优先，上报的旧许可或迟到授权不能重新创建已撤销许可。

面板保存全部持有节点的占位。没有活跃连接不等于许可已失效，空闲缓存和离线宽限仍占一个设备名额；撤销后要等所有持有节点确认停用，或相应固定期限结束，才能释放。单一节点重启或清空连接快照不会提前释放其他持有者。多节点共用同一许可只计一个名额，同出口其他账号分别处理。

面板 `1.111.1`（本地未发布）会在许可到期或停用确认后清理该节点不再需要同步的账号，协调记录已经过期的旧队列条目也会清理。仍有有效许可或待确认撤销通知时继续保留；其他节点尚未结束的任务独立处理。

握手通过 `realtime.device_lease_cache=1` 声明能力，设备会话使用 `lease_cache=1` 协商。申请响应和同步列表包含许可确认时间、到期时间及面板当前时间；同一业务序号重传不延长确认时间。缓存确认写入成功后才返回，恢复时不根据节点上报重建未知许可。HTTP 与长连接共用相同校验，申请仍保持各来源独立，并防止在途旧空列表删除刚授予的许可。

完整保证要求面板和全部涉及设备计数的 Node 配套更新，先面板后 Node。旧 Node 和旧面板继续原协议；缓存模式运行期间面板回滚或不再确认该能力时，Node 不续期，已有许可按固定期限失效。此功能不改数据库、管理端、订阅或两个核心 fork。

## 兼容与交付

- 先更新面板，再更新所有涉及设备计数的 Node。旧面板与新 Node 组合继续原设备检查。
- 混用旧 Node 时，旧节点无法报告准确的新建连接时间和关闭确认；该账号满额时保留原拒绝规则，不能把升级了一部分节点视为全局替换已生效。
- 回滚到旧 Node 后，旧协议握手会恢复旧来源计数，避免遗漏旧节点的名额。
- 设备协议优化本身无数据库迁移，用户无需重新导入订阅；面板 `1.57.0` 同时包含此前省份缓存修复迁移。正式版本、下载来源、镜像与检查结果以 [兼容矩阵](../YZ_COMPATIBILITY.md) 为准。

## 首次授权与批量测延迟（1.104.4 / v2.24.0，本地未发布）

面板握手增加可选能力 `realtime.device_handover_admit_sync=1`。支持此能力时，Node 向原 `device-handover/admit` 接口或 `device.admit` 长连接事件，同时提交当前完整设备状态和授权申请。面板先保存状态，再在账号锁内核对名额，返回授权结果及 `sync` 状态确认。新增来源在正常空位路径中只需一次业务请求；启动会话握手、每秒同步和需要等待其他节点真实关闭的重试仍然存在。

嵌套 `snapshot` 包含同一运行代次、独立状态序号、全部未结束申请、实际连接来源及关闭标记。状态序号不得早于申请序号，待处理列表必须包含当前申请。缺失列表、跨代状态、非法连接序号和非完整状态均拒绝；过期快照不覆盖较新状态，较新状态已删除的申请返回 412，不重新授权。HTTP 与长连接使用相同校验和业务处理，长连接确认丢失后保留同一申请与快照转 HTTP。

合并请求只协调当前申请账号并返回其撤销结果；其他账号由周期同步协调。Node 保留其他账号的关闭标记直到周期同步确认。等待替换时，每次重试携带最新完整状态；撤销回调执行不等于底层关闭完成，来源仍有实际连接时继续占位。迟到授权、错误或缺失状态确认不能放行新连接。

新 Node 在旧面板未声明能力时继续“同步后授权”；新面板仍接受不带 `snapshot` 的旧申请。握手后面板回滚并忽略新增字段时，Node 丢弃缺少状态确认的结果，关闭该能力，实际重新同步后使用原申请序号重试。会话丢失时先关闭旧连接，再重建会话并清除上一代续期基线。此改动不修改数据库、订阅、管理端、两个核心或固定依赖。

### 超时排查：事实与尚未验证的原因

已由代码和本地测试确认：

- 原首次准入先等待设备同步，再请求授权；同步等待和两个请求消耗同一连接等待预算。合并后无需在 Node 的同步锁后排队，仍保留最多 8 秒及调用方更短的截止时间。
- 框架缓存锁默认抢锁失败后等待 250 毫秒才重试，锁提前释放也存在等待。设备协调改为 25 毫秒重试，原 15 秒锁期限与每次 2 秒抢锁上限保持。嵌套锁等待与实际处理时间可累计，2 秒不是整个接口的总耗时上限。
- 原同步会遍历待协调账号；合并授权避开这段整队列处理。授权仍会查询用户权限、设备状态、节点存在性和旧 Node 的 Redis 来源；用户筛选插件可能读取完整名单。授权路径没有调用外部 IP 归属地查询。
- 长连接单次确认等待最多 3 秒后转 HTTP，仍受总准入预算约束；HTTP 客户端 30 秒设置不会把准入等待延长到 30 秒。长连接事件直接同步执行设备处理，慢查询或锁等待可阻塞该工作进程的其他事件。

尚未确认：生产环境是否存在数据库或 Redis 慢响应、长连接工作进程积压、DNS/TLS/反向代理延迟，以及 Clash 自身更短的测延迟时限。没有生产请求分段耗时，不能认定其中某项就是线上偶发超时根因，也不能承诺此次修改消除所有超时。后续若定位实际链路，应对同一时段核对请求总耗时、缓存锁与数据库耗时、工作进程积压和客户端截止时间；记录不得包含认证内容或完整连接配置。

### 本地验证

面板接口和服务测试覆盖完整状态校验、权限、同一授权重试、乱序与已结束申请、最新连接排序、撤销后真实关闭、会话重启和旧接口；文件缓存配合独立 SQLite 测试文件启动 8 个 PHP 进程，验证不同来源不超额、同来源重复授予及不同账号并发。锁竞争专项使用框架的模拟时钟确认 25 毫秒重试和超时不放行，缓存写入故障验证拒绝返回授权。

Node 覆盖 32 个有效等待者共享申请、32 个独立账号并发、取消隔离、同步阻塞、截止时间、迟到响应、撤销等待、会话恢复和回滚兼容，并进行竞态检查。双核心与普通 WireGuard 沿用固定依赖，执行接入、关闭确认、配置快照、重载恢复专项。实际结果见两仓库兼容矩阵；多进程测试使用文件缓存，不代表生产 Redis 性能实测，没有连接真实服务器或运行 Clash 生产批量测试。
