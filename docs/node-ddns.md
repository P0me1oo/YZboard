# 节点 DDNS

面板 `1.106.1`、管理端 `0.77.0` 的本地开发功能，尚未发布。Node 沿用 `v2.25.0`，两个核心及固定依赖不变。

## 地址与域名

解析来源为管理员在节点设置里手填的连接 IP。修改该 IP 后，面板更新基础解析；不读取服务器上报地址来替换它，也不修改节点之间的内部地址、来源白名单、端口或认证信息。

例如，域名预设为 `ddns.example.com`，节点前缀为 `hk01`：

| 用途 | 域名 | 记录 |
| --- | --- | --- |
| 节点基础解析 | `hk01.ddns.example.com` | A 或 AAAA，指向节点手填 IP |
| 用户个人域名 | `随机标识.hk01.ddns.example.com` | CNAME，指向节点基础域名 |

随机标识独立生成，不使用用户编号、邮箱、订阅凭据或连接身份。同一用户和入口保持固定；共用入口的多条中转线路共用个人域名，只有用户失去全部对应线路权限后才撤销。

## 配置

1. 在「系统设置 → DDNS 设置」保存配置名称、可用域名、Cloudflare Zone ID 和专用 API Token。可用域名必须属于该 Zone；凭据仅需必要的 DNS 读写权限，加密存储且不回显，编辑时留空保留。
2. 使用「检查额度」读取 Cloudflare 的实际记录用量和配额；同一个 Zone 下的多个预设共用额度。该操作验证读取能力，首次实际创建记录才能确认写入权限。
3. 在普通节点编辑页手工填写连接 IP，开启 DDNS，选择域名预设和未占用的前缀。第一版沿用一个 IPv4 或 IPv6 输入，不支持在连接地址里填写多个 IP 或上游域名。
4. 中转线路使用前置入口的配置。在前置负载均衡启用时，DDNS 配置位于统一调度入口，必须明确填写统一入口连接 IP；原池域名及其托管记录保持独立，个人 DDNS 需要不同前缀。
5. 保存后后台创建基础解析和有效用户的个人别名，首次启用后用户更新一次订阅。仅 IP 变化时，个人域名保持不变。同步尚未完成时订阅返回可重试的 503，不下发未创建的个人域名。

标准 TLS 节点开启前需要明确填写证书验证域名，Reality 节点需要填写握手域名。HY2、TUIC、AnyTLS 按各自协议的 TLS 配置读取证书域名。订阅只替换连接地址，其余握手和认证参数沿用原配置，不关闭证书校验。

## 同步与用户状态

节点地址、权限和用户状态变化后排队同步，每分钟的 `ddns:sync` 任务补偿自然到期、批量写入遗漏及外部接口错误。定时任务和队列使用共同的同步锁，按最新数据库状态计算，不把旧 IP 放入队列载荷。每十分钟重新核对远端记录，修复被移除或修改的本功能记录。

队列单轮使用 20 秒预算，定时任务最多使用 180 秒；分页、用户处理、记录批次和 HTTP 请求共用截止时间。时间用完会保留已完成批次，下轮先处理后面的入口，再重新读取远端状态继续未完成的操作。未读完的分页快照不会用于修改或删除记录。个人别名批量读取、分批补建，远端记录按域名索引，避免逐用户查询和反复扫描整个区域。

- 有效用户须未封禁、未过期、流量未耗尽，并拥有该入口至少一条可用线路的权限。
- 用户到期、封禁、流量耗尽、失去权限或删除后，撤销对应个人别名，保留本地随机标识。
- 续费、解封或恢复流量和权限后，重新创建原别名，不改变已保存的个人域名。
- DDNS 不代替现有节点端认证、过期限制、计费和权限控制。DNS 更新受任务调度、Cloudflare 发布和客户端缓存影响，不承诺即时断线或恢复。

解析固定使用仅 DNS（灰云）及 60 秒 TTL，不提供用户层泛解析；泛解析可能使已删除的个人域名继续得到 IP。

## 复制、关闭与清理

复制节点沿用现有规则：保留服务器绑定、协议和端口，副本默认关闭并隐藏；独立部署的空运行状态按原规则处理。DDNS 绑定存于独立表，副本不继承基础域名、个人域名或 Cloudflare 记录编号。需要在副本中重新开启并选择未占用前缀。

关闭 DDNS 后，新订阅回到原连接 IP。旧个人域名保留，继续跟随地址变化和用户资格同步，以便已保存的配置过渡使用。修改前缀或预设时，新订阅使用新域名，旧绑定显示为「保留旧解析」。

关闭后若把连接地址改成普通域名，旧解析暂停地址更新并提示补回有效 IP，但仍撤销失效用户的个人别名；其余旧记录保留。补回 IP 后继续同步，或明确清理不再需要的旧解析。

在系统设置中明确选择「清理解析」后，后台删除对应旧记录和本地绑定；客户端中仍使用这些旧域名的配置会失效。清理失败保留归属信息供重试。删除节点则自动进入清理流程，不提前删除记录归属信息。节点改为中转落地时，撤销其原入口解析，不发布内部落地 IP。

配置被当前或保留的绑定引用时不能删除；正在使用的预设不能修改域名和 Zone ID，可以更换凭据。

## 记录归属与容量

面板先保存记录意图及独立归属标记，再通过 Cloudflare 批量接口操作。接口写入成功但响应丢失时，下次通过标记恢复记录编号；不会接管同名的其他用途记录。只更新、删除本功能记录；原前置池记录分别管理。

按每入口一个 IP、每用户拥有全部入口计算，记录数为「入口数 ×（用户数 + 1）」。例如 100 个入口、30 个有效用户需要约 3100 条，还要加上该 Zone 下的网站、邮箱及保留旧解析。Cloudflare 配额按实际区域或账户计算，在多个子域名预设之间不能重复使用同一份额度。

同一入口先撤销失效记录、更新已有解析，再检查额度并新增记录。额度不足会暂停新增用户解析，但不会阻止已有记录更新 IP。订阅同时检查个人别名和基础解析；已确认远端记录不存在时清除旧编号，重建成功前返回可重试的 503。若远端编号仍存在但归属发生变化，保留本地归属信息并停止下发，等待处理冲突。外部接口限流或失败会稍后重试，不将外部响应、认证头或凭据写入错误信息。

## 验证范围

本地使用 SQLite 内存数据库、隔离的测试身份和模拟 Cloudflare 响应验证。真实 Cloudflare Token、真实域名写入、生产服务器和客户端实际重新解析行为不在本次本地验证中。具体命令和结果记录在兼容矩阵与管理端维护记录。
