# 前置负载均衡

面板 `1.106.1`、管理端 `0.77.0`、Node `v2.25.0` 的本地开发功能，尚未发布。本版只开放 **VLESS Reality + TCP/RAW** 前置池；已有独立节点、HY2 和单前置中转保持原有配置。两个核心和固定依赖不变。

## 工作方式

流量路径为「用户 → 统一调度入口 → 池内前置 → 指定落地 → 外网」。调度入口实际承载全部流量，需选择有足够带宽的服务器；可以使用已有服务器，但监听端口不能与现有服务冲突。

- 每个新 TCP 连接独立轮询，已有连接固定在原前置上。优先级数字越小越优先，同级轮询；该级全部不可用后使用下一级。TCP 建连失败会尝试其他成员，不重放已经转发的用户数据。
- 以每个池专用入口的有效上报时间判断在线，不继承父级节点状态。全局离线阈值默认 180 秒；调度任务每 30 秒推送状态，REST 同步也会重新计算。阈值不是秒级切换承诺。
- 不执行延迟、丢包、端口或落地连通性探测。心跳在线只表示节点管理通信仍然正常。
- 成员更新不重建调度监听。所有成员不可用时拒绝新连接，不回退到前置直连或其他落地。
- 单个统一入口故障会使该入口下的线路不可用，本版不提供调度入口自身的多机高可用。

## 配置顺序

1. 确保调度入口、参与前置池的服务器及 WG 落地均运行 Node `v2.25.0` 或更新版本，并完成版本上报。旧 Node 不下发池管理的实例。
2. 在「节点管理 → 前置负载均衡 → Cloudflare 配置」保存名称、主域名、Zone ID 和专用 API Token。Token 仅授予指定域名的 DNS 编辑权限，加密保存，接口不回显；编辑时留空表示保留。
3. 新建前置池，选择 Cloudflare 配置，填写独立入口子域名并选择调度入口服务器，不填写入口 IP 或连接端口。
4. 从已有节点中勾选成员。首个节点自动识别协议并导入连接模板；其余节点需兼容。每台服务器在同一个池中只允许一个成员，填写各成员优先级。
5. 在指定落地节点的「前置入口」中选择该池。支持 Shadowsocks、VLESS、WireGuard 落地，各条线路保持独立身份、权限、倍率和固定落地。父级节点选择与前置池独立。
6. 保存后同步 DNS；成员及入口实例由机器管理流程自动发现并下发，用户刷新订阅后使用统一域名。

新建池默认启用，后续在列表的「状态」列使用滑动开关启用或停用，编辑表单不设置启停。开关保存后生效；请求失败保持原状态，正在编辑的其他内容不会随开关提交。

创建时自动读取所选服务器上报的公网地址，优先 IPv4，无 IPv4 时使用 IPv6；没有上报地址会提示先恢复节点程序上报。连接端口读取首个前置节点；已被其他实例占用时，从 20000 起分配可用端口。修改已有池或切换列表开关时保留已保存的连接参数，改选另一台调度服务器后重新读取。

保存后的实际域名和端口显示在列表的「连接地址」列，需要配置云安全组时以该地址中的端口为准。

池为各服务器创建独立的专用入口，自动选择共同可用的内部端口，不改写原直连节点。模板在创建时保存快照，后续修改原直连配置或成员优先级不重新生成密钥。节点被池引用时，删除前先移除对应成员。

成员节点的地址必须分别直达各自服务器，不能都填写同一个轮询域名。池实例沿用各成员原节点的自动防火墙开关；关闭自动防火墙或使用云安全组时，需自行放行调度入口到池内部 TCP 端口的连接。端口由面板分配，保存后可在编辑池的「高级设置」中查看。

## 真实来源与计费

调度入口使用标准 TCP PROXY v2 传递真实来源。自动创建的池默认信任调度服务器上报的具体 IPv4/IPv6 地址；普通节点保持原有接收开关。入口经过 NAT、私网或其他出口访问前置时，可在池的高级设置中填写前置实际看到的来源 IP，不接受全网网段。

用户认证、设备限制和用户计费继续由池成员上的现有核心执行，统一入口不重复扣除用户流量。调度入口服务器配置流量限额时使用网卡计量模式；本版不支持在该服务器上使用「代理流量」作为限额计量来源。

池专用入口只下发已绑定落地的线路权限，不开放前置自身直出；原直连节点仍使用各自原有权限。

WG 落地为不同前置派生独立对端密钥和隧道地址，落地配置包含全部对端，避免多台前置共用一个 WG 身份造成端点切换。旧单前置的密钥格式保持不变。

新增、移除 WG 对端会更新落地配置，现有 WG 会话可能重建；仅成员心跳在线、离线变化不修改 WG 对端配置。

## DNS 管理

域名只指向统一调度入口，前置成员的选择由调度入口执行。固定使用仅 DNS（灰云）和 60 秒缓存，不提供按成员轮流修改解析记录的功能。选择不配置 Cloudflare 时，需要自行把域名解析到入口 IP。

只修改本功能创建并记录归属的 DNS 记录。发现入口域名已有其他用途的 A、AAAA 或 CNAME 时暂停同步，禁止接管或删除。接口失败保留现有记录并显示错误，后续任务重试。停用池后同步清理托管记录，再解除落地引用和删除池；更换域名或 Cloudflare 配置前须先完成旧记录清理。

面板 `1.106.1` 起，创建前先持久化意图及随机归属标记。Cloudflare 写入成功但响应丢失时，可恢复记录编号或直接按标记清理，不会重复创建，也不会接管同名外来记录。既有已登记的旧记录编号继续有效；增加的兼容迁移不删除旧记录。存在尚未确认的写入时，须先完成同步或清理，再回滚该迁移，避免丢失归属。

统一入口也可配置[用户个人 DDNS](node-ddns.md)。开启个人 DDNS 时明确手填入口连接 IP，使用与原池域名不同的前缀；两类托管记录分别维护。

本地验证覆盖轮询、并发、优先级、离线边界、连接失败回退、来源地址传递、配置更新、两种核心与固定落地的组合，以及管理页面和 DNS 归属。Cloudflare 使用模拟接口，未使用真实 Token 修改域名；没有连接、更新生产服务器。具体检查结果见本次兼容记录。
