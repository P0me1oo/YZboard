# 实时通信

目标版本：面板 `1.31.0`、YZ-Agent `v1.25.0`、管理端 `0.12.0`，尚未发布。

## 数据与周期

运行状态包括连接数、在线公网 IP、负载和运行指标，以每秒采样和发送为目标。浏览器使用现有 `/ws` 入口；状态变化可提前通知，定时检查补偿通知丢失和状态过期。每秒是采样及推送目标，不是已经测得的端到端延迟保证。

流量按原配置组成批次，默认 60 秒。批次先落盘，收到面板可靠接收确认后才清理；WebSocket 确认丢失、发送失败或超时，使用 HTTP 重发相同编号与内容。面板继续使用原批次表、队列、数据库事务和永久去重编号，接收确认不代表后台结算已经完成。补报流量不再附带旧的在线状态。

## 节点协议

握手中的 `realtime.version=1` 表示支持新协议；旧面板不声明能力时节点沿用旧报告路径。节点通过 `realtime/begin` 登记随机运行身份，面板返回运行代次 `epoch`。同一次运行的两种通道共用递增 `sequence`，重连不重置序号；缓存丢失后必须重新握手。

`runtime.state` 和 `machine.state` 是完整当前状态，`state.ack` 确认对应请求及版本。没有提供某种采样代表未知；提供空数组代表该采样已清空。35 秒没有有效状态时实时视图显示过期或未知，旧包和重复包不延长有效期。

`report.traffic` 对应 `traffic.ack`，请求编号和流量批次编号分别校验。HTTP 回退仍使用原报告入口，通过 `realtime=true` 只接收可靠批次数据。旧端兼容不意味着旧节点也具有秒级采样。

配置、用户和跨节点设备同步使用完整、有版本的快照。HTTP 迟到响应不覆盖新推送；用户空列表实际清空用户。设备 IP 变化通过 Redis 集合合并通知，广播标记由 WebSocket 进程展开为当前在线节点，再按各节点可用用户生成设备快照。

## 浏览器

管理员通过现有 HTTP 登录鉴权获取有效期 30 秒的一次性票据；票据放在 WebSocket 认证消息中。服务定期核查管理员权限与登录令牌，退出或令牌撤销后停止订阅。订阅仅包含可见用户、节点、机器和打开的 IP 详情，响应不发送完整账号或机器配置。

同一标签页共享一条连接。认证成功后仍保留 HTTP 兜底，收到完整状态才切回。断线立即同步，之后默认每 10 秒轮询；后台重连和重新发现入口，15 秒静默连接判为失效。切页、隐藏标签页及退出会撤销对应订阅，丢弃旧连接与旧请求回调。

HTTP 与 WebSocket 快照共用面板捕获版本；另以订阅编号、连接代次及帧序号隔离旧回调。完整快照允许跳号，无需重放已经过时的状态。实时状态单独覆盖展示字段，原列表请求仍负责首次加载、筛选、翻页和保存。节点排序期间暂停该页订阅，不改变拖动顺序。IP 详情只在 IP 集合变化时补充位置查询，位置结果缓存复用。

首页只接入队列运行状态，收入、订单、工单和历史曲线保持已有请求方式。开发代理同时转发 `/api` 和 `/ws`，生产沿用现有站点长连接入口。

## 验证与发布条件

本机验证包括 PHP/SQLite、Go 模拟通信、两种核心的现有测试、前端行为及浏览器测试。本机模拟结果不代表真实 Redis、Linux 常驻进程、跨机断线或端到端延迟已经通过。

本次经用户明确授权，通过 Netcatty 在 DGN-HK 运行 Docker 隔离测试面板，在 YT-HK 运行隔离 Node，并执行测试安装、启动和清理。真实联调完成前不发布，也不提供生产更新命令。保留此前已有用户管理修改与正式历史版本；最终发布来源、镜像摘要和附件校验值以兼容矩阵中的核验记录为准。真实故障与恢复结果见 [联调记录](realtime-acceptance.md)。
