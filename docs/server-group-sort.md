# 权限组排序与名称显示

权限组排序自面板 `1.18.0` 引入，与节点管理的“编辑排序”使用同一套交互和接口约定。固定发布来源、镜像和验证记录见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 使用方式

在“权限组管理”页面点击“编辑排序”进入排序模式：

- 列表切换为单页显示全部权限组，隐藏用户数、节点数和操作列，左侧出现拖拽手柄。
- 按住任意一行拖到目标位置松开即可调整顺序，顺序只保存在页面上。
- 点击“保存排序”把当前顺序一次性提交给面板，随后自动退出排序模式并重新拉取列表。
- 进入排序模式时会清空列头排序，避免列排序和拖拽结果互相覆盖。

排序值越小越靠前。新建的权限组排在末尾，升级前已有的权限组按升级前列表顺序写入排序值，升级后顺序不变。

组名较长时完整显示，不再截断。权限组列表在需要时横向滚动，`NoodSeek_Lite_Ultra` 一类的长名称可以完整读出。

## 跟随排序的位置

权限组顺序由面板统一提供，所有读取权限组列表的入口都跟随同一顺序：

- 权限组管理列表。
- 编辑节点时的权限组选择。
- 节点列表中每个节点显示的权限组标签。
- 套餐、用户等使用权限组选择的表单。

节点上已保存的权限组集合不变，只改变展示顺序；排序不影响节点可用性、订阅内容或用户权限判断。

自面板 `1.20.5` 起，节点列表的权限组标签只平铺前 3 个，其余折叠为“+N”按钮，避免权限组多时把行和窄屏卡片撑高；平铺的 3 个仍按上述统一顺序取前三。桌面端悬停“+N”展开全部组名，窄屏改为点按弹出，长组名仍完整显示。

## 接口与数据

- 新增 `POST /api/v2/<管理路径>/server/group/sort`，请求体为 `[{"id": 1, "order": 1}, ...]`，与节点排序 `server/manage/sort` 的参数形式一致，在同一事务中写入，失败整体回滚。
- `GET /api/v2/<管理路径>/server/group/fetch` 按排序值升序返回，排序值为空的排在最后，同序时按 `id` 倒序兜底。
- 数据库迁移 `2026_09_19_000002_add_sort_to_v2_server_group` 为 `v2_server_group` 增加可空的 `sort` 列并建立索引，同时把已有数据按升级前的显示顺序（`id` 倒序）回填为 `1..N`。
- 排序的唯一来源是 `ServerGroup::scopeOrderedForDisplay()`。新增读取权限组列表的代码应复用该作用域，避免出现第二套顺序。

## 验证记录

- 面板：PHP `8.4.21`、内存 SQLite 完整回归 235 项测试、3179 个断言通过，其中权限组排序 3 项测试覆盖新建追加到末尾、保存顺序后列表跟随、历史空排序回落末尾，以及节点读取权限组时的顺序一致。
- 管理前端：YZboard-Dash `0.3.0` 源码检查、12 项单元测试与开发模式冒烟通过；冒烟检查覆盖长组名不截断、拖拽后提交的顺序内容，以及保存后列表按新顺序刷新。
