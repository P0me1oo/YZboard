# 路由管理

路由管理定义“哪些流量做什么处理”，再选择要用这条路由的节点。节点程序（YZ-Agent）把路由翻译成 Xray 或 sing-box 的规则执行。

## 启用与停用

- 每条路由都可以在列表或编辑窗口中单独启用、停用，新建及升级前已有路由默认启用。
- 停用后保留全部匹配条件、动作和节点绑定，面板不再把这条路由下发给节点；重新启用后恢复下发。停用最后一条路由时，会明确下发空路由列表，清除节点之前收到的规则。
- 切换后立即向已连接的节点推送配置，其他节点在下次获取配置时生效。节点按照现有配置更新机制处理后续连接，开关不承诺终止已建立的连接。
- “新增节点默认应用”只决定新节点是否预选这条路由，与启用状态独立。停用时仍保留默认选择设置和新节点的绑定，但不执行；重新启用后按现有绑定生效。
- 列表开关只保存目标路由的启用状态，等待期间不能重复点击；保存失败保留原状态，可重试。

## 匹配条件

一条路由可以同时设置以下条件：

| 条件 | 说明 |
| --- | --- |
| 匹配值 | 每行一个域名或 IP 网段，例如 `example.com`、`1.1.1.0/24`，任一命中即可 |
| 协议 | 目前只有 BitTorrent，由节点内核识别 |
| 目标端口 | 单个端口或范围，逗号分隔，例如 `25,465,6881-6889` |
| 网络类型 | 不限、仅 TCP 或仅 UDP |

- 填了几种条件，就要几种条件同时满足才命中；同一种条件里的多个值，任一个对上即可。例如“目标端口 25 + 仅 TCP + 拦截”只拦截 TCP 的 25 端口，其他连接正常。
- 至少填写一种条件。只填协议、端口或网络类型而不填匹配值时，对所有目标地址生效。
- 已有路由升级后没有这些新条件，匹配结果不变。

## 快捷预设

面板 `2.25.0`、管理端 `0.107.0` 提供以下十项新预设，并保留原“屏蔽测速网站”。在添加路由中点击预设只填表，选好应用节点并确认保存后才下发；不自动选择节点。

| 预设 | 匹配范围 | 默认动作 |
| --- | --- | --- |
| 禁止 BT | 内核识别的 BitTorrent | 禁止访问 |
| 禁止大陆 IP | `geoip:cn`，包括域名解析后的目标 IP | 禁止访问 |
| 禁止内网 | `geoip:private`，包括域名解析后的目标 IP | 禁止访问 |
| OpenAI 直连 | `geosite:openai` | 本机直连 |
| RFC EMBY | `rfc.uhdnow.com` 及其子域名 | 转发，填写已有出口 |
| TikTok 解锁 | `geosite:tiktok` | 转发，填写已有出口 |
| AI 分流 | `geosite:category-ai-!cn` | 转发，填写已有出口 |
| Google/Meta 走 WARP | `geosite:google`、`geosite:meta` | 转发到 `warp` |
| 金融支付走 WARP | `geosite:category-finance`、`geosite:paypal`、`geosite:stripe` | 转发到 `warp` |
| 测速走 WARP | 与下方测速拦截相同的专用域名清单 | 转发到 `warp` |

预设替换匹配值、协议、动作与出口，并清空旧端口和网络条件；保留已有备注、应用节点、启用状态和“新增节点默认应用”。保存前可继续修改。RFC EMBY 入口依据[规则反馈](https://github.com/blackmatrix7/ios_rule_script/issues/1574)，仅包含该入口，不扩大到所有 Emby 服务；如服务入口变更，应按实际地址修改。

WARP 预设默认使用名为 `warp` 的**已有出口**；实际名称为 `warp-v4` 等时，修改转发标签。出口可来自节点的自定义出站、本地出站配置或自定义配置文件，必须在每个应用节点上存在，标签大小写一致。面板不会安装 WARP、创建 WireGuard、改系统路由或注册账户；Agent 发现出口不存在会拒绝配置，不自动回退直连。TikTok、AI、RFC EMBY 的出口留空，填写后才能保存；“解锁”效果取决于实际出口和服务限制。

OpenAI 直连与 AI 分流存在范围重叠，同一目标的非拦截规则按下发顺序先命中者生效。测速拦截和测速走 WARP 同时绑定时，拦截优先。大陆 IP 指目标地址，不是访问者来源；来源限制使用节点的独立设置。

## 两种核心共用分类

分类预设及入口拦截顺序需要 Agent `v2.44.0`。Xray 直接读取地理数据目录中的 `geosite.dat`、`geoip.dat`；sing-box 读取同一文件并转换为内联规则集，不再使用单独的 `.db` 分类库。支持域名包含、正则、域名后缀、精确域名、分类属性筛选（如 `geosite:类别@属性`）、IPv4/IPv6 网段和 IP 分类反选（如 `geoip:!cn`）。同一分类中的值为“或”，端口、协议和网络等附加条件仍须同时满足。

沿用 [Loyalsoldier 分类文件](https://github.com/Loyalsoldier/v2ray-rules-dat)的缺失时下载机制；已有文件不自动覆盖。多实例应使用同一个地理数据目录（配置项 `kernel.geo_data_dir`）。分类不存在、文件损坏或下载失败会使新配置应用失败，不静默跳过或扩大成全流量规则。更新数据后需重新应用配置；本次不增加定时下载或热更新分类文件的任务。

转换仅面向普通面板路由。sing-box 的高级结构化路由仍使用规则集或明确域名、网段；原生自定义配置按其内核格式编写。旧 Agent 的 sing-box 不支持这些普通面板分类引用，先升级 Agent 再绑定分类预设；回退前移除或改成明确域名、网段，并注意旧版本的中转优先级不同。

## 拦截与中转顺序

两核心均先执行面板“禁止访问”规则，再按线路转发到落地，随后执行普通直连／分流规则，入口自身线路的默认直连位于最后。面板拦截规则之间保留原顺序，非拦截规则之间也保留原顺序。

- 入口拦截同时作用于入口直出和经该入口中转的流量；落地仍执行自己绑定的规则。
- 带 IP 条件的入口拦截需要先在入口解析域名，才能检查解析后的 IP。没有 IP 拦截时，中转保留由落地解析目标域名的行为。
- Xray 的 Reality 防盗用规则、自定义高级／原生规则及已有内网保护保留各自优先级；高级自定义规则仍可显式覆盖普通面板规则。
- 普通直连和 WARP 分流不能改写已选定的中转线路出口。要让这类分流作用于中转流量，应把规则应用到落地。

## 屏蔽测速网站预设

在“路由管理 → 添加路由”中点击“屏蔽测速网站”，自动填入域名和“禁止访问”动作；备注为空时也会填入预设名称。选好要应用的节点后点击确认，才会保存和下发。预设不会自动选择全部节点。

预设包含以下测速专用域名及其子域名：

```text
fast.com
speedtest.net
speedtestcustom.com
ooklaserver.net
cdnst.net
speed.cloudflare.com
nperf.com
speedtest.cn
speedtest.tw
speedtest.org
speedof.me
testmy.net
openspeedtest.com
```

点击预设会替换匹配值、动作，并清空协议、端口、网络和动作参数，避免只拦截部分测速连接；已填备注、所选节点、启用状态和“新增节点默认应用”设置保留。之后可以继续增删域名，保存失败保留输入，保存后作为普通路由编辑、启停或删除。

域名清单参考 [v2fly 测速分类](https://github.com/v2fly/domain-list-community/blob/master/data/category-speedtest)、[Ookla 分类](https://github.com/v2fly/domain-list-community/blob/master/data/ookla-speedtest)和 [OpenSpeedTest 分类](https://github.com/v2fly/domain-list-community/blob/master/data/openspeedtest)，只保留专用测速域名，不包含 Netflix 视频域名或 Cloudflare 主站。清单随面板版本维护，不自动从网络更新。

这是域名拦截预设，不保证覆盖所有测速服务；未列出的自建测速服务器、直接 IP 连接或无法识别目标域名的连接可能不命中。需要新增服务时，按它实际使用的测速域名补充匹配值，不建议直接填写 `fast`、`speedtest` 之类的泛关键词。

配套面板 `2.20.0`、管理端 `0.102.0`，沿用现有路由接口和节点域名匹配，无需数据库迁移、Agent 或核心升级。

## BitTorrent 识别

- BT 使用内核自带的协议识别，不靠关键词或固定端口：Xray 识别 TCP 握手和 uTP 建连包，sing-box 另外识别 UDP Tracker。两种内核都识别不了加密的 BT 连接和 DHT。
- 只有绑定了 BT 路由的节点才开启识别。开启后，由服务器先发数据的连接（例如邮件）建立时最多多等约 0.2 秒（Xray）或 0.3 秒（sing-box）；普通网页、视频等由客户端先发数据的连接不受影响。
- Agent v2.44.0 起，入口绑定的 BT 拦截同时约束直出和中转；落地仍执行自己的路由，详见上方执行顺序。

## 选择节点

- 创建或编辑路由时可以多选节点，也可以一键全选或清空。保存时，新选中的节点加上这条路由，取消选中的节点去掉这条路由，节点上绑定的其他路由不受影响。
- 节点编辑页原有的路由多选继续可用，两边改的是同一份绑定关系。
- 删除路由时，这条路由会同时从所有节点上移除。
- 修改后，面板立即向在线节点推送新配置（包括隐藏但仍在运行的节点），其他节点在下次拉取配置时生效。

## 新增节点默认应用

- 路由上的“新增节点默认应用”开关打开后，新建节点时会预先选中这条路由，保存前可以去掉。新建路由时默认开启，可以手动关闭；已有路由升级后保持关闭。
- 通过接口新建节点而没有提交路由时，面板自动套用这些路由；提交了路由列表（包括空列表）时以提交值为准。
- 编辑已有节点、复制节点都不套用默认路由，复制节点沿用原节点的路由。

## DNS 动作

节点程序目前没有真正实现 DNS 动作：Xray 节点会直接拦截命中的域名，sing-box 节点上命中的连接会失败。管理端新建路由时不再提供 DNS 选项；已有的 DNS 路由原样保留，编辑时仍可保存。DNS 动作不能使用协议、端口或网络类型条件。

## 版本要求

路由启停开关需要面板 `1.72.0`、管理端 `0.45.0`。开关由面板过滤下发列表，不增加节点通信字段，无需为此升级 Node 或核心。回退到不支持开关的旧面板后，已绑定的停用路由会重新下发，回退前需确认这一差异。

需要面板 `1.26.0`、Node `v1.22.0` 和管理端 `0.9.0`。旧 Node 不认识新条件：只填新条件的路由会被整条跳过；同时填了匹配值的路由会被当成只按匹配值处理，范围变大。先升级全部 Node，再使用新条件。
