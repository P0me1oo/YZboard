# 多前置到固定落地的动态调度

适用：面板 2.16.0、管理端 0.98.0 起。维护者：P0me1oo。已随面板 2.16.2、管理端 0.98.1 发布并部署至 Solid-US LA，见[发布记录](release-2.16.2.md)。运营商 DNS 仍须先完成下述权威端准备；后文保留开发阶段验证记录。

## 动态负载分配

前置池新增“动态负载分配”。关闭时使用原有选择方式、优先级和权重；开启时在最高可用优先级内按负载分配，原选择方式和权重保留供关闭后恢复。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| 成员可用带宽 | 留空 | Mbps；填写实际可用于前置的容量，留空按节点活跃连接数调度 |
| 带宽利用率阈值 | 80% | 范围 10–100% |
| 活跃连接数阈值 | 1000 | 范围 1–10000000 |
| 持续确认时间 | 60 秒 | 范围 30–600 秒，同时至少需要三份新监测快照 |
| 改派冷却时间 | 300 秒 | 范围 60–3600 秒，每个用户、落地及运营商分配独立计时 |

带宽使用 Agent 节点 `inbound_speed`、`outbound_speed`（字节/秒）的较大值乘 8，再除以容量，避免将转发同一流量重复相加。这是节点代理流量速率，不是整机所有网卡业务总速率。未填带宽使用 `active_connections`。无需修改 Agent 上报格式或代理核心。

两类指标分别除以各自阈值，得到可比较的压力。例如带宽利用率 40% / 阈值 80%，与 500 个连接 / 阈值 1000 的压力均为 0.5。平滑比例为 0.3 新值加 0.7 旧值，只有新快照参与。新用户按剩余负载空间稳定分配；已有用户只有持续超阈值、其他成员压力至少低 0.15 且冷却结束才逐步转移。每池每 60 秒最多主动改派当前用户数的 10%（向上取整，至少一份分配）。

监测缺失、字段不完整或超过 120 秒时不补零：健康成员上的已有分配冻结，新分配回退到原权重；恢复数据后重新确认超载。心跳离线、停用、流量保护和链路故障仍执行故障转移，不受负载冷却和批次限制。DNS 写入成功后才确认分配、冷却与批次状态，失败保留上次结果。

阈值改变重置对应平滑与确认状态；关闭开关保留成员带宽及运营商配置。DNS 调度影响后续解析和连接，不能迁移已经建立的连接。

## 链路健康探测

一个开关统一面板到前置公网 IP/端口的 TCP 检查，以及各前置到该池每条固定落地的检查。开启需要所有前置至少运行 Agent v2.30.0。原延迟策略仍可选；开启链路探测后分别使用每条线路的实际落地，不再选一个影响全池的测速落地。

- 公网各 IPv4/IPv6 地址连续两次失败撤下、两次成功恢复，超时 2 秒。心跳中断、停用和地址失效打断恢复确认。
- 前置到落地按成员及落地节点独立保存状态。两份新失败报告后退出；恢复需两份成功报告且跨度达到 15 秒。重复同步同一报告不增加次数。
- 落地测量超过 90 秒不再新鲜；短暂缺测沿用此前状态，从最后测量或首次等待起超过 180 秒退出，恢复重新确认。更换落地地址/端口使旧结果失效。
- 先剔除不健康成员，再在该落地和运营商范围内应用额度、优先级及策略，保留实际可用的备用。
- WireGuard、KCP、Hysteria 等 UDP 内部链路沿用心跳及流量保护，显示“仅节点状态”。现有探测只能确认 TCP 建连，不能证明 UDP 或完整代理握手、认证和目标网站均正常。

新订阅按“用户 + 落地”派生固定 32 位域名标签，不随改派变化。两条落地可以使用不同前置；一条落地全部不可达时只撤下该线路解析并在订阅中暂时过滤它。原单个个人域名和池域名按所有启用线路共同可用的入口兜底；获得完整的落地隔离效果需要在启用后更新订阅。

已有落地主备继续选择自身实际目标，本功能检查其选中目标。线路编号、权限、计费和代理配置格式不变。DNS 每分钟同步，实际切换还受 TTL、否定缓存和客户端缓存影响。

## 运营商 DNS 分流

### 已核对能力和来源识别

2026-11-12 通过 Lite MCP 只读核对 Hytron-HK、学长-HK¹、Cloudnium-US、Aether-US：四台使用 `gsqlite3`，配置差异及区域元数据未启用 Lua。Hytron-HK 为 PowerDNS Authoritative 5.1.5，编译含 `lua`、`lua-records`，没有启用 GeoIP 后端。此方案使用 CIDR 匹配，无需付费 GeoIP 服务或 ASN 数据库。

权威 DNS 优先使用 ECS 转交的客户端网段，没有 ECS 时使用递归解析器源 IP，因此公共递归解析器未携带 ECS 时无法可靠识别用户本人运营商。ECS 不作权限凭据。ECS 前缀比匹配网段更宽、零长度、未知、非公网或同时命中多个运营商均走默认线路。

### 数据、默认线路与记录

网段库采用 MIT 许可的 [gaoyifan/china-operator-ip](https://github.com/gaoyifan/china-operator-ip)，按 BGP/ASN 路径分类，包含电信、联通、移动 IPv4/IPv6；并非运营商官方名单，覆盖与准确性以其公开算法为限。初始提交 `0ae37d32d44ff03cc38a7dac79e329f6bcb46855`，源数据日期为 2026-11-11 09:57:15 UTC。提交、六个源文件 SHA-256、生成与失效时间记录于 `resources/dns/carriers.json`，许可证在同目录。

使用 `python3 tools/update-carrier-ranges.py --revision <完整提交 SHA>` 显式更新固定版本。工具校验公网 CIDR、地址族及数量后原子替换文件，不直接改 DNS，不新增定时任务。有效期从源数据提交时间起计算 30 天，重复下载旧数据不续期。库缺失、无效或过期时同步默认 CNAME；已发布 Lua 本身也检查失效时间，缺少任一公共数据分片同样默认兜底。

成员可属于一个或多个运营商线路，开启至少需要一个默认成员。先在对应落地的健康成员中选择运营商线路，再应用额度、优先级和负载。没有对应运营商成员时选默认；默认也故障时使用其他健康成员；全部故障时撤销解析。

个人域名实际生成 `LUA CNAME`，指向该用户在对应运营商下已确认的成员。网段以区域内 `LUA LUA` 分片传送。`include` 按区域相对名称引用，TXT 分段只在完整 Lua 词法单元之间发生，兼容旧版插入空格及 5.x 直接拼接。沿用随机归属标记和 RRset PATCH，CNAME/Lua 切换同时清理旧类型，拒绝覆盖外部记录。

### 生产启用条件

本次没有修改生产 DNS。前端读取后端准备状态，未完成时显示原因并禁止启用，后端也拒绝首次开启。

另行授权生产操作后，需在四台权威统一启用 `enable-lua-records` 和 `edns-subnet-processing`，确认两个区域的 Lua 均能执行；不能假定区域 `ENABLE-LUA-RECORDS` 元数据会随 AXFR 同步。可以使用 `enable-lua-records=shared`，生成规则每次查询重置自身状态。提供区域传送的主权威还需设置 `workaround-11804=yes`，让 AXFR 每报文只含一条记录，避免默认每组 100 条较长 Lua 记录超过 65535 字节而传送失败；4.9.18 完整网段库测试已复现默认分组失败，5.1.5 源码保留相同分组开关。保留现有 TSIG 和 API 访问控制。

每台权威的 TCP/UDP、有/无 ECS、IPv4/IPv6、默认兜底及区域传送全部验证后，在面板环境设置 `POWERDNS_CARRIER_READY=true`，再从管理端开启并选择成员。`POWERDNS_CARRIER_RANGES` 可覆盖网段文件路径。此环境标志表示操作者已完成部署验证，不会自动配置或验证远端服务器。

参考：[PowerDNS Lua](https://doc.powerdns.com/authoritative/lua-records/index.html)、[查询来源和网段匹配](https://doc.powerdns.com/authoritative/lua-records/functions.html)、[数据来源说明](https://github.com/gaoyifan/china-operator-ip#readme)。
