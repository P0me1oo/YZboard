# 设备协调优化

维护者：P0me1oo。日期：2026-11-15。本文记录面板 2.16.9 的实现与验证；配套管理端保持 0.98.5，无需 Agent 或核心更新。正式发布与生产更新另行记录。

## 依据与范围

[生产排查](device-lock-diagnosis-20261115.md)确认每秒同步仍会竞争节点锁和实际关联账号的锁，同时发现无关账号的重复解码、只判断资格却读取完整用户字段等开销。当前资源采样没有证明硬件不足，本次在保留协调规则的前提下减少锁内工作，并区分预期退让与真实失败。

修改设备许可同步、设备协调服务与协议入口、账号状态解码器及资格查询。没有修改数据库结构、Redis 持久记录格式、许可期限、同步频率、重试预算或 HTTP/WebSocket 协议。

## 实现

- 设备同步使用账号编号集合判断资格，普通查询只选择编号；流量、到期、封禁、权限组、中转线路和机器流量限制沿用原条件。WireGuard 资格查询不派生用户密钥。存在用户过滤插件时，仍调用原完整名单路径，保留字段、处理顺序和过滤结果。
- 关联筛选继续最多 256 个账号一批，从 Redis 批量读取最新原值。与账号锁内单读共用解码备忘，只有原值完全相同时才复用数组；修改、删除、重建和损坏立即可见，不使用时间缓存代替当前权威读取。
- 解码备忘最多 128 条、合计最多 4 MiB 原始序列化数据，最低记录大小从 4 KiB 调整为 512 字节，使较小的共享账号也可复用。PHP 解码数组另有运行时开销，4 MiB 不代表进程总内存上限。自定义缓存、客户端序列化与压缩继续使用框架原路径，缓存事件与读取诊断保持。
- 完整同步复用同一节点锁内已读取、校验的节点快照，先合并最新轻量续期进度，再保存较新的完整快照。减少一次节点完整记录读取与解码，旧序号不能覆盖新状态。
- 支持快速退让的请求在锁占用时仍立即返回 503，日志按调试级别限频记录；旧节点等待超时继续记录警告。Agent 的八秒预算、同业务内容重试和最终失败日志保持。

## 正确性验证

PHP 8.4.27、PHPUnit 11.5.57，使用任务专用临时目录中的 Redis 8.0.2、phpredis 6.2.0 和 MariaDB 11.8.6。服务只监听本机，测试配置缓存、存储、数据库、前缀和多进程临时文件独立；没有连接生产数据库或向生产注入故障。MariaDB 开启 `ONLY_FULL_GROUP_BY`。

相关范围包括设备换网、许可与解码、并发准入、故障日志、机器流量、中转、节点控制和 WireGuard。命令通过任务环境执行：

```bash
php vendor/bin/phpunit --do-not-cache-result \
  --filter 'Device(Handover|Lease|Available|Coordination)|FailureLogging|MachineTraffic|ServerRelay|NodeControlStateService|WireGuard'
```

MariaDB 使用项目的 `tests/bootstrap-mariadb.php` 引导入口；两个数据库环境均设置专用 Redis 的两项测试端口变量。

| 环境 | 用例 | 断言 | 结果 |
| --- | ---: | ---: | --- |
| SQLite 内存 + Redis | 269 | 5,509 | 268 通过，1 项 MariaDB 行锁专用检查按条件跳过 |
| MariaDB + Redis | 269 | 5,517 | 全部通过，无跳过 |

验证覆盖编号查询的资格规则与插件完整资料、WireGuard 资格不生成身份、批读与单读复用和数组隔离、同长度状态修改、删除重建、损坏与不完整响应失败、自定义缓存与序列化回退、事件与诊断计数、轻量续期后的旧完整快照、缺失队列恢复、同序号重试、撤销、写入失败和真实 Redis 八进程准入。

修改的 PHP 文件语法检查与 `git diff --check` 通过。按项目现有 PHPStan 5 级配置检查五份服务文件，并对优化前原文件比较：基线 12 项、当前 11 项，无新增告警。保留的告警涉及框架锁接口缺少链式方法声明、模型动态属性，静态检查整体没有计为通过。

## 隔离性能对比

优化前五份服务文件来自提交 `fb005c0c9eb5c971d4db34a2ff5a56d47adc237d`，优化后使用当前工作区文件；同一 PHP、Redis 和内存 SQLite 环境运行，未运行其他本任务测试。每项先预热 20 次，优化前后顺序执行三组，取中位数。

模拟 33 个账号，每个账号有 2 个来源、5 个其他节点持有许可，单次批读原始数据为 130,629 字节。账号状态在本项测量期间不变；测量为空闲节点筛选无关账号的场景，既包含完整同步，也单独测量批量预读。不能将结果推导为生产整机 CPU 降幅或所有请求的改善比例。

| 场景 | 测量次数 | 原总耗时 | 优化后总耗时 | 耗时下降 | PHP CPU 时间下降 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 账号状态批量预读 | 500 | 132.738 ms | 63.712 ms | 52.0% | 63.4% |
| 普通空节点完整同步 | 150 | 214.570 ms | 175.207 ms | 18.3% | 22.2% |
| WireGuard 空节点完整同步 | 150 | 366.401 ms | 177.869 ms | 51.5% | 57.5% |

表中是固定次数的总耗时，不是单次请求延迟。每批仍访问 Redis；主要减少用户字段处理、重复解码、一次节点读取及额外的 WireGuard 密钥派生。

完整三组数据、验证计数及源码摘要见[结构化验证](device-coordination-optimization-20261115.json)。实际生产收益和间歇通信超时是否改善，需要部署授权后再观测。

实现阶段仅修改本地源码、测试、版本与相关文档，没有执行发布、部署、节点升级或系统配置修改。该阶段临时服务与文件已清理，保留工作区原有的其他修改。后续正式发布与生产更新采用独立记录。
