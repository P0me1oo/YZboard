# 前置 DNS 调度

新建池使用单台自建 PowerDNS Authoritative，通过 API 管理解析；后端需支持 RRset comments，例如 gsqlite3 或 gmysql。连接路径为“用户 → 前置成员 → 落地”，PowerDNS 仅提供 DNS 答复，不承载代理转发。已有的旧转发池保留兼容，转换方式见下方。

## 配置与分配

1. 准备 PowerDNS 区域和 API，在“前置 DNS 调度 → DNS 配置”填写区域名称、API 基础地址、服务器 ID（通常为 `localhost`）和 API Key。基础地址不含 `/api/v1`、认证信息或查询参数；编辑密钥留空保留原值，密钥加密保存且不回显。多个区域共用同一台 PowerDNS 的 API 地址及服务器 ID。
2. 新建前置池，选择 PowerDNS 配置并填写池域名。可以直接使用委托区域的根名称，例如 `pool.example.com`；也可以使用区域内的子域名。每台服务器选择一个 VLESS Reality + TCP 前置模板，服务器需运行 Agent v2.25.0 或更新版本。
3. 面板创建各前置的池专用实例，使用共同的空闲端口并复制首个模板的协议与密钥。原直连节点不变。池列表显示用户实际连接的域名和端口；前置公网端口需可从用户及面板访问，端口自动放行沿用前置节点设置。
4. 落地节点选择对应前置池。用户订阅使用池域名和成员端口。DNS 模式不创建调度入口实例，也不启用旧入口所需的 PROXY 协议接收。

优先级数字越小越优先。面板每 60 秒执行 `balancer:sync`，按池成员实例自身的心跳、机器启用与流量保护状态筛选，再并发检查实际 IP 的 TCP 成员端口。检查在后台完成，用户建立连接时不等待这一轮探测；手动同步 DNS 也会立即检查。仅发布最高可用优先级的全部地址；该级无可用地址时自动使用下一优先级。同级多个地址由 DNS 和客户端选择，不保证均匀会话数量。IPv4 和 IPv6 分别检查，失败的地址族不发布。

心跳离线阈值在全局设置中配置，默认 180 秒。开启服务器流量限额后，有效计量上报满 180 秒未更新才因上报中断进入保护，用量为零或没有增长的有效新报告照常续期；明确超限、计量异常和手动停用仍立即阻止参与调度。端口连接超时为 5 秒。故障成员不再出现在新答复中；全部不可用时撤销本功能托管的池 A/AAAA 与个人 CNAME，恢复后重新加入。健康检查不受 DDNS 或用户状态跟随开关影响。API 同步失败在列表显示错误，下一轮重试；不会改写其他用途的解析。

TTL 每池独立配置，范围 30–86400 秒，默认 60 秒。切换还受定时检测、递归 DNS 和客户端缓存影响，不能迁移已建立的连接；从无记录恢复时还受区域 SOA 的否定缓存时间影响。单台 PowerDNS 不可用时，解析和同步依赖已有缓存，面板不能通过故障 API 撤销旧答复。

## 三个独立开关

| 开关 | 默认 | 生效范围 |
| --- | --- | --- |
| DDNS | 关闭 | 仅负责成员 IP 变化后的同步。关闭时保留首次配置或最后一次同步的地址，健康检查照常剔除或加入这些地址 |
| 用户独立域名 | 关闭 | 关闭时所有用户共用池域名；开启时每名用户使用固定随机标识的四级域名 |
| 跟随用户状态 | 关闭 | 独立域名开启后，可显式选择按封禁、到期、流量耗尽撤销个人解析，资格恢复后恢复同一名称；DDNS 不会自动开启它 |

开启独立域名时，池域名必须有三级，例如 `pool.example.com`。个人域名为 `固定随机标识.pool.example.com`，CNAME 指向池域名；发生前置切换不改变用户名称。关闭独立域名会改为下发池域名并撤销个人解析，但保留随机标识，重新开启仍使用原名称。权限组授权仍决定哪些用户可以获得该池的解析；“跟随用户状态”只控制额外的账号状态撤销，不替代节点认证或订阅权限检查。

成员地址优先采用服务器上报的有效公网 IPv4/IPv6，无有效上报时使用模板节点手填 IP。DDNS 关闭时不追踪后续 IP 变更。各前置须可通过记录中的 IP 与池端口直达；DNS 不能为同一域名按 IP 指定不同的 TCP 端口，不应把只有不同 NAT 映射端口的入口放入同一池。

## 从 Cloudflare 委托子域

以 Cloudflare 管理 `example.com`、委托 `pool.example.com` 为例：

1. 为 PowerDNS 准备一个可公开解析的 NS 主机名，例如 `ns1.example.com`，A/AAAA 指向该服务器 DNS 地址，Cloudflare 中设置为仅 DNS。使用委托范围之外的 NS 名称可避免子域内 NS 的胶水记录依赖。
2. 在 PowerDNS 创建 `pool.example.com.` 区域，配置对应 SOA 与 `ns1.example.com.` NS，并开放面向解析器的 UDP/TCP 53。API 通过受保护的管理地址供面板访问，不对用户暴露 API Key。
3. 在 Cloudflare 父区域添加名称 `pool`、内容 `ns1.example.com` 的 NS 委托。处理该名称原有冲突的 A/AAAA/CNAME；PowerDNS 内保留区域根部 NS/SOA。面板不会自动改写父区委托，也不会安装或重启 PowerDNS。
4. 在面板中添加 PowerDNS 配置，区域填 `pool.example.com`；池域名同样填 `pool.example.com`。由 PowerDNS 管理池 A/AAAA 和用户四级 CNAME，Cloudflare 只保存 NS 主机地址及委托，不保存每名用户的记录。
5. 用 `dig NS pool.example.com`、`dig @<PowerDNS地址> pool.example.com A`、`dig +trace pool.example.com` 检查权威答复、委托和最终解析。若启用 DNSSEC，父区 DS 与子区签名须配套；否定缓存 TTL 建议配合故障恢复要求设置。

API 采用官方的区域 RRset `GET` / `PATCH`，名称使用完整域名，以 `REPLACE` / `DELETE` 更新。每组记录先持久化随机归属标记，再写入 PowerDNS comments；请求响应丢失时按同一标记恢复，不重复建记录、不认领外部记录。域名冲突、归属变化、覆盖范围内的泛解析或下级 NS 委托会阻止写入。区域根部 NS/SOA 始终保留。

参考：[PowerDNS 区域 API](https://doc.powerdns.com/authoritative/http-api/zone.html)、[PowerDNS HTTP API](https://doc.powerdns.com/authoritative/http-api/index.html)。

## 旧方案兼容与转换

升级迁移不会自动切断旧转发池。已有池标记为“旧转发模式”，继续使用原调度服务器、原端口及 Cloudflare 托管记录；旧 API 带调度服务器参数的新建请求仍按旧模式处理。管理端新建统一使用 DNS 模式。

转换前准备 PowerDNS 委托及前置成员端口，依次执行：

1. 在列表停用旧池，执行“同步 DNS”清理旧池记录。
2. 如有旧池 DDNS，分别关闭其 DDNS 和独立域名，再到 DDNS 设置中清理旧解析，等待绑定完成清理；保留旧名称的退休绑定也需清理后再更换用途。
3. 编辑池，将调度方式改为 DNS，选择 PowerDNS 配置并保存。原模板、池成员实例与落地引用保留；旧调度入口实例删除并通知原机器更新节点列表。新连接端口使用原成员端口。
4. 启用池，确认成员心跳、端口和 DNS 同步正常，再让客户端更新订阅。原调度入口端口不会继续转发。

DNS 池不能改回旧转发模式；需要旧方式时另建兼容配置。更换池域名或 PowerDNS 预设前，同样需停用并同步清理已有托管记录。删除池需先解除落地引用并完成 DNS 清理。数据库回退在仍存在 DNS 池、PowerDNS 配置或托管记录时拒绝执行，避免遗失记录归属。
