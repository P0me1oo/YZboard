# 统计分析

## 入站 IP 完整属性补查（1.77.1，未发布）

后台网页查询改为读取 `https://www.ip2location.com/<IP>` 内公开展示的 JSON。该页提供对应地址的网络类型，以及 VPN、Tor、数据中心、各类代理、垃圾邮件、扫描、僵尸网络、非法地址和爬虫的独立判断。只接受明确的布尔值：`true` 显示“是”，`false` 显示“否”；缺失、占位或错误类型仍显示“无法查询”。代理类型和威胁分类为 `-` 时，不单独据此推测各项结果。

读取前核对 JSON 中的地址与查询目标一致，兼容完整和压缩格式的 IPv6；官网请求路径保留 IPv6 冒号，地址先经过规范化公网校验。响应必须包含唯一的结果区块，错误地址、重复区块、损坏 JSON、跳转页和访问拦截页按原失败重试处理。只解析 HTML 内的数据，不启动浏览器、不执行脚本，也不增加付费接口配置。IPv4 归属地、省份分类、原 ASN 与接口缓存及在线设备、Telegram 的数据来源沿用原规则；管理端属性卡片直接展示保存结果。

新增迁移只将旧摘要结果的有效期和补查时间归零，保留原网页内容、地区、ASN 和历史出现时间；即使旧网络类型已知，其细分检测项也重新补齐。带完整来源标记的结果不重复失效，写入时核对读取快照，避免覆盖迁移期间新保存的结果。迁移本身不请求外网，原每分钟任务按每批最多 32 个、四个并发和每日 1,000 次上限逐步补查；全局退避和每日计数继续有效。入站网页使用新的缓存版本，不复用旧摘要，也不清空在线设备共享缓存。

沿用管理端 `0.49.0`，无需更新 Node 或核心。回滚面板可保留迁移及缓存列，旧程序忽略完整来源标记；回退本次迁移不恢复旧摘要的有效期、不删除数据。版本及验证范围见[兼容矩阵](../YZ_COMPATIBILITY.md)。

## 节点用量与服务器代理流量（1.77.0，已发布）

配套管理端 `0.49.0`。两类统计均使用代理程序上报的原始上传加下载，不乘计费倍率：

- **节点用量**按用户实际使用的线路归属。直出计入入口节点，中转只计入落地节点，入口不再重复累计这部分用量。
- **服务器代理流量**包含绑定在本机的直出、前置转发和落地承载量。前置和落地绑定到同一服务器时只计一次；跨服务器时分别记录。它不是新节点用量的简单相加，也不包含网卡计数或其他程序的流量。未绑定服务器的节点不猜测服务器归属。

例如直出 A 使用 1 GB，经 A→B 使用 4 GB：

| 统计对象 | 用量 |
| --- | --- |
| 节点 A | 1 GB |
| 节点 B | 4 GB |
| 服务器 A（A、B 异机） | 5 GB |
| 服务器 B（A、B 异机） | 4 GB |
| A、B 同机所在的服务器 | 5 GB |

节点管理同时展示“节点用量”和“承载量 / 上限”；服务器管理新增“服务器代理流量”。流量统计增加服务器页签，节点页签可选择新用量或“旧口径”。旧口径继续分别累计入口及落地承载量，用于核对历史和节点流量上限；用户套餐扣费、节点上限和重置规则沿用原处理方式。

新增统计表及累计值，新口径从升级迁移完成后收到的上报开始。旧记录和升级前已接收的排队批次保留原口径，不重算缺少完整机器归属的历史数据。两类新累计值不随原节点“重置流量”归零，复制节点的新用量从零开始。趋势和排行按面板时区查询最近 30 天，分钟记录仅保留今天；启用前的时间不补造数据。

接收上报时保存节点、机器归属，后续改绑或删除不搬移旧批次；结算失败整体回滚，批次重复处理不重复累计。入口与中转独立采样的差值按有符号数保存，汇总后再显示非负值，避免逐批截断产生虚假直出；短时采样未齐时仍需等待后续上报校正。复用现有 Node 上报，不增加通信字段或核心修改。

## 入站 IP 网页补查（1.73.0，已发布）

`1.73.0` 初版使用原有每分钟后台任务分批读取 `https://www.ip2location.io/<IP>` 的公开 HTML，补充页面明确展示的运营商、网络类型、ASN、网络名称和代理摘要；`1.77.1` 改为上节的完整属性查询。直接使用 HTTP 请求和 HTML 解析，不启动浏览器，也不执行网页脚本。列表、明细和属性卡片读取数据库中已保存的结果，不在点击时请求网页。

网页结果与原免密钥接口分别存储。网页提供的运营商、网络类型和代理判断补充到入站属性，ASN 和网络名称在原接口结果不可用时由网页补充；IPv4 纯真归属地、IPv6 地区及省份分类沿用原规则。初版仅把摘要明确列出的代理类型和威胁分类标记为“是”，其他项目保留接口已有的明确结果或显示“无法查询”；完整属性查询改为读取每项明确的布尔值。均不以空值、欺诈评分或总代理判断推断细分检测为“否”。只补充现有卡片支持的字段，不新增欺诈评分等展示项。

每批最多 32 个地址、四个网页并发，连接最长两秒、请求最长五秒，单个 HTML 最多 256 KiB；只查询规范化公网 IP，不跟随跳转。成功结果缓存和存储 30 天，普通失败按 IP 五分钟后重试，同一 IP 正在查询时不重复请求。网页查询使用独立的每 UTC 日期 1,000 次内部上限，不占用免密钥 API 的次数；明确限流时仅暂停网页查询，至少等待五分钟，并尊重服务返回的更长重试时间，最长一天。普通失败不触发全局暂停，也不清空原 ASN、网络名称或归属地。日志只记录失败类别和数量，不记录完整网页或认证信息。

新增迁移只增加网页结果、有效期和下次补查时间，原接口缓存不换格式，旧 IP 按原任务顺序逐步补齐；网站结果写入数据库后，即使内存缓存清空也不会重复下载有效页面。网页结构变化或无法访问时保留原接口结果。用户管理在线设备、Telegram 提醒和统计等共用接口的场景不发起网页请求；入站网页数据也不写回它们使用的共享缓存。

沿用管理端 `0.45.0`，无需修改管理端、Node 或代理核心。回滚面板可以保留新增列，旧代码忽略网页缓存；回退迁移只删除网页列和对应索引，不删除原 IP、ASN 或历史时间。正式发布及固定来源见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 中转独立倍率（1.71.2）

独立倍率由节点编辑中的开关控制，默认仍跟随前置。新批次保存首次接收时的入口倍率与独立线路倍率，用户扣费、按倍率的日汇总和用户线路明细使用同一份分配结果；修改倍率、改绑或失败重试不改变历史扣费。节点统计继续保留入口及落地各自的完整承载量。

节点基础倍率和日计费汇总的倍率存储精度扩大为 8 位小数，避免 MariaDB 将不同小数倍率合并为两位精度。已有汇总的上下行和已扣量不变，回退迁移时保留较宽精度。

包含独立倍率的新批次按入口用户总量分配直出及中转用量。采样合计超过入口时按比例分配，不增加可计费流量；相同倍率累计取整。其线路记录类型为 `direct` / `transit`，保留当时生效倍率及已扣量；旧批次继续使用 `entry` / `relay` 原始采样及原归属逻辑，不回填、不重算。新旧记录均参与排行、筛选、日 / 小时 / 分钟明细和合计，前端仍显示“直出 / 中转”。回滚旧面板前须评估新记录的展示兼容性。

## IP 属性卡片（1.69.0，未发布）

配套管理端 `0.42.0`。入站 IP 明细按“IP 地址、归属地、运营商、网络类型、首次出现、最近出现”排列；运营商仅显示名称，不带 AS 编号。名称优先使用外部接口提供的运营商，缺失时使用本地运营商信息，再回退到网络名称，仍缺失时显示“未知”。运营商旁提供 Lucide 信息图标，点击查看当前 IP 的纯白卡片；ASN 未知时仍可打开。支持键盘、关闭按钮、点击外部关闭和手机点按。网络类型、归属地、ASN 和网络名称位于上方，代理检测及风险、爬虫检测分别列出。不同省份采用统一列宽，长 IPv6 和网络名称换行。

IP 地址及已有外部位置链接均跳转到 `https://www.ip2location.io/<IP>`，IPv6 按完整地址编码；用户管理的在线设备地址链接使用相同规则。

网络类型仅使用 [IP2Location 官方分类](https://www.ip2location.io/ip2location-documentation) 中的地址用途，不用 ASN 或网络名称推断住宅属性。“ISP”显示固定宽带，“MOB”显示移动网络，“ISP/MOB”显示固定 / 移动网络，“DCH”显示数据中心。代理、VPN、Tor、各类代理、扫描、僵尸网络及爬虫等只接受接口明确返回的布尔值；缺失、占位和类型错误均显示“无法查询”。不以总代理标记推断 VPN 或其他细分结果，也不把所有检测为“否”解释成绝对安全。

免密钥响应不保证提供网络类型和细分风险字段，网站展示的数据也不等于当前 API 可以返回的数据。自 `1.73.0` 起，入站 IP 按上节规则由后台补查公开网页；用户在线设备等场景继续使用免密钥 API。未被当前数据来源明确提供的内容仍显示“无法查询”，不增加付费配置。

新增属性随有效位置缓存 30 天，包括接口未提供的属性；位置失败或无有效位置时缓存五分钟，沿用每日 1,000 次、并发八个、限流退避和每批最多 32 个地址的处理。共享位置缓存升级到新格式，旧缓存不会误装成完整属性；入站数据库保存属性后，即使内存缓存清空也可恢复，属性到期时不展示旧判断。列表读取已保存结果，点击卡片不单独请求外部服务。

新增迁移仅增加属性存储列并让旧记录进入待查询队列；原地区、ASN、历史 IP 和出现时间保留，之后由原分批查询补齐。回滚迁移只删除属性列，不删除入站历史。面板和管理端需要配套交付，无需升级 Node 或核心。

### 地区与 ASN

- IPv4 地区使用随源码和镜像交付的 [纯真 `20260930` 数据库](../resources/ip/README.md)，不在运行时跟随最新下载。归属地和省份从库中的中文地区解析；纯真不提供 ASN，不从运营商文字猜测 ASN。
- ASN 与 IPv6 地区复用 IP2Location.io；成功的完整查询结果按 IP 缓存 30 天。共享查询缓存由此前七天延长到 30 天，因此用户管理的在线设备查询也使用新期限。失败或缺少位置信息的结果仍短暂缓存五分钟，不把失败固定保留 30 天。
- 外部查询沿用连接一秒、请求两秒、最多八个并发及每个 UTC 日最多 1,000 次的全局额度。额度与在线设备详情共用，额度耗尽、网络失败或未知位置时显示“未知”，IPv4 仍显示纯真结果。IPv6 省份按服务明确返回的省级地区分类，不能识别时归“未知”。位置为数据库标注，不保证是用户的实际物理位置。
- 新增地址资料表 `v2_inbound_ip`，由每分钟 `inbound-ip:refresh` 分批补齐；查看用户明细也会补齐最多 32 个到期的外部查询。本地 IPv4 分类在分页前分批完成，因此省份筛选不依赖先浏览全部页面。尚未查询到的 IPv6 归“未知”，后续查询成功会更新分类。
- 外部查询不在节点上报路径中执行。ASN 或 IPv6 位置文字保留 IP2Location.io 来源链接；IPv4 位置不被外部地区覆盖。

## 1.50.0 当前统计规则

配套管理端 `0.27.0`，Node 沿用 `v2.5.0`。节点管理的累计流量与节点额度判断保持原样；套餐仍按入口用户上传、下载乘入口当时生效的倍率扣除。

| 位置 | 当前依据 |
| --- | --- |
| 节点管理、概览节点排行 | 前置包含直出和中转，落地记录各自承载量 |
| 概览总量和趋势 | 所有节点的日统计相加，包含前置和落地；不等于用户实际用量 |
| 用户实际流量及明细 | 中转归到落地，前置只保留该用户的直出；纯中转不再显示一份前置流量 |
| 用户扣费排行及明细合计 | 保存实际结算量，不用查询时的倍率反推；新排行与明细使用同一升级后记录范围 |
| 用户节点明细 | 始终显示实际上传、下载和总量；非 1 倍同时显示生效倍率与归属扣除量，1 倍不附加这两项 |

例如前置直出 1 GB、经过前置到落地 4 GB：节点管理为前置 5 GB、落地 4 GB，概览合计 9 GB；用户明细为前置直出 1 GB、落地 4 GB，用户实际合计 5 GB。前置 2 倍时合计扣 10 GB。落地自己的倍率不参与扣费。用户详情保留实际量、扣费量两个合计；明细不再切换成仅显示扣费量。

### 记录和扣费归属

新增 `v2_stat_user_route_source` 保存用户、上报入口、节点、日期、结算倍率、入口原始量与实际结算量，以及同批的用户落地明细。入口总量与落地明细先按同一用户、入口、日期、倍率汇总，再从入口扣掉已归属落地的上下行量；不能先按界面选中的节点筛选，也不能逐批将负差值截为零。节点重新绑定前置后不会改变原有记录。

入口和线路计数不是同一时刻读取，短时可能有采样差异。负的直出差值按零展示，原始累计值保留，后续上报可继续对齐，不累计逐批截断产生的虚假直出。用户落地明细使用用户线路上报，不使用可能包含封装开销的落地节点总计数。跨日期或倍率边界的采样差异无法从旧上报精确追溯到单个字节。

节点明细的扣除量是**已实际扣费的归属分配**：在同一用户、入口、日期、结算倍率内，按各线路的上传、下载占比分别分配该方向已扣量，用整数运算固定取整余量；所有线路的扣除量之和严格等于已结算量。这只是展示归属，不再次扣费。流量来源有采样差异时，不保证某一行的实际量乘倍率恰好等于分配量。不同倍率分别成行，按周、月汇总也不合并成虚构的单一倍率。

新增 `v2_stat_node_hour` 汇总所有节点的小时用量，与节点日统计同事务写入。可靠上报使用首次接收时间，失败回滚、重试去重，跨天处理保留原日期；旧接口任务入队时保存时间，没有接收时间的旧任务不补造小时记录。小时与日汇总不一致时，单日趋势回退为日汇总，升级当天可能回退。

### 升级与历史

新用户归属统计从迁移启用后接收的报告开始，入口和落地旧记录不回填，新接口不推算旧线路倍率或扣费。升级前已接收的延迟批次仍正常扣费并保留旧统计，但不混入新用户归属记录；用户套餐已用量不清零。概览可直接复用已存在的节点日统计，旧入口小时表保留但不冒充全节点小时统计。

新表沿用 30 个自然日保留范围，清理时保留仍被新明细引用的已删除节点名称。普通旧接口继续记录直出；中转明细需要配套 Node 已有的用户线路上报。没有更改 Node 通信格式或核心。回退可保留新增表，不回滚删除数据；旧版本运行期间没有新归属记录，恢复新版后不补算该段明细。

| 用户扣费流量排行 | 现有用户日统计，包含当时的计费倍率 |
| 用户节点明细的扣费流量 | 保存结算时的值；倍率变化后不按新倍率反推历史 |
| 节点排行 | 现有节点日统计，每个节点各自的用量；入口和落地均可出现，不能相加当作用户总量 |
| 用户的中转落地明细 | 现有用户线路上报，只显示原始用量；没有独立扣费量，扣费列显示「—」 |

上传、下载方向沿用现有 Node 上报。数据是代理上报的流量，不是网卡总流量。不同核心的中转计数位置可能不同，入口、落地数值不保证相等，详见 [中转节点](relay-nodes.md)。用户入口合计和落地合计分开显示。

## 历史与保留

旧用户统计只保留用户、倍率和日期，不能可靠反推出用户在各节点的原始流量，零倍率数据尤其无法还原。因此不自动回填新明细。

实际用户流量、总趋势和用户节点明细从新功能启用后记录。`1.48.1` 起页面不再显示开始记录提示；趋势仍不会把启用前的日期补成零。只有一天记录时，按天趋势只有一个点。升级前已接收但尚未结算的报告可能迟到，按报告原日期保存实际收集到的部分数据。节点排行和扣费流量排行可复用仍在保留期内的旧日统计。升级当天的实际记录是部分数据，不能与整天历史扣费记录直接对账。

每日清理保留今天及此前 29 个自然日，包括旧用户日统计、节点日统计和新增用户节点明细。**这会将原来两个月的保留范围缩短为 30 天**；清理后的历史不能通过回退代码恢复。用户套餐已用流量、节点累计计数、上报去重编号不在此次清理范围内。

`1.48.1` 起，管理员单个或批量删除节点时保存删除前最后使用的名称，排行、用户节点明细和节点筛选统一显示「原名（已删除）」。在此之前已删除且没有留下原名的节点，不再显示对应节点行或筛选项；过滤在分页前完成。隐藏不等于删除流量记录，总趋势、用户排行和用户流量合计仍保留实际已经发生的用量。停用、隐藏但尚未删除的节点仍显示当前名称。已删除用户继续显示用户编号。

名称记录只包含节点编号、名称和删除时间，不保存节点配置。删除失败时名称记录一并回滚，重复删除不会刷新原删除时间。名称超过 30 天且已无剩余节点统计或用户节点明细引用后，由每日清理任务移除。

## 记录与兼容

新增日统计表为 `v2_stat_user_server`，以用户、节点、统计位置和日期唯一标识一条记录，保存原始上传、下载及结算后的扣费值。开始时间保存在设置项 `traffic_statistics_started_at`。两者由新增迁移创建，不修改已有套餐扣费算法。

可靠上报由 `ProcessNodeReportBatch` 在同一事务中更新旧汇总、新明细和批次状态。批次重试不会重复累加，任一步失败整体回滚。旧版上报的 `StatUserJob` 也记录入口明细；旧接口没有报告编号时，仍无法跨网络重试去重，这是原接口限制。

继续使用现有 Node 的流量与用户落地上报，无通信格式、核心依赖或 Node 版本变更。正常发布时需要同时纳入前端源码构建与面板后端迁移，仅运行管理端构建不会部署后端。

管理员接口位于 `/api/v2/<管理路径>/statistics/`：`traffic`、`nodes`、`users`、`user`、`searchUsers`，沿用管理员认证。所有范围、分组、页码和筛选均由后端校验，日期查询限制在保留范围内。

已随 [面板 v1.48.0](https://github.com/P0me1oo/YZboard/releases/tag/v1.48.0) 正式发布，配套管理端 `0.25.0`，Node 沿用 `v2.5.0`。双架构镜像和 `latest` 已核验可获取；只需更新面板，更新前备份数据库。验证结果和固定产物来源见 [兼容矩阵](../YZ_COMPATIBILITY.md)。
