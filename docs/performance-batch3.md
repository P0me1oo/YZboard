# 第三批性能优化

本批只优化查询和维护任务的资源使用，不新增历史存储层，不改变现有保留周期、计费账目、批次防重记录或统计口径。

## 统计查询

- 节点和机器排行、长范围趋势直接使用已有日汇总。短范围趋势在需要细分数据时，用一次按日期和实体的细分/日汇总核对；迟到数据不一致时，完整日期回退到日汇总，日内边界仍使用可用的小时或分钟数据。
- 趋势点通过连续时间桶合并，上传和下载按桶求和，迟到扣减先按原逻辑处理后再合并。接口接受 `max_points`，范围为 1–1000，默认 1000。
- 统计页面、旧排行和机器历史共用两个重查询槽。等待超过 0.5 秒返回 429，不缓存结果；MariaDB/MySQL 查询会设置 5 秒会话上限（支持的变量按数据库类型选择）。机器历史最多返回 500 点，分桶时保留原字段的平均值，并增加对应的 `_avg` 与 `_peak` 字段。
- 用户明细的节点名称查询只保留当前结果涉及的节点，避免扫描用户全部线路历史；统计结果、权限和筛选条件不跨请求复用。

## 导出和维护

- 用户 CSV 按用户主键每批 500 条读取；礼品卡文本导出按创建时间和主键游标每批 500 条读取。导出完整结果，读取或写出失败会终止响应，不静默跳过记录。
- `reset:log`、节点报告清理和机器历史清理均限制批次、单轮批次数和单轮时长。`reset:log` 保留所有原清理条件和删除顺序，复合主键表按完整键删除；每批事务提交后保留进度，失败可以从候选范围重试。定时任务增加 30 分钟的重叠保护。
- 新增索引覆盖机器历史的机器/时间查询、用户线路时间筛选、小时/分钟线路查询和审计日志清理时间。

## 验证记录

- PHP 8.4.21，受影响回归 64 项、725 次断言通过；加入分桶和小批清理用例后，相关统计、清理、节点报告回归 76 项、856 次断言通过。
- SQLite 完整回归最终为 1,018 项、9,969 次断言，4 项按项目既有条件跳过。中途发现的直接构造控制器兼容问题已修正；一次并发计数波动与本批代码无调用关系，专项和完整回归复跑均通过。
- 隔离 SQLite 合成 30 天、4 个实体的节点排行：返回 4 行，查询事件 6 次，43.943 ms；执行计划使用 `v2_stat_proxy_traffic` 主键的 `scope + unit + record_at` 范围索引。该数据用于确认扫描路径，不代表生产耗时。
- 当前环境未发现 `mariadbd`、`mysql` 或 Docker，未执行 MariaDB 实例验证；不能把 SQLite 结果表述为 MariaDB 通过。迁移和 SQL 使用 Laravel SQLite/MariaDB 兼容写法，接入专用 MariaDB 后应运行项目规定的严格 `ONLY_FULL_GROUP_BY` 回归。
