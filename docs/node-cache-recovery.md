# 节点版本缓存故障与恢复

源码版本：`1.33.1`。记录日期：2026-09-30。正式发布来源见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 已确认的故障

节点初始化读取面板配置时反复收到 500。面板异常位于 `NodeControlStateService` 读取配置版本代次（`epoch`）的位置。对运行中缓存的只读检查确认：部分节点的版本记录保存了后台设置字段，却没有版本代次；同机其他节点的记录正常。

配置版本记录只应包含版本代次、递增序号（`sequence`）和配置内容摘要（`hash`）。原实现只检查是否为数组，随后直接读取这些成员。遇到错误数组时不会重新初始化，且该缓存没有过期时间，因此重试、Node 重启或只重启面板容器都不能保证恢复。

2026-09-30 的检查覆盖面板中的 90 个节点，先后确认 14 个节点有同类错误。定向删除节点 201 的异常配置版本缓存后，Node 自动重试并成功监听 TCP、UDP 端口。后续按授权仅删除仍符合已确认异常结构的记录；结构已变化的记录跳过，不执行全局缓存清空。

15:39 再次检查 90 个节点，现有 126 条配置与设备版本记录全部结构正常，其余 54 条尚无缓存；不能把未生成缓存直接判作故障。此前受影响的 14 个节点均已恢复持续状态上报。本次恢复没有重启面板或 Node，没有替换生产代码。

## 修复行为

- 校验版本记录的完整结构、代次与摘要格式、序号类型及取值范围；拒绝混入其它字段的记录。
- 缓存丢失或结构错误时，在原有节点锁内创建新代次，从序号 1 开始保存；即使业务配置内容没有变化，也会完整替换异常记录。
- 正常重复读取不改变版本；配置变更在同一代次递增序号。配置收集失败不覆盖上一次有效记录。
- 配置与设备快照共用此恢复逻辑。其他节点、后台设置、数据库、流量账本及实际配置不在清理范围内。
- 恢复日志只写异常缓存的位置，不输出缓存值或认证内容。

## 验证与结论边界

使用合成的后台设置数组在本地复现了相同的缺少版本代次异常。回归用例覆盖配置与设备两类缓存恢复、内容摘要未变化时的替换、缺项与错误类型、其它字段混入、重复请求、新服务实例读取、配置变化、缓存丢失、收集失败，以及实际 HTTP 配置同步入口。

本地 PHP 8.4.21 验证结果：完整测试 403 项、4455 次断言通过；最后补充零序号校验后，相关测试 33 项、134 次断言通过。命令使用 `php -d extension=pdo_sqlite -d extension=sqlite3 vendor/bin/phpunit --do-not-cache-result`，定向验证追加 `tests/Feature/Server/NodeControlStateServiceTest.php tests/Feature/Server/RealtimeServerTest.php tests/Unit/Services/RealtimeStateStoreTest.php`。本地使用 SQLite 内存库和内存缓存，不把它等同于新版代码已完成生产部署。

这次修复解决的是“异常版本缓存永久阻断配置下发”的确定性缺陷。现有证据尚不能确定后台设置最初通过哪个操作写入这些记录，不能将并发、Redis、本次版本升级或插件作为已经证实的首次写入原因，也不能承诺所有缓存写入问题已经排除。

部署修复后，同类结构异常会自动重建，仍应关注恢复日志是否反复出现；反复恢复意味着首次错误写入来源仍在，需要继续定位。生产环境定向清理缓存不能代替部署，发布与部署核验结果以兼容矩阵为准。
