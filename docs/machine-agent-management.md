# 服务器 agent 管理

面板 `1.19.0`、管理前端 `0.4.0` 和 Node `v1.16.0` 配套提供本功能，已于 2026-09-21 正式发布。

## 页面行为

本地待发布的面板 `1.23.0`、前端 `0.6.0` 配套 Node `v1.19.0`：在线服务器执行升级或重启期间，状态显示“升级中”“重启中”，悬停和读屏仍能看到具体阶段；服务器离线时仍显示离线。结束后的结果（包括失败和超时）只对本页看到过执行过程或由本页提交的任务显示，刷新页面后不再显示；面板仍保存最近一次任务，接口不变。列表默认按名称里的国家或地区排序，依次为亚太、美洲、欧洲、其他地区，认不出国家的排在最后；点击列头排序时，这个顺序作为同值行的先后。

本地待发布的面板 `1.20.3`、前端 `0.4.3` 配套 Node `v1.16.1`：默认升级先比较已安装版本与最新正式版，仅目标版本更高才下载、校验、安装及重启。相同版本显示“已是最新版本”，更高版本显示“当前版本更高，不自动降级”；这两种结果不重启并直接完成任务。查询失败、读取当前版本失败和版本无法识别均停止升级并显示原因。仍可单独发起手动重启。

本地待发布的面板 `1.20.2`、前端 `0.4.2` 将操作状态并入原有“状态”栏：在线、离线状态继续保留，等待和执行中使用转圈动画，结束后显示结果。详情、编辑、删除和三点菜单保持一排；独立操作状态列移除。

面板 `1.20.1`、前端 `0.4.1` 已发布，Node 配套版本不变。表格依次展示服务器名称、状态、负载、节点数、最后心跳、运行版本、公网 IP 和操作状态；选择框在最左侧，操作列在最后。单台“升级”“重启”位于删除按钮后的三点菜单内，批量操作仍在工具栏。

语言资源地址带内容摘要，内容更新后自动使用新的缓存地址。批量响应缺项、重复或格式异常时显示“提交结果未确认”，不计为成功；此时应刷新并核实任务状态，不自动重发。

- 运行版本来自当前 yz-agent 进程的构建版本，不读取安装记录来推断。离线时保留最后一次回报，可结合现有在线状态判断。
- 公网 IP 按 IPv4、IPv6 分别记录：控制请求的来源地址记入对应的一种，Node `v1.19.0` 起还会每 5 分钟分别只经 IPv4、只经 IPv6 回报一次。两种都有时分两行显示，IPv4 在上；某一种的最近回报比另一种旧 15 分钟以上时不再显示，服务器整体离线时保留最后一次地址。旧 Node 只能显示控制请求的那一个地址；面板域名只有一种解析时，也只能看到这一种。可信代理沿用现有代理头规则；私网和无法识别的来源不记录。NAT 下显示出口地址，不枚举网卡；反向代理应正确转发来源地址。
- 操作前确认目标；重启对象是 yz-agent 服务，其全部实例和节点会短暂中断。更新固定到执行时解析的最新正式版，复用原有附件校验及失败回滚事务。
- 历史 Node `v1.16.0` 不比较已运行版本与最新正式版；即使版本相同，也会重新下载、安装并重启。需使用 `v1.16.1` 才具备本次版本检查逻辑。
- 列头选择当前页，翻页保留选择；排序和刷新按服务器 ID 绑定，切换筛选条件清空选择。批量逐台返回受理或拒绝结果。
- 每页数量仅保存在当前浏览器，刷新及重新登录保留，不跨浏览器同步。

## 通信与结果

管理接口 `POST server/machine/operate` 接收 `ids`（最多 200 个）与 `action`（`upgrade` 或 `restart`），沿用管理员鉴权。前端超过 200 台时分批提交。

Node 每 5 秒调用 `POST /api/v2/server/machine/control`，使用已有机器鉴权，上报运行版本、进程标识、控制能力及任务结果。此通道不依赖 WebSocket，也不要求机器绑定节点。旧面板返回 404 时继续原有服务。

Node `v1.19.0` 起另外调用 `POST /api/v2/server/machine/address`，同样使用机器鉴权、不带其他字段。面板按请求来源的地址族记录公网地址，并在 `ip` 字段回显识别结果；非公网来源回显空值且不记录。旧面板返回 404 时，Node 改为每小时重试一次。

`agent_runtime` 和 `agent_operation` 分别保存最近运行信息和最近任务。数据库行锁保证同一服务器只能有一个未完成任务。30 秒无控制回报视为离线，拒绝新操作；15 分钟未确认则显示超时，不自动重试。

实际更新和手动重启的成功必须同时满足独立执行器完成和新 agent 进程回报，发出请求或只替换文件均不算成功。面板 `1.20.3` 仅对升级中 `up_to_date`、`current_newer` 的成功结果允许原进程确认，结果保留到下次任务；重复、迟到回报不能覆盖已完成任务。网络中断可能导致“超时未确认”，应先检查实际服务状态，不能据此认定没有执行。

`operation.result` 为可选字段，取值为 `updated`、`up_to_date`、`current_newer`；新增失败码为 `release_query_failed`、`current_version_failed`、`current_version_invalid`、`latest_version_invalid`，分别对应查询正式版、读取当前版本、当前版本识别及正式版识别失败。只回传固定码，不回传命令输出。旧 Node 缺少该字段时保留原成功判断，不推测其版本比较结果。

## 安装条件

远程操作要求 Linux 上安装的 yz-agent、root 权限及 systemd 或 OpenRC。systemd 使用独立临时服务执行，OpenRC 使用独立会话执行。本机执行锁避免多个面板实例同时修改同一服务。容器、手工二进制路径或不支持的旧 agent 不宣称具备控制能力。

操作标识与固定结果码位于安装目录 `remote-operations`，不保存凭据和命令输出。重复请求与配置重载不重复执行；异常退出后任务超时，内核执行锁自动释放。面板超时不强杀正在安装或回滚的事务，仍在执行的进程继续持锁，后续操作返回忙碌。

本次配套版本尚未发布。后续部署应先更新面板及前端，再更新 Node；旧面板不能完整接收新结果，旧 Node 仍按原逻辑升级。历史已发布版本、完整来源及镜像 digest 见 [兼容矩阵](../YZ_COMPATIBILITY.md)。回滚面板前应等待在途任务结束，并核对其是否支持正在运行的 Node 结果协议。
