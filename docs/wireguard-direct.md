# 普通 WireGuard 节点

配套版本为面板 `1.53.0`、Node `v2.7.1`、管理端 `0.30.0`，发布核验状态见兼容矩阵。

## 创建与订阅

节点协议选择 WireGuard，前置入口选择“无”，填写对外地址、UDP 端口和权限组即可作为普通节点。支持 Xray 和 sing-box，默认 MTU 1420，允许 1280–1500。选择前置后仍使用已有 WG 中转，用户订阅继续连接前置协议。

普通 WG 通过 Mihomo、sing-box 和通用 `wireguard://` 链接订阅交付，不提供官方 WireGuard 客户端配置文件或配置份数管理。sing-box 1.11 及以上使用 endpoint 格式，旧版使用 outbound 格式；1.10 的格式没有保活设置，订阅不输出未知字段。通用链接能否导入取决于客户端自身支持，旧 Clash 等不支持 WG 的格式不会包含该节点。

每个用户在每个节点有独立密钥和稳定 IPv4/IPv6 隧道地址。刷新订阅不换身份；重置用户连接凭据后，旧 WG 密钥撤销，客户端须刷新订阅。Node 只接收用户公钥和地址，客户端只取得自己的私钥与服务端公钥。

身份通过面板应用密钥派生，节点编号、创建时间和用户连接凭据共同参与，不增加 WG 身份表。须保留原应用密钥；变更它会轮换全部普通 WG 身份。用户编号 1–16777212 可分配稳定地址，超出容量明确报错。各节点采用独立用户态网络栈，地址不占宿主网络接口。

## 权限、设备与计费

- 权限组、启停、用户封禁、到期和流量余额沿用面板判断。用户变化全量同步 WG 身份；Node 每包检查到期，后台每秒清理过期 peer 和已有连接。封禁、余额耗尽和权限变更随面板推送或轮询生效。
- 设备额度按通过 WG 认证的外层公网 IP 计算，复用其他协议的 IPv4 单地址、IPv6 /64 合并、排除名单与全局在线快照；同一 IP 不重复占额。不按隧道地址、公钥数量或配置下载次数计算。
- WG 没有明确断线通知。来源有 90 秒活动期限，已准入来源的认证数据或保活续期；失联后回收。未认证 UDP 和陌生来源的空保活不占额度。面板全局快照的同步间隔与既有协议一致，跨节点不是分布式原子锁。
- 同一用户同一节点共享一个 WG 身份。WG 会把该身份的回包发送给最近认证的端点；复制同一身份到多台设备可能互相抢占连接。IP 限制不会改变 WG 的端点漫游机制，也不识别物理设备数量。
- 统计转发的 TCP/UDP 有效负载，排除 WG 握手、保活、加密封装和 IP 包头。重载、停止、撤销用户后保留累计数，由现有差值上报、倍率和结算流程处理。
- 同一用户所有连接共享套餐限速；已有连接可应用限速调整。限速等待只影响该用户连接，不阻塞公共 WG 队列。连接数量和新建速率也沿用已有套餐限制。

## 大陆来源与中转

普通 WG 可以启用“屏蔽大陆来源 IP”，按外层 UDP 的来源匹配共用大陆库，在认证前丢弃受限来源；具体 IP 例外仅跳过该地区限制。首次缺库、缓存与刷新行为见 [来源拦截](source-policy.md)。

WG 中转仍采用原链路身份和 Linux 网络空间方案，落地不单独启用此项来源策略，用户来源在前置限制。普通 WG 采用用户态 TCP/UDP 转发，不要求建立系统 TUN，也不承诺原中转 Linux TCP/BBR 的性能；不提供 ICMP 转发。

## 验证与使用条件

三个项目必须配套后才能启用普通 WG，旧 Node 不具备此入口能力。面板没有新增 WG 专用迁移，但本版包含此前来源策略的可空数据库列。回退旧版本前先停用普通 WG 节点，保留现有 WG 中转。

参考了 3x-ui 的 WG 用户身份、地址和订阅处理方式；没有修改参考仓库或两个核心 fork。具体测试与构建结果见 [兼容矩阵](../YZ_COMPATIBILITY.md)。本地验证不代表真实服务器已经更新。
