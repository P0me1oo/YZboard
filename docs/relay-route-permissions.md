# 中转线路权限

配套版本：面板 `1.37.1`、Node `v2.3.1`。发布状态见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 问题与行为

旧实现按逻辑落地的权限组过滤订阅，却只在入口认证用户身份。用户被移出某条落地线路的权限组后，入口可能仍保留该用户及全部落地线路，因此更新订阅只能隐藏节点，保存的旧配置仍可重新连接。

新实现分别判断入口直连和每条落地线路的权限。用户拥有哪个节点的任一权限组，就可使用对应线路；入口汇总这些用户以完成认证。仅拥有落地权限的用户可以通过入口访问该落地，但不能使用入口直连或其他落地。一个节点同时属于多个组时，只要仍有一个组匹配，就继续授权。

套餐“强制更新”修改现有用户权限后，面板刷新旧组、新组及这些组所关联落地的前置入口。修改用户权限、落地权限组、封禁、到期及流量耗尽也使用最新用户状态。取消套餐“强制更新”仍保留原有存量用户规则。

Node 校验用户请求中的线路编号。撤权后拒绝保存的旧配置和旧会话发起的新请求，并关闭该线路已登记的 TCP、UDP 连接；保留权限的线路与其他用户继续使用。恢复权限后可重新连接。重复同步、重载和恢复不能重新放开已撤销的线路。

## 通信与兼容

入口用户列表增加允许使用的线路编号数组（协议字段 `relay_routes`），包含获准的入口直连编号和落地编号。该字段不写入用户订阅或数据库。普通节点保持原授权格式，落地仍不接收普通用户凭据。

Node 将线路权限纳入用户快照与内核内容摘要。只变更权限也会应用更新；迟到的旧版快照不能恢复权限。Xray 在 Node 调度层校验认证会话的线路，sing-box 只生成获准线路的认证身份和路由，并检查旧会话的新请求。两种实现均由 Node 管理连接关闭，不修改两个核心 fork 或固定依赖。

旧面板缺省该数组时，Node 保留旧版已配置线路的行为；明确的空数组表示没有任何线路权限，两者在复制和摘要中严格区分。旧 Node 不识别新授权字段，因此只有面板和 Node 都升级后才完成修复。发布后的更新顺序为先 Node、后面板；回滚任一端都可能重新出现旧行为。

管理端沿用 `0.18.0`，无需修改表单、重新创建节点或重置用户凭据。客户端刷新订阅用于整理列表，不能替代服务器授权校验。

## 验证

面板测试覆盖强制更新、恢复权限、重复保存、仅拥有落地权限的用户、落地权限组修改、流量耗尽以及入口授权快照变化。Node 使用本机回环地址的真实 Xray、sing-box，测试 VLESS、HY2 的旧配置重连、旧会话、已有 TCP/UDP、保留线路、恢复权限、空授权和重启恢复；另检查并发登记与撤权、协议复制和旧快照保护。

最终测试与构建结果见 [兼容矩阵](../YZ_COMPATIBILITY.md)。本次不连接生产服务器，不把本地验证等同于已部署。
