# 内置中转落地的来源限制

## 移除中转来源限制（1.37.0）

面板 `1.37.0`、Node `v2.3.0`、管理端 `0.18.0` 移除自动来源 IP 白名单、出口核对、手动确认和待确认提示，恢复已有自动端口放行。中转绑定、运行开关和端口跳跃不变。

必须配套更新节点程序：只更新面板不能清理旧节点的来源规则。新版 Node 忽略旧面板来源策略；先建立普通放行，再清理本实例旧来源规则，写入失败保留旧规则并重试。保留旧规则格式读取与清理代码，不认领手工或其他实例规则。没有启用 UFW/firewalld 的环境仍不自动安装或启用防火墙。

上述配套版本已发布，先升级 Node，再更新面板，发布核验见 [兼容矩阵](../YZ_COMPATIBILITY.md)。以下旧版本说明保留为历史记录，不代表新版行为；服务器更新由用户执行。

面板 `1.35.0`、节点程序 `v2.1.0`、管理端 `0.16.0` 配套使用，发布结果见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 自动处理范围

只处理设置了前置入口的内置 Shadowsocks、VLESS、WireGuard 落地实际中转监听端口。普通节点、前置公开入口、订阅连接端口和 Hysteria2 端口跳跃保持原有行为。系统原有自动防火墙后端必须可用；本功能不自动安装或启用 UFW/firewalld。

前置每 30 秒读取内置中转目标的系统选路源地址，不发送探测流量、不增加监听端口。面板核对这些地址与前置经过机器认证回报的公网地址，只对一致的地址生成来源规则，不使用订阅域名的解析结果冒充出口。IPv4、IPv6 分别核对，只生成对应地址族的精确 IP 放行。

自动核对适用于默认内置中转、公网直出的路径。私网/NAT、无法解析目标、未回报出口或自定义出站不作为已确认来源；这不是从落地抓包得到的端到端测量。有策略路由、按协议分流或特殊 NAT 的部署，应在待确认界面由管理员核对实际出口后确认，不能把面板所见地址直接当成所有目标的出口。

每次配置快照重新读取绑定、地址和端口占用；前置选路变化后更新报告。只改来源策略时不重建中转监听。绑定变化及其他运行参数变化仍遵循原有配置重载流程。

## 待确认

管理页在前置入口旁显示“来源限制待确认”，点击查看原因。缺少出口地址时可以确认一个或多个具体 IP，不接受域名、网段或全地址范围；内网中转的具体私网来源也必须明确确认。确认绑定当前落地、前置、机器、目标和已观测公网地址；这些条件变化后重新核对。

同机配置共用内部端口、多个运行节点共用落地端口、其他 UFW/firewalld 规则覆盖该端口或默认策略无法保证限制时，暂停变更并说明冲突。必须先处理端口/规则冲突，不能通过填写来源绕过。

UFW 入站规则使用无法确认端口的应用名或复杂范围时，也进入待确认。旧托管规则若合并了相邻端口，须等范围内其他节点完成检查后再替换，包含另一地址族的旧全开放规则。

待确认时保留该端口现有托管规则及监听，不新建全开放规则。旧规则若原本全开放，待确认期间仍是全开放，不视为已经完成保护；新节点没有旧规则时也不会因此自动全放行。确认后先建立来源规则，成功后撤销旧来源及旧全开放托管规则。手工规则和其他实例的规则不会被认领或删除。

节点侧失败原因通过现有运行指标回传。规则写入失败时保留监听并每 30 秒重试；地址不明确时等待新的配置或管理员确认。运行中的绑定落地即使配置未变也会定期复核，新增冲突和冲突解除都更新面板提示。正常停用、删除和退出仍清理本实例托管规则。

## 升级与恢复

无需数据库迁移或批量修改旧节点记录。先更新面板，再更新前置，待出口回报完成后更新落地；两端升级完成后已有绑定自动生效。旧 WireGuard `1.x` 升到 Node `2.x` 还须遵守系统 WG 的双端格式迁移要求。

落地升级前须在面板处理仍待确认的来源。旧程序正常停止时会清理自己的托管规则；新版只能保留当时仍存在的规则，不能依赖已被旧程序清理的全开放规则继续通行。

异常退出后的规则先保留到所有实例完成节点发现和来源检查，防止较快启动的节点提前清理尚未恢复节点的规则。明确待确认的端口继续保留旧规则，其余遗留规则按运行节点重新核对。带来源的归属文件使用版本 2，新程序兼容读取版本 1；回滚旧程序前应由新版正常停止并完成规则清理。
