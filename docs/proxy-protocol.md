# 节点接收 PROXY 协议

节点级接收开关已随面板 `1.92.0`、管理端 `0.64.0` 和 YZ-Agent `v2.16.1` 发布。

在节点编辑页的“高级设置 → 连接设置”开启“接收 PROXY 协议”，转发机向落地节点发送 TCP PROXY v1 或 v2。版本自动识别，不需要填写转发机 IP；不带头的普通连接也能继续使用。Realm 可关闭接收 PROXY，开启发送 PROXY v2。

面板 `1.95.2` / 管理端 `0.66.2` 起，接收开关使用与 VLESS Encryption 一致的背景框。

开启后信任任意来源提供的地址，必须配合防火墙限制节点入口，防止伪造用户来源。解析发生在认证和 TLS 握手之前；设备数、来源拦截及访问记录使用解析后的地址，PROXY 头不计入业务流量。

## Realm 脚本与面板自带中转

已对照 `realm-xwPF` 的本地固定源码 `ef90071cca0073a4dd41f62708a6c9e82a27873c`。普通客户端经 Realm TCP 转发时，在脚本的 Proxy Protocol 管理里关闭全局开关，再选择对应规则、协议 v2、方向“仅发送”。接收该连接的 YZ 节点开启“接收 PROXY 协议”。v1 同样支持。

脚本的“全局开启”会同时设置发送和接收；普通客户端没有 PROXY 头，因此这里使用规则级“仅发送”。不要把“仅接收”或“双向”当作该场景的发送设置。

面板自带的“前置入口 → 落地”仍使用原有内部协议，不要求开启此开关，也不会因此自动向落地发送 PROXY 头。若在 VLESS TCP 前置入口外再套 Realm，只需给该入口开启接收；入口按还原后的来源统计用户及所选落地线路，用户套餐流量仍在入口统计一次。落地无需额外开启接收。

原生 HY2/QUIC 的 UDP 入口和 WireGuard 不接收这项 TCP 协议头；其既有中转方式不变。

## 开关与旧配置

- 面板 `1.100.1`、管理端 `0.71.1` 和 Agent `v2.21.1` 的本地修复统一为两个状态。旧空值按原界面显示转换：旧传输接收选项为 `true` 时开启，其余关闭；已有明确开关不变。数据库禁止新增空值，接口和配置始终提供布尔值。
- 新建节点默认关闭。开启下发 `accept_proxy_protocol: true`，关闭下发 `false`，分别表示信任所有 TCP 来源和不解析 PROXY 头。关闭始终优先于旧传输配置和前置 IP 名单。
- 旧传输配置 `networkSettings.acceptProxyProtocol` 仅在没有节点级字段时恢复同样的布尔开关；两个字段都缺失时关闭。不再存在按名单接收的第三种状态。
- “前置服务器 IP”（`device_ip_exclude`）继续排除设备数和相关来源统计，增删名单不改变接收策略。名单本身不触发核心重载。
- 开关变化通过现有配置推送和轮询传递，并按需重载所属节点；重复配置不反复重建，停止后恢复继续使用当前设置。不同节点、同进程不同核心实例相互独立。

## 支持范围与更新

支持两种 YZ 核心通用 TCP 监听，包含 Shadowsocks/SS2022、VMess、VLESS、Trojan、SOCKS、HTTP，以及 sing-box 的 AnyTLS 和 Naive TCP。TCP 上的 WebSocket、gRPC、HTTPUpgrade 等传输同样在握手前解析。

原生 UDP、QUIC、KCP、WireGuard 和 Mieru 独立监听不支持此开关，界面不提供开启入口。开启 TCP 接收不会给 Shadowsocks 的原生 UDP 添加真实来源支持。

复用现有固定核心依赖，无需单独升级核心。此修复需同时更新面板和 YZ-Agent，先面板后 Agent，两端更新完成后再操作开关。旧版本仅填前置名单、界面显示关闭却使用带头转发的节点，修复后会关闭接收，需要明确开启；原来显示开启的旧节点不再限制为名单内来源。回退前评估带头连接兼容性，迁移回退保留明确的布尔值。本地版本尚未发布。
