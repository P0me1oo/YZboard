# 节点状态与设备同步读取优化

## 1.37.3：减少未变化设备的重复处理

本次针对每秒状态上报之后的重复设备处理，不减少状态采样、统计插件回调或可靠流量批次。

### 处理方式

- 设备内容变化仍通过共享通知集合在下一轮约一秒定时器中展开为在线节点。去掉每次上报都通知自身的路径；每五秒重新读取全部在线节点的可用用户和设备，处理用户禁用、到期、流量耗尽、权限变化、设备过期以及丢失通知。
- 上述校准是完整读取，不跨轮缓存用户资格或设备结果。未收到通知的变化和自然过期最多额外等待约五秒；实时页面的状态仍在 35 秒无有效采样后显示过期。正常配置、用户修改与首次连接继续通过完整同步发送设备。
- 同一物理连接分节点记录已成功交给发送缓冲区的设备版本。版本未变时跳过发送；新连接、重新绑定和显式同步请求强制完整发送。新代次或新版本的空设备集合正常发送，发送失败不会留下成功标记。
- 相同设备只刷新来源时间与有效期，按每批最多 128 个用户合并缓存命令，避免删除后重建。保留其它节点的设备记录与节点索引，保留数据库一分钟节流和设备变化后的立即更新。缓存执行失败仍报错，不伪装为空设备或接收成功。
- 设备写入扩展方法继续调用原实现，统计插件仍收到每次完整上报。原有同批设备读取优化、资料版本缓存、流量事务、批次去重和排序保护保持有效。
- 管理页面去重排除仅用于捕获顺序的版本号；实际发送的帧仍带原有版本信息。页面采样及权限检查周期不变。

部署前后应在同一主控保留相同状态上报和插件设置，各连续采样约两分钟，比较整机、节点处理进程、面板容器、Redis 和数据库 CPU，以及报告速率、有效节点数和每秒缓存/数据库命令。百分比采用明确的整机或单核口径，不将节点数和业务量变化当成优化收益。发布及生产结果完成后追加实测记录。

## 1.33.2：读取复用

面板版本：`1.33.2`。本次只调整面板读取路径，无数据库迁移、通信格式或前端修改。

## 原因

状态上报和设备下发每次都查询节点或机器记录。设备下发还会对每个用户重复读取所涉节点的完整实时状态。只减少统计队列不能消除这些同步处理开销。

## 实现与时效

- 状态上报和设备下发使用进程内资料缓存；每次读取检查共享版本，最长保留五秒。普通修改、禁用、删除和节点归属变化在数据库事务提交后更新版本；批量删除节点、删除机器时解除节点关联也主动更新版本。事务内部直接查询，回滚不发布新版本。
- 缓存只保存节点与机器资料，不缓存当前在线状态、用户资格或设备结果。缓存不可用时直接查数据库；返回独立模型，避免机器历史保存或插件操作污染后续报告。
- 心跳、负载和流量累计不触发资料整体失效。用户筛选插件可以读取任意节点字段，因此存在此类插件时，设备下发仍查询最新节点记录。认证、完整配置下发、流量结算不使用本次资料缓存。
- 外部直接改数据库且不经过面板事件的操作，最多五秒后重新读取；需要立即生效的新增批量管理入口必须调用资料失效方法。正常面板管理操作不等待此期限。
- 多用户设备读取每批最多发送 256 条 Redis 读取命令，再汇总节点，统一读取其状态并复用过期检查结果。减少网络往返和重复解码，不把不同用户的设备合并。下一次调用重新读取，设备来源过滤、IPv6 合并和过期规则保持原样。
- 扩展服务覆盖单用户设备读取方法时，继续调用其定制方法，不以批量路径绕过插件行为。
- 读取失败会报错，不把失败当成设备清空。原有快照锁、版本顺序、重复报告处理、设备写入、变化通知与重连同步保持原样。
- 每秒上报和现有管理页刷新频率不变；插件采样次数、来源活跃时间及连接统计不减少。
