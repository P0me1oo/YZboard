# 连接数限制

连接数限制自面板 `1.17.0` 引入，需要配套 YZ-Agent `v1.15.0` 或更高版本。固定发布来源、镜像和验证记录见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 使用方式

套餐和用户各有两个可选项，留空或填 0 表示不限制：

- 并发连接数：同一时刻该用户最多保持的活跃连接数。
- 新建连接速率：该用户每秒最多新建的连接数。

两者互相独立，可以只设其中一个，也可以同时设置。

### 套餐

在套餐管理的新建和编辑表单中填写。保存后，后续购买、分配或更换到该套餐的用户会同步拿到这两个上限。自 `1.18.1` 起，后台按套餐生成用户和注册领取试用套餐也会同步设备数、并发连接数和新建连接速率上限；已生成的用户不会自动补写。

套餐未配置上限时，会给用户写入空值，避免换套餐后继续沿用上一个套餐的限制。已经在上限引入前购买的用户不会被追溯修改，需要重新分配一次套餐，或手工在用户编辑页设置。

### 单个用户

在用户管理的编辑表单中填写，只影响该用户，不受套餐覆盖。之后该用户再次购买或更换套餐时，会以新套餐的值为准。

## 生效方式

上限随用户列表下发给 Node。Node 刷新到新列表后生效，不需要重启内核，也不影响已经建立的连接——限制只作用于之后新建的连接。

面板保存成功不等于节点已经生效，具体时机取决于节点获取用户列表的周期和实时通知是否可用。

## 节点侧行为

Node 在每条新连接建立时按用户做准入判断，超限只拒绝这一条新连接，不关闭该用户已有的连接。

- 并发连接数：比较该用户当前的活跃连接数与上限，达到上限即拒绝。
- 新建连接速率：按每秒一个额度的令牌桶判断，桶容量为一秒的额度，容纳客户端打开页面时的正常突发；额度消耗后按上限速率回填。

并发判断在速率判断之前。并发已经超限时直接拒绝，不再消耗速率令牌，否则用户恢复到正常并发后还要额外等待令牌桶回填。

未配置上限的用户不受连接数或速率限制，节点仍保留已有的连接统计。上限配置刷新时，已存在的令牌桶原地调速而不是重建，正在被限速的用户不会因为一次刷新拿到完整的突发额度。

Node `v1.15.1` 将并发检查与名额占用合并，避免多条连接同时到达时突破上限。正在调度的连接也占用名额；Xray 调度返回错误或连接关闭后归还名额，重复关闭不会重复扣减。

## 超限上报与通知

Node 按上报周期汇总本周期内触发上限的用户，随状态上报一起发送。同一用户在同一周期内同时触发并发和速率时，分成两条上报。

每条上报包含用户 ID、类型（并发或速率）、触发时生效的上限和被拒次数。并发超限的观测值是本周期触发拒绝时，已占用连接名额的最大值，包含正在调度的连接；它不是整个周期的连接峰值，也不代表用户尝试建立的总连接数。速率超限没有可观测值，该项为 0。

Node `v1.15.1` 在取得上报快照后释放本周期的统计记录，新事件进入下一周期；并发写入不会丢失次数或拆散次数与观测值，已删除用户的迟到事件不再创建记录。

面板收到后只做校验和归一化，不写入数据库：

- 用户 ID 不是正整数的条目丢弃；
- 类型不是并发或速率的条目丢弃；
- 上限、观测值和次数中的负数归零。

之后交给 `server.limit.exceeded` 钩子，载荷包含节点 ID、名称、类型和归一化后的事件列表。是否发送通知、如何合并和去重由插件决定。面板不做去重，同一个周期重复上报会原样再触发一次钩子。

没有有效事件时完全不触发钩子，也不产生额外开销。

## 实现与验证

- 面板侧的字段、校验、套餐同步和上报处理在 YZboard 内实现；管理端输入框由 YZboard-Dash 源码工程实现，随管理端产物一起发布，含中、英、俄文案。
- Node 侧的准入判断由 `internal/limiter` 实现，内核通过 `model.ConnLimiter` 接口调用。接口放在 model 层，避免内核包反向依赖 limiter 包；Xray 和 sing-box 各自在新连接路径上接入。
- Xray 侧按 `email` 解析面板用户 ID 并统计活跃连接数。设备数限制校验已经登记了来源 IP 计数，连接被连接数限制拒绝时会先回退该计数，避免泄漏。
