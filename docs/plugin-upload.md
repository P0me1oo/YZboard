# 插件上传限制与错误提示

从正式版 `1.13.3` 起，管理端允许上传最大 **64 MiB** 的插件 ZIP，即 `67,108,864` 字节。恰好达到上限的文件允许上传，超过上限一字节即拒绝；文件格式仍需通过原有 ZIP 校验。

正式版 [1.15.1](https://github.com/P0me1oo/YZboard/releases/tag/v1.15.1) 已发布，增加独立上传超时和完整错误提示。双架构镜像及 `latest` 已核验，来源和回滚记录见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 上传超时

插件上传接口单独使用 `300000` 毫秒，即 **5 分钟** 的浏览器请求超时。其他管理端请求仍为 30 秒，主题上传等接口不受本次超时调整影响。

浏览器等待超过 5 分钟时，上传页面显示：

> 插件上传请求超时（5 分钟），请刷新插件列表确认结果后再重试

这个限制包括文件传输和等待响应的时间。浏览器超时并不能确认服务端是否已经完成安装，因此不会自动重发请求。失败后上传状态和文件选择框会复位，可以确认结果后重新选择文件。

浏览器超时与服务端执行限制分别生效。Octane 的 `OCTANE_MAX_EXECUTION_TIME` 默认仍为 **60 秒**，约束服务端处理请求的时间；外部反向代理也可能提前结束请求。如果在 5 分钟内就收到 408、504 或 524，应按实际状态码检查对应网关和服务端日志，不能据此认定浏览器的 5 分钟设置没有生效。

## 错误提示

管理端优先显示服务端提供的具体原因，支持 JSON 的 `message`、表单 `errors`、`error` 和纯文本响应。服务端没有可用消息或返回 HTML 错误页时，根据状态码或浏览器错误类型生成提示，并将同一原因交给页面处理；插件上传只显示一次错误提示。

| 情况 | 提示内容 |
| --- | --- |
| 插件上传等待超时 | 明确标出 5 分钟，并提示先确认插件列表 |
| 普通请求等待超时 | 显示该请求的实际超时配置，默认 30 秒 |
| 网络连接失败 | 未收到服务器响应，请检查网络或服务状态 |
| 请求被取消或中断 | 分别显示“请求已取消”或“请求已中断”，不误报为等待超时 |
| HTTP 408 | 服务器接收请求超时 |
| HTTP 413 | 上传文件过大，请检查服务器上传限制 |
| HTTP 500 / 502 / 503 | 分别提示服务器内部错误、网关连接服务异常或服务暂时不可用 |
| HTTP 504 / 524 | 网关等待响应或与服务器通信超时，提示检查对应配置或处理耗时 |
| 其他 HTTP 错误 | 保留实际状态码，避免仅显示“未知异常” |

错误对象保留原有表单校验详情和业务错误码，401 / 403 继续执行原有登录状态处理。没有 HTTP 响应的错误也会保留可用的客户端原因。

## 请求大小配置

旧版插件接口和 Octane Swoole 默认都限制为 10 MiB。包含本地 IP 数据库的插件包可能超过这个大小，导致请求在进入安装逻辑前返回 HTTP 413。管理端原先没有对应提示，容易显示为“未知错误”或“未知异常”。

新版同时调整三个位置：

| 位置 | 新上限 | 作用 |
| --- | --- | --- |
| 插件上传接口 | `65536 KiB` | 约束单个插件 ZIP 为 64 MiB |
| Docker PHP | `upload_max_filesize=64M`、`post_max_size=80M` | 单文件大小和整次表单请求大小 |
| Octane Swoole | `package_max_length=80 * 1024 * 1024` | 在 HTTP 接收阶段允许完整上传请求 |

请求上限大于文件上限，是为 multipart 表单字段和分隔内容留出空间。管理端也会在发送前检查文件大小；服务器返回 413 时显示“上传文件过大，请检查服务器上传限制”。

PHP 配置位于 `.docker/php/zz-xboard.ini`，Swoole 配置位于 `config/octane.php`。自行挂载 PHP 配置时，需要确认生效值没有覆盖成更小的限制。非 Docker 部署也应在实际加载的 PHP 配置中设置同样的值，并重启相应 PHP / Octane 服务。

## 外部反向代理

镜像自带的 Caddy 没有额外设置请求大小上限。如果容器前还有 Nginx、OpenResty 或其他网关，也需要让它允许至少 80 MiB 的请求；容器配置无法覆盖外部网关的限制。

Nginx / OpenResty 可在对应站点配置中设置：

```nginx
client_max_body_size 80m;
```

修改后使用实际管理该站点的服务检查配置并重载。若站点已有更大的限制，可以继续使用原值。

## 发布与配置检查

64 MiB 大小限制已随正式版 [1.13.3](https://github.com/P0me1oo/YZboard/releases/tag/v1.13.3) 发布。独立超时和完整错误提示已随 `1.15.1` 发布，不可变镜像为 `ghcr.io/p0me1oo/yzboard:1.15.1-8714e57`；`latest` 已核对指向相同 digest。更新与检查命令见 [本版 Release](https://github.com/P0me1oo/YZboard/releases/tag/v1.15.1)，完整来源见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

管理端由固定上游子模块提供，镜像构建按 `Dockerfile` 的顺序应用本仓库补丁。插件上传补丁会同步更新资源名称、manifest 和 HTML 引用；只读取未打补丁的上游资源不会包含这些调整。

排查上传限制时，确认实际加载的 PHP `upload_max_filesize` 为 `64M`、`post_max_size` 为 `80M`。若仍返回 413，先检查外部网关和自定义 PHP 配置；文件超过 64 MiB 则会在页面中直接提示。

## 本地验证

```bash
php -d extension=pdo_sqlite vendor/bin/phpunit tests/Feature/PluginUploadTest.php
node --test tests/admin-plugin-upload.test.cjs
```

测试调用真实控制器的文件校验并替换安装操作，验证旧上限以上、恰好 64 MiB、超出一字节、非 ZIP 和缺少文件等情况。

管理端测试执行实际构建补丁产物的上传方法、请求错误处理和上传页面回调，覆盖独立 5 分钟配置、两种浏览器超时码、断网和网关错误、错误只提示一次、失败后重新上传及原有登录处理；同时核对资源引用、旧补丁升级、重复运行以及锚点失效时不改写文件。超时错误通过模拟触发，不需要实际等待 5 分钟，也不连接真实服务器。
