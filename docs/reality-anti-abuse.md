# REALITY 防盗用模式

防盗用模式自面板 `1.22.0` 引入，需要 Node `v1.18.0` 及以上、内核为 Xray 才会生效。固定发布来源、镜像和验证记录见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

## 要解决的问题

REALITY 服务端在读到客户端首包之前，就会先拨通伪装站点（表单里的“伪装站点(dest)”）。凡是认证不通过的连接——包括握手时用了别的 TLS 域名——都会被原样双向转发到伪装站点。

伪装站点通常指向一个 CDN。于是任何人只要把 TLS 握手里的域名换成同一 CDN 上的其它站点，就能借这台节点访问它：流量记在节点账上，来源看起来也是节点。节点等于对外白送了一个通用 TLS 转发入口。

## 使用方式

在节点管理里编辑 VLESS 或 Trojan 节点，安全性选择 Reality 后出现“防盗用模式”开关，默认关闭。

开启后，节点会把 REALITY 的伪装回源改接到一台只监听本机的专用入口，由它按“伪装站点域名”列表放行：命中的连接按客户端实际请求的 TLS 域名回源，端口沿用伪装站点的端口；其余连接一律直接阻断。

生效条件：

- 节点内核是 Xray。sing-box 没有对应实现，该开关对 sing-box 节点无效。
- 节点启用了 REALITY。
- 伪装站点域名列表至少有一个域名。列表为空时节点会忽略该开关并在日志中给出提示，回源行为保持原样。

保存后由节点在下一次拉取配置或重启服务时应用，和其它节点配置一样，保存成功不等于远程节点已经生效。

## 副作用

关闭状态下，用错域名探测的人会拿到伪装站点的真实响应；开启后这类连接会被直接断开。主动探测者可以观察到：用白名单里的域名握手有回应，换个域名就断。

这是拿一部分伪装表现，换掉节点被当成公共转发入口的风险。两者不能兼得，所以默认关闭，由运营方自行选择。

其它注意事项：

- 域名按完整匹配，不支持通配符，与 REALITY 内核自身比对伪装站点域名的口径一致。
- 域名填错会让伪装回源全部被阻断，开启前先确认列表填写正确。
- 开关只改变伪装回源的处理方式，不影响正常客户端的 REALITY 握手、密钥、Short ID 和流控设置。

## 升级与回滚

- 面板与 Node 可以分别升级，建议先升级面板再升级 Node。
- 旧版 Node 收到这个设置会忽略，行为不变；新版 Node 连到旧面板时按关闭处理。
- 面板升级本身不会自动开启任何节点的防盗用模式。
- 面板回滚到 `1.21.1` 后，已保存的开关值仍留在数据库中但不再下发，节点恢复原来的伪装回源行为。

节点侧的配置细节、专用端口选取和日志字段见 Node 仓库的 `docs-reality-anti-abuse.md`。
