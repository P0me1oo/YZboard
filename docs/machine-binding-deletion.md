# 删除服务器后的 Agent 自动解绑

YZboard 2.32.0 和 YZboard-Next 0.39.0 使用同一套协议，配套 YZ-Agent v2.57.0。

管理员在服务器管理中直接删除机器。面板在一个事务中解除节点关联，保留节点编号、配置和累计用量，并保存机器编号、删除时间及删除时有效令牌的 SHA-256 摘要。原有删除记录继续有效，离线时间长短不影响确认。

## 通知与确认

- 删除提交后，已通过认证且凭据匹配的机器长连接收到 `machine.deleted` 事件，`data.machine_id` 标识目标。Agent 随即发起一次控制心跳，同一连接重复收到提示时合并处理。
- 仅使用 HTTP 时，Agent 在现有 `POST /api/v2/server/machine/control` 心跳中携带 `nonce`。启动、安装合并和无法运行控制心跳的受保护实例恢复期间，通过现有 `POST /api/v2/server/machine/nodes` 使用同一确认格式。每次挑战都是独立生成的 32 字节随机数，以 64 个小写十六进制字符传输。
- 只有服务器已删除且凭据摘要匹配时，面板才返回 HTTP 200 和 `binding_deletion` 对象。对象包含 `version=1`、`state=deleted`、`machine_id`、`nonce` 和十六进制 `proof`。签名为 HMAC-SHA256，密钥是原令牌的二进制 SHA-256 摘要，原文为 `yz-agent-machine-deleted-v1\n<十进制机器编号>\n<本次挑战>`，其中 `\n` 表示单个换行。响应禁止缓存。
- Agent 仅通过配置的 HTTPS 面板或本机回环 HTTP 接受确认。它检查响应状态、版本、机器编号、挑战和签名，并在写入前重新核对对应面板和本地凭据。网络故障、停用、令牌轮换、普通 403／404 或迟到的旧响应都保留绑定。恢复同编号服务器后，当前身份优先于历史删除记录。

## 混合版本

新 Agent 遇到旧面板会继续使用原有机器接口，保留未获有效确认的绑定。旧 Agent 接入新版面板也可继续工作，删除服务器后保留本机绑定。双方都升级后，已保存的删除记录可用于补做确认。旧的独立状态查询接口已移除。早于删除记录迁移、没有凭据摘要的历史删除需手动解绑。

删除最后一个已确认绑定后，Agent 进入等待绑定状态。其他绑定、证书、历史备份和待补报流量保留。按实例加密的配置可以使用外层机器身份确认删除。旧式整文件加密恢复副本需手动处理。
