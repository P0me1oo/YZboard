# 节点状态与设备同步读取优化

面板版本：`1.33.2`。本次只调整面板读取路径，无数据库迁移、通信格式或前端修改。

## 原因

状态上报和设备下发每次都查询节点或机器记录。设备下发还会对每个用户重复读取所涉节点的完整实时状态。只减少统计队列不能消除这些同步处理开销。

## 实现与时效

- 状态上报和设备下发使用进程内资料缓存；每次读取检查共享版本，最长保留五秒。普通修改、禁用、删除和节点归属变化在数据库事务提交后更新版本；批量删除节点、删除机器时解除节点关联也主动更新版本。事务内部直接查询，回滚不发布新版本。
- 缓存只保存节点与机器资料，不缓存当前在线状态、用户资格或设备结果。缓存不可用时直接查数据库；返回独立模型，避免机器历史保存或插件操作污染后续报告。
- 心跳、负载和流量累计不触发资料整体失效。用户筛选插件可以读取任意节点字段，因此存在此类插件时，设备下发仍查询最新节点记录。认证、完整配置下发、流量结算不使用本次资料缓存。
- 外部直接改数据库且不经过面板事件的操作，最多五秒后重新读取；需要立即生效的新增批量管理入口必须调用资料失效方法。正常面板管理操作不等待此期限。
- 多用户设备读取每批最多发送 256 条 Redis 读取命令，再汇总节点，统一读取其状态并复用过期检查结果。减少网络往返和重复解码，不把不同用户的设备合并。下一次调用重新读取，设备来源过滤、IPv6 合并和过期规则保持原样。
- 扩展服务覆盖单用户设备读取方法时，继续调用其定制方法，不以批量路径绕过插件行为。
- 读取失败会报错，不把失败当成设备清空。原有快照锁、版本顺序、重复报告处理、设备写入、变化通知与重连同步保持原样。
- 每秒上报和现有管理页刷新频率不变；插件采样次数、来源活跃时间及连接统计不减少。

## 验证

新增回归覆盖查询复用、对象隔离、跨读取实例的修改与删除、机器禁用、事务提交/回滚、五秒重新读取、进程重建、缓存故障和清空、用户筛选插件、批量删除和机器解绑，以及设备批量过滤、过期和读取失败。

本地命令：

```powershell
php -d extension=pdo_sqlite -d extension=sqlite3 vendor/bin/phpunit --do-not-cache-result
node --test tests/admin-dist.test.cjs
```

本地使用独立 SQLite 内存库与内存缓存。新增事务测试不使用外层测试事务，直接验证提交后失效与回滚行为；不使用生产数据。

本地完整回归通过 417 项、4525 次断言，管理端资源检查通过 5 项。之后补充扩展服务单用户读取兼容分支，相关回归通过 18 项、80 次断言。服务器 PHP 8.2.34 与真实 Redis 的独立临时键验证通过：批量结果、下一次读取的过期判断、错误类型读取均符合预期，临时键和容器测试文件已清理。

固定发布来源在 GitHub Actions 的 PHP 8.2 环境完成全部 418 项测试、4526 次断言，管理端资源 5 项检查和 Linux 双架构构建均通过。

首次直接运行 PHP 时未启用 SQLite 扩展，补充上述启动参数。新增测试初版使用迁移回滚清理，遇到既有 SQLite 索引对应列的迁移回滚错误；现使用每项独立内存库，显式迁移并直接验证业务事务，不改动产品迁移文件。

## 部署与评估

正式部署采用固定来源的双架构镜像。前后对比应使用相近节点数和上报速率，记录节点工作进程 CPU、数据库与 Redis 每秒命令量，并核对状态新鲜度、HTTP 健康和错误日志。CPU 的 100% 表示一个逻辑核心，不能把调用栈采样占比当成整机可下降的幅度。

无新增持久化结构；回滚至 `1.33.1` 时旧程序忽略新增资料版本键，不需要删除数据库或现有状态。

### 生产验证（2026-09-30）

经用户授权，已从 `1.33.1` 更新到固定来源 `ba30df55efb028fef42154d07061bf56888d9fff` 的 `1.33.2` 镜像。更新前备份数据库、Compose、环境配置、插件和主题，校验备份可读取并保留旧镜像。更新后核对运行镜像来源及 digest，持久化挂载、Compose 和环境配置一致，没有待执行迁移。使用面板配置的 Host 请求首页与公共接口均为 200，63 个节点有新鲜状态。

部署前采样一次、部署后采样两次，每次约 120 秒，期间保持原有报告和刷新频率。CPU 采用单核口径；上报速率略有增加，不是通过减少上报降低负载。
