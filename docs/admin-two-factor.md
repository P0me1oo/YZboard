# 管理员两步验证

两步验证自面板 `1.16.0` 引入，采用基于时间的一次性密码（TOTP），配合 Google Authenticator、1Password、Microsoft Authenticator 等验证器 App 使用。固定发布来源、镜像和验证记录见 [兼容矩阵](../YZ_COMPATIBILITY.md)。

当前版本只提供后端能力，后台界面尚未随面板产物发布，原因见兼容矩阵中的「管理端交付阻塞」。

## 适用范围

只有管理员账号（`is_admin`）可以绑定和被校验，且完全自愿，后台没有强制开关。普通用户的注册、登录和订阅流程不受影响。

同一个账号在绑定之前，登录行为与旧版本一致。

## 登录流程

启用后，登录变成两步：

1. 提交邮箱和密码。密码正确时，接口不再直接下发登录令牌，而是返回 `totp_required` 和一次性的 `challenge_id`。
2. 携带 `challenge_id` 和验证器上的 6 位动态码调用 `loginWithTotp`，通过后才拿到登录令牌。

挑战标识有效期 5 分钟，成功一次即作废，不能重放。同一个挑战累计 5 次验证码错误后直接失效，需要重新输入密码登录。

邮件链接登录和快速登录链接同样绕过密码，因此这两条路径在管理员启用两步验证后也会返回 `totp_required`，需要补完第二步。这是为了避免有人用一封登录邮件直接跳过两步验证。

第一步失败时的提示与旧版相同，不会因为账号是否绑定两步验证而泄露差异；密码错误次数限制仍然照常生效。

## 恢复码

确认启用时会一次性返回 8 个恢复码，格式为 `XXXXX-XXXXX`。请立即保存到安全的地方：

- 恢复码只显示这一次，数据库里只保留哈希，任何接口都不会再次返回明文。
- 每个恢复码只能使用一次，用过即作废。
- 恢复码可以代替动态码完成登录，也可以用于关闭两步验证。
- 可以随时重新生成；重新生成后，旧的 8 个全部作废。

## 验证器丢失时的自救

手机或验证器丢失且恢复码也用尽时，在面板所在服务器上执行：

```bash
php artisan reset:totp 管理员邮箱
```

该命令清除指定账号的密钥、启用时间和恢复码，账号回到只用密码登录的状态，请随后尽快重新绑定。命令只能在服务器本地执行，不通过任何接口暴露。

Docker 部署在部署目录执行：

```bash
docker compose exec xboard php artisan reset:totp 管理员邮箱
```

## 接口

登录第二步（免鉴权）：

| 方法与路径 | 说明 |
| --- | --- |
| `POST /api/v1/passport/auth/loginWithTotp` | 提交 `challenge_id` 与 `code`，成功返回登录令牌 |
| `POST /api/v2/passport/auth/loginWithTotp` | 同上，供管理端使用 |

自助管理（需管理员登录，挂在后台安全路径下）：

| 方法与路径 | 说明 |
| --- | --- |
| `GET /totp/status` | 查询是否启用、启用时间和剩余恢复码数量 |
| `POST /totp/setup` | 生成待绑定密钥、otpauth 链接和二维码，此时尚未启用 |
| `POST /totp/confirm` | 提交一次动态码确认启用，返回恢复码明文 |
| `POST /totp/disable` | 提交动态码或恢复码后关闭 |
| `POST /totp/recoveryCodes` | 提交动态码后重新生成恢复码 |

这些接口只作用于当前登录的账号，不能代其他管理员绑定或关闭。

## 实现说明

- 算法按 RFC 6238 实现于 `app/Utils/Totp.php`：HMAC-SHA1、6 位、30 秒步长，校验时允许前后各一个时间窗口，容忍约 30 秒的设备时钟误差。没有引入新的 composer 依赖；绑定二维码复用已有的 `bacon/bacon-qr-code`。
- 密钥和恢复码在 `v2_user` 中按 `APP_KEY` 加密存储，恢复码另外经过哈希。两个字段都在模型的 `$hidden` 中，不会随管理端用户列表等接口返回。
- 待绑定的密钥暂存在缓存中，有效期 10 分钟，确认启用后才写入数据库。绑定过程中断不会影响现有登录方式。
- 更换 `APP_KEY` 会导致已加密的密钥和恢复码无法解密，相关账号需要用 `reset:totp` 清除后重新绑定。
