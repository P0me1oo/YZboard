# PowerDNS 请求容错

维护者：P0me1oo。适用版本：本地开发面板 2.13.2、管理端 0.97.1；生产修补版面板 2.12.4、管理端 0.96.2。

## 请求与重试

连接及单次 HTTP 请求上限均为 5 秒。首次失败后最多重试 3 次，即最多 4 次业务请求；等待时间为 200、400、800 毫秒。仅重试暂时性连接故障、地址解析失败，以及 HTTP 408、429、500、502、503、504。认证、权限、区域、证书、记录冲突、重定向及无效返回立即失败。

服务返回 Retry-After 时遵守其等待时间；若等待将超过本轮预算，结束本轮并保留原始故障类别。每轮区域同步的读取、退避、写入及核对共用 25 秒预算，接近截止时缩短单次等待，避免超过队列任务或同步锁时限。因此 3 次是重试上限，预算耗尽或核对失败会提前停止。

前置池保存可能连续执行旧区域清理和新区域同步。管理端对前置池保存、删除及手动 DNS 同步等待最多 60 秒，其他请求继续使用原有等待时间。

## 写入结果核对

PATCH 失败可能只是响应丢失。重发前读取区域，比较记录内容、TTL、停用状态和归属注释：全部已生效则直接确认，不重复写入；尚未生效且区域仍与首次归属检查后的快照一致才允许重发。比较忽略服务端注释时间和自动更新的 SOA 序列号，保留其他记录及注释检查。

核对不可用、区域内容变化或归属变化时停止重发，保留待确认记录。最后一次失败写入在预算允许时再核对一次；每轮最多 4 次业务请求、4 次写入核对。下一轮仍按原归属标记重新协调，不认领外部记录、不覆盖新增的泛解析或下级委托。

现有每分钟同步、成功后清除错误、失败保留已确认用户分配、前置调度失败与恢复事件继续生效。

## 故障提示与日志

页面显示具体故障，例如连接/响应超时、密钥认证失败、来源 IP 白名单或权限拒绝、API 路径/区域不存在、证书校验失败、限流和服务端异常，并说明请求及写入核对次数。预算中断时保留实际故障原因，写入无法确认时提示下轮核对。

每次调用只记录最终失败，或本次重试/核对后的恢复摘要，不为每一次尝试写一条重复日志。使用现有系统日志及开关，结构化字段包含配置编号、请求方法、故障类别、HTTP 状态码、cURL 错误码、请求/核对次数、预算状态和耗时。前置池跨轮恢复仍记录在已有调度历史。

不记录 API Key、请求头、完整 URL、响应正文、个人域名、解析内容、归属注释或原始异常对象。系统日志关闭时不绕过开关；日志写入失败不改变 DNS 请求结果。

## 公网权威 DNS 双活与写入容灾

本次实现请求容错，没有改造当前一主三从的部署。四台继续对外解析，管理 API 仍写入同一台主服务器。

要使任意一台 DNS 宕机后其他节点仍能解析、添加和修改记录，需要同时具备独立的可写数据副本与 API 入口切换。可以使用两台 PowerDNS 提供查询/API，配合独立高可用存储或仲裁；完整同步必须包括记录、归属注释、区域元数据及密钥。普通 AXFR 区域同步不能替代管理数据库复制。

PowerDNS 官方 LMDB + Lightning Stream 可经 S3 兼容存储同步多写节点；5.1 起 LMDB 支持本面板依赖的记录注释。该方案是最终一致，同步依赖对象存储，切换时需要处理未同步写入、并发冲突、时钟与面板归属核对，不能承诺无延迟或零丢失。

若要求已确认写入在单机故障后仍保留，采用数据库复制与自动选主更适合明确这种保证。必须配置防止旧主继续写入的隔离机制；若采用严格同步复制且要求任意单台故障后仍能继续确认复制写入，应准备至少三个数据副本，而非只给两个副本增加一个不存数据的仲裁节点。跨地区同步会增加延迟，失去足够副本时应暂停写入，现有权威解析继续使用本地数据。

参考：[PowerDNS LMDB](https://doc.powerdns.com/authoritative/backends/lmdb.html)、[Lightning Stream](https://doc.powerdns.com/lightningstream/latest/index.html)、[Patroni 复制模式](https://patroni.readthedocs.io/en/latest/replication_modes.html)。
