# 访问记录

面板 `1.92.0` 与 YZ-Agent `v2.16.1` 已发布，节点归属改为实际出口。沿用已有管理页面，无需更新管理端源码。

原开发版本 `1.104.2` 的查询优化已随面板 [v1.104.3](https://github.com/P0me1oo/YZboard/releases/tag/v1.104.3) 发布：用户汇总按所选时间范围读取，避免数据库为用户去重而扫描全部历史用户索引。新增一项索引迁移，此项优化无需修改管理端、Agent 或核心。

在管理端「统计分析 → 访问记录」查看用户通过代理节点发起的连接。仅管理员可以查询。默认显示今天的用户汇总，按访问次数从多到少排序，也可选择最近访问优先。支持最近 7 天、自定义时间、用户邮箱或编号、节点名称或编号、目标地址和端口筛选，次数只统计符合筛选条件的记录。

进入用户后，按次数查看时合并相同目标地址和端口，跨节点的访问计入同一组；不同端口、子域名和用户分别统计。点开目标可查看每次访问实际使用的出网节点和连接时间。切换为按时间查看则逐条显示该用户的连接，最新记录在前。次数指已保存的连接记录数量，不代表网页打开次数或连接成功次数。

连接时间按面板时区显示；默认今天从当天零点开始，截止到次日零点，不混入相邻日期的记录。翻页、排序、展开与返回沿用本次查询的记录上限及时间边界，跨日翻页仍查询原来那天，点击刷新查看新记录。返回保留上一级页码和滚动位置，等待列表加载完成后恢复；读取失败后重试仍会恢复。到期记录仍立即排除，快照不会延长留存。

## 存储与性能取舍

用户与目标汇总由数据库执行后分页，进入用户后使用已有的用户与时间索引；用户资料只读取当前页涉及的用户，原始明细计数和排序不再逐条关联用户表。每次最多返回 100 项，浏览器不会先下载全量数据再合并。继续使用现有查询并发和耗时限制。

`1.104.2` 新增按连接时间、用户编号和记录编号排序的索引（`proxy_access_time_user`）。MySQL / MariaDB 在没有用户筛选的用户汇总中明确使用它，计数和汇总先读取所选时间范围；默认今天只扫描今天对应的索引区间。未附加节点、目标或端口条件时，汇总所需数据可直接从索引读取。用户筛选与用户详情继续由数据库选择已有用户索引；SQLite 沿用自身查询计划。最近七天查询仍需读取七天的数据，复杂筛选仍受原有五秒查询上限约束。

升级时先完成新增索引迁移，再加载新版查询代码。建索引需要额外磁盘空间和时间，耗时取决于已有数据量与磁盘性能；不拆分数据表，也不缩短七天留存。迁移回退只移除新增索引，记录和原有索引保留；回退查询代码应与迁移回退配套，避免新版查询引用已移除的索引。

本机 MariaDB `11.4.8` 下，4,427,160 条模拟记录中当天有 632,452 条；计数和汇总实际读取的索引记录均从全表记录量缩小到当天记录量。单轮计数为 1.574 → 0.325 秒，汇总为 1.424 → 0.433 秒；查询服务当天约 1.477 秒，最近七天约 6.434 秒，两条查询分别受原有五秒上限约束。迁移新增、回退和重建后记录数量一致。以上使用模拟数据，不代表生产环境的实际耗时。

参考 Lite 的数据库内筛选分页、索引和到期清理设计。Lite 的匿名访客事件限流不适用于已认证节点的连接记录，未照搬。现有系统已有批量写入、批次重试去重和分批清理；保留这些机制，不新增汇总表、压缩归档或字典表，避免维护第二套统计数据及其一致性。重复访问只在展示时合并，存储仍保留逐次时间和历史节点名称，不采样、不缩短留存。新增索引会增加磁盘占用；尚未测量生产环境的实际耗时改善。

## 记录范围

- 每条记录包含用户编号、实际出网节点及名称、连接时间、目标域名或 IP 和目标端口。用户邮箱由现有用户资料关联，不上报用户认证信息。
- 记录经过身份和连接准入检查、交给核心处理的目标请求。时间是 Node 观察到该请求的时间，不是网页加载完成时间，也不保证远端连接成功。
- 优先使用代理请求携带的域名；sing-box 也可使用现有路由处理已经识别的域名。无法取得域名时保存目标 IP。不会为此开启新的内容嗅探、DNS 反查或 TLS 解密。Xray 保留 Node 调度入口取得的目标，在选路后记录实际出口。
- TCP 按逻辑连接记录，UDP 按核心创建的目标会话记录，不逐个数据包记录。普通 WireGuard 在 Node 的用户准入层记录。中转由前置采集并归属最终选中的落地节点，落地端不重复采集；前置自身直出才归属前置。自定义路由改选出口时按最终出站记录，不按原计划线路猜测；不会把落地服务器地址当成最终目标。
- 不保存 URL、网页路径、查询参数、请求头、请求正文或通信内容。域名以小写 ASCII 形式保存，国际化域名使用 Punycode；IPv6 使用规范化形式。
- 只记录配套版本启用后发生的请求，旧数据不能补造。先更新面板，再更新相关 Agent；版本 2 的握手会让旧 Node 停止访问记录采集，流量上报继续工作。新 Agent 遇到只支持版本 1 或未声明能力的面板时不采集，独立运行模式不采集。已有历史记录保留原节点归属，到期正常清理。

## 保存与上报

面板保留最近 7×24 小时的记录，查询立即排除到期数据，每 5 分钟分批清理。需要保持项目原有调度器运行。迟到或重试的过期记录会被确认，但不会重新入库。

Node 每 5 秒由独立协程批量上报，每批最多 256 条，与流量计费及状态上报分离。批次在发送前保存到节点自己的配置目录，确认后清除；相同节点、批次和位置仅保存一次。快照中的批次编号固定，重启或确认响应丢失时重发不会产生重复记录。缓存文件使用仅当前用户可读写的权限，文件名区分面板、机器和节点，不包含凭据。

为避免记录故障影响代理转发，每个节点最多缓冲 32,768 条。长时间断网、磁盘错误或持续超量时不能保证全量保存；队列满会在 Node 日志中记录丢弃数量，不输出目标地址。突然断电或强制终止可能丢失最近一次快照后的记录；正常退出会保存剩余队列。损坏缓存保留原文件并停用本次运行的采集，避免覆盖；应先检查节点日志再处理该缓存。节点停用期间没有后台任务清理其缓存，重新启动后会排除过期批次。

## 接口与兼容

`POST /api/v2/server/access-log` 复用现有节点或机器认证，上报身份仍是前置或普通节点。面板握手声明 `access_log.version=2`；单条记录包含实际出网节点编号（`node_id`）、用户编号（`user_id`）、连接时间 Unix 秒（`connected_at`）、主机名或 IP（`destination`）、端口（`port`）。面板只允许归属上报节点自身或它的中转落地，落地可以位于另一台机器；内部落地不能再次上报。单次请求最大 128 KiB，最多 256 条，拒绝非法主机名、附加内容字段及超前超过 5 分钟的时间。面板确认返回相同批次编号后，Node 才移除缓存。

旧缓存没有实际节点编号的记录，以及落地已移除、已更换前置或不属于上报节点的迟到记录，会被确认但不入库，避免错误归属或堵塞新批次。批次重试保持原落地编号与位置，已经保存的节点名称不随重命名或重试改变。实际出口归属修改沿用现有表与索引，本身不需要数据库迁移；`1.104.2` 的查询优化另有上述索引迁移。

管理查询使用现有管理员路由下的 `statistics/accessLogs`，不向普通用户开放。继续使用已有表 `v2_proxy_access_log`，不修改流量账本、套餐扣费或已有统计。两个核心保持现有固定依赖，无核心源码修改。回退时使用配套的面板和 Node；撤销最初创建访问记录表的迁移会删除全部记录，应按需先备份。

查询增加 `view=users|targets|records`，省略时仍返回原逐条记录，兼容旧管理端；`sort=count|time` 控制汇总排序。目标汇总必须传入精确用户编号 `user_id`；目标详情再传入精确地址 `destination` 与端口 `port`，不使用模糊搜索代替分组匹配。客户端沿用响应的 `snapshot_id` 和 `snapshot_at` 翻页或展开，刷新时移除两者。现有记录立即参与汇总，无需重报或重写记录。

旧面板没有访问记录清理任务。回滚后如保留新表，应单独安排到期数据清理，不能继续依赖旧版本自动执行 7 天留存规则。
