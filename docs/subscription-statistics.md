# 订阅统计

面板 `1.89.0`、管理端 `0.61.0` 新增「统计分析 → 订阅统计」。Node 沿用 `v2.14.0`，两个核心和通信格式不变。固定来源与发布验证见[兼容矩阵](../YZ_COMPATIBILITY.md)。

## 页面与口径

- 按用户汇总拉取次数、成功与失败次数、不同 IP 数、客户端数和最近拉取时间。客户端数按软件及版本去重，IP 按完整地址跨日去重。
- 进入用户后，按 IP、客户端及版本合并，展示次数、首次和最近时间。展开可切换每日统计与最近 7 天逐次记录，另显示响应状态和实际订阅格式。
- 默认今天，可选最近 7、30、90 天和自定义整日范围，按面板时区计算，结束日期包含当天。次数均受筛选范围限制。
- 支持邮箱或编号、IP、客户端名称筛选，已删除用户显示编号。IP 支持完整或部分地址，完整 IPv6 的压缩、展开写法及映射 IPv4 归到同一地址。
- 筛选和查询结果不写入浏览器持久存储，仅记住每页条数。返回用户汇总保留当前筛选和页码。

覆盖普通订阅、旧版订阅接口和应用配置下载，不包括应用版本查询。请求结束后使用最终响应状态，一次请求只记一次。成功表示 2xx 或 304 响应，不能证明客户端完整接收。

只记录鉴权过程已经识别用户的请求。浏览器限制、用户限频、客户端限制、账户不可用、参数错误和生成失败均按最终状态计入失败。IP 防护在识别用户前直接拒绝的请求、无效凭据继续使用原防护记录，不额外查询用户以绕过防护。

客户端取自请求的软件标识，只保存常见软件规范名称和数字版本，不认识的显示未知。软件标识可伪造，不能当作设备认证。输出格式来自实际生成器，与客户端分别记录。来源 IP 沿用可信代理规则，通过转换服务下载时记录转换服务的地址。不保存订阅链接、凭据、正文、完整请求头或异常正文。

## 保存与处理

| 数据 | 保留范围 |
| --- | --- |
| 每次拉取时间及对应状态、格式 | 今天及此前 6 天，共 7 个自然日 |
| 每日用户、完整 IP、客户端及版本、状态、格式、次数、首次和最近时间 | 今天及此前 89 天，共 90 个自然日 |
| 写入批次去重标记 | 90 天，用于提交后尚未确认的重试 |

借鉴 Lite 的分层保留、时间差编码和压缩块思路，不引入独立存储服务。日统计只保存一次维度文本；逐次时间关联日统计，不重复 IP 和软件信息。时间按秒排序并编码差值，零差值保留同秒的每次请求；压缩有收益时用 Deflate，否则直接保存差值编码。数据库以 Base64 文本存放，兼容 SQLite 和 MariaDB。

复用 Redis 和 `stat` 队列。请求只追加精简记录，调度每分钟投递批处理任务，每批最多 500 次。先原子认领固定批次，再将去重标记、日统计和时间块一起提交，最后确认移除 Redis 批次。重试及多进程取得同一批次不会再次累计，真实新请求仍增加次数。正常显示约延迟一分钟，队列繁忙时可能更久。

每五分钟清理到期数据并有限量合并小块。合并前校验摘要、数量和边界，重新编码后再次校验，成功后同事务替换，不改日计数。每块最多 4,096 次。深分页按时间归并需要读取的块，不累计前面所有页的展开数据。查询也限制保留范围，不依赖清理准时运行。

待处理缓冲区最多 200,000 次，另有最多 500 次已认领请求。满额或采集失败不阻断订阅，通过 `subscription_statistics_failure` 日志中的 `stage`、`count` 统计故障；Redis 可用时另保存按天、阶段的故障次数，保留 8 天。阶段为 `capture`、`flush`、`maintenance`。数据库故障时已认领批次保留，后续调度重试。

未入库数据的持久性取决于现有 Redis 的持久化配置；Redis 数据丢失不能回填。采集故障可能造成漏记，统计不能用作计费依据。数据库清理不保证磁盘文件立即缩小。

## 存储样本

本机 SQLite 样本：10 名用户，各用同一完整 IPv6 和客户端，每天拉取 60 次，持续 90 天，共 54,000 次。两种数据库均在回收空闲页后测量，包含表和索引。

| 方式 | 数据库体积 |
| --- | ---: |
| 逐次重复保存 IP、软件、版本和状态等，逐次保留 90 天 | 4,837,376 字节 |
| 本方案，90 天日统计和 7 天压缩逐次记录 | 372,736 字节 |

本方案保存 900 条日统计、70 个块、4,200 次近期时间，时间块正文共 1,120 字节。差异同时来自分层保留和压缩，**不是单独的压缩率**。样本时间规则、维度少，实际大小取决于请求分布、IP 与版本变化和数据库引擎。

## 接口与兼容

以下接口位于 `/api/v2/<管理路径>/statistics/`，沿用管理员认证和现有重查询限制：

| 接口 | 返回 |
| --- | --- |
| `subscriptionUsers` | 用户汇总 |
| `subscriptionUser` | 指定用户的 IP、客户端明细 |
| `subscriptionDays` | 指定 IP、客户端及版本的每日记录 |
| `subscriptionEvents` | 对应最近 7 天逐次记录 |

通用参数为 `period`、`start_date`、`end_date`、`page`、`page_size`、`search`、`ip`、`client`。用户明细要求 `user_id`；每日和逐次记录另要求完整 `ip`、`client`，以 `client_version` 精确匹配版本。每页最多 100 条，返回实际页码、总数和时间范围元信息，不调用外部 IP 服务。

新增三个独立统计表，不改用户用量和已有流量统计，不回填升级前历史。回退代码可保留新表；旧版停止采集、维护，恢复新版后不能补造停用期间的数据。清理后的记录不能靠回退代码恢复。正式发布需同时纳入后端迁移和管理端资源。
